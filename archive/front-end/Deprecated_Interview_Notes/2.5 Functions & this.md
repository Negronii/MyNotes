# Function Invocation and Implementation Patterns / 函数调用与手写实现模式

**Core / 核心：** For ordinary functions, `this` comes from the call form; arrow functions capture it lexically. `call`, `apply`, and `bind` make receiver and argument handling explicit. 普通函数的 `this` 取决于调用形式；箭头函数词法捕获 `this`。`call`、`apply` 与 `bind` 显式处理接收者和参数。

## `this` Keyword in JavaScript
The value of `this` depends on how an ordinary function is called, not simply where it is written. Arrow functions instead use the `this` value of their surrounding lexical context.

### `this` in Different Contexts:

1. **Classic browser script context**
   At the top level of a browser classic script, `this` is the global `Window` value. Top-level module code has `this === undefined`, and other hosts have their own global environment.

   ```javascript
       console.log(this === window); // true in a browser classic script
   var myFunction = function() {
       console.log(this === window); // true: a non-strict plain call substitutes the global object
   };
   myFunction();
   ```

2. **Function Context**
   The value of `this` within a function is determined by how the function is invoked.

   - **Regular Functions:** 
     In non-strict code, a plain call converts `null` or `undefined` to the function's global object and boxes primitive receivers. In strict code, the supplied receiver is used as-is, including `undefined`.

     ```javascript
     function myFunction() {
       'use strict';
       console.log(this); // undefined in strict mode
     }
     myFunction();
     ```

   - **Arrow Functions:** 
     Arrow functions have no own `this`; they capture it from their enclosing scope. Use them when that lexical receiver is intended, not when the API supplies a dynamic receiver to the callback.

     ```javascript
     const myObject = {
       myMethod: function() {
         console.log(this); // `this` refers to myObject
         setTimeout(() => {
           console.log(this); // `this` still refers to myObject, thanks to arrow function
         }, 1000);
       }
     };
     myObject.myMethod();
     ```

3. **Object Context**
   In `object.method()`, the base `object` is passed as the receiver. Extracting the function and calling it plainly loses that receiver unless it is rebound.

   ```javascript
   const myObject = {
     myMethod: function() {
       console.log(this); // `this` refers to myObject
     }
   };
   myObject.myMethod();
   ```

4. **Constructor Context**
   With `new`, `this` is the new instance during construction. If the constructor returns an object or function, that value becomes the result; a primitive return is ignored.

   ```javascript
   function MyConstructor() {
     this.myProperty = 'value';
   }
   const myInstance = new MyConstructor();
   console.log(myInstance.myProperty); // 'value'
   ```

5. **Explicit Binding**
   `.call()` and `.apply()` invoke immediately with a supplied receiver; `.bind()` returns a wrapper with preset arguments. For strict functions the receiver is preserved as supplied; non-strict functions apply their usual conversion. Arrow functions ignore receiver changes.

   - **`.call()` and `.apply()`** both invoke immediately. `.call()` takes separate arguments; `.apply()` takes an array-like argument list (or `null`/`undefined` for no arguments).

     ```javascript
     function myFunction(a, b) {
       console.log(this);
       console.log(a + b);
     }

     myFunction.call({my: 'object'}, 1, 2); // Logs: {my: 'object'} and 3
     myFunction.apply({my: 'object'}, [1, 2]); // Logs: {my: 'object'} and 3
     ```

   - **.bind()** returns a new function with a specified `this` value, allowing you to invoke the function later with the context already set.

     ```javascript
     const boundFunction = myFunction.bind({my: 'object'}, 1, 2);
     boundFunction(); // Logs: {my: 'object'} and 3
     ```

## Implementing a `bind` Function

Native `bind` returns a new function with preset arguments and, for ordinary calls, a bound receiver. Arrow functions keep their lexical `this`.

### Application of `bind`:

- **Returns a New Function**: Unlike `call` and `apply`, which execute the function immediately, `bind` returns a new function. When called, this new function has its `this` context and any initial arguments pre-set.
- **Binds `this` and Partial Arguments**: `bind` allows for the binding of the `this` context to an object and permits partial application of arguments, enabling some function arguments to be pre-filled and the rest supplied upon calling the bound function.
- **Arrow Function Limitation**: Arrow functions do not have their own `this` context but inherit it from the surrounding lexical context. Thus, using `bind` to change the `this` context of an arrow function is ineffective. However, `bind` can still be used to pre-fill parameters.
- **Use as a Constructor**: If the target is constructable, the bound function can be used with `new`; the bound receiver is ignored and the new instance is used. Preset arguments are still prepended.
- **Normal Function Call**: In a regular function call scenario, `this` refers to the object that was bound using `bind`, which ensures a consistent context in callbacks and event handlers.

### Implementation Strategy:

This teaching helper supports ordinary calls and argument prepending. It intentionally does not emulate native `bind` construction, `new.target`, function metadata, or prototype behavior.

### Example:

```typescript
function fn(this: { name: string }, a: number, b: number) {
    console.log(this, a, b);
}

const obj = { name: 'Alex' };
const boundFn = fn.bind(obj, 1); // Binds 'obj' as 'this' and '1' as the first argument
boundFn(2); // Output: { name: 'Alex' } 1 2
```

### Custom `bind` Implementation:

```javascript
function fn(a, b) {
    console.log(this.name, a, b);
}

Function.prototype.myBind = function(context, ...preBoundArgs) {
    const originalFunction = this;
    return function(...newArgs) {
        return Reflect.apply(originalFunction, context, [...preBoundArgs, ...newArgs]);
    };
};

const obj = { name: 'Alex' };
const boundFn = fn.myBind(obj, 1);
boundFn(2); // Alex 1 2
```

## Implementing `call` and `apply` Functions

Native `call` and `apply` invoke immediately with an explicit receiver. The small example below uses a temporary Symbol property, so it is limited to extensible ordinary object or function receivers; it is not a replacement for the built-ins' primitive conversion and exotic-object behavior.

### Binding `this`

- `bind`, `call`, and `apply` are all crucial for setting a function's `this` context in JavaScript.
- In contrast to `bind`, which returns a new function, `call` and `apply` invoke the function right away with a specified `this` context.
- The primary difference is argument shape: `call` accepts separate arguments, while `apply` accepts an array-like list (or nullish input for no arguments).

## Custom Implementation of `call` and `apply`

```javascript
Function.prototype.myCall = function(context, ...args) {
    if (context === null || (typeof context !== 'object' && typeof context !== 'function')) {
        throw new TypeError('This exercise requires an object receiver');
    }
    const key = Symbol('temporary call');
    Object.defineProperty(context, key, { value: this, configurable: true });
    try {
        return context[key](...args);
    } finally {
        delete context[key];
    }
};

Function.prototype.myApply = function(context, args) {
    const list = args == null ? [] : Array.prototype.slice.call(args);
    return this.myCall(context, ...list);
};

const receiver = { base: 10 };
function sum(a, b) { return this.base + a + b; }
console.log(sum.myCall(receiver, 1, 2)); // 13
console.log((function() { return arguments.length; }).myApply(receiver, [])); // 0

const cleanupTarget = {};
try {
    (function() { throw new Error('boom'); }).myCall(cleanupTarget);
} catch (error) {
    console.log(error.message); // boom; the error propagates
}
console.log(Reflect.ownKeys(cleanupTarget)); // []: temporary key was removed in finally
```

## Drawbacks of Arrow Functions and Situations Where They Can't Be Used

Arrow functions, introduced in ES2015, have lexical `this` and cannot be constructors. They are useful when those semantics fit the callback; they do not supply a dynamic receiver or their own `arguments` object.

### Arrow Functions and `this` Context
Arrow functions do not have their own `this`; they inherit it from the enclosing lexical scope.

1. **Dynamic callback receiver**: A regular DOM event-listener function receives the current target as `this`; an arrow does not. Use the event's `currentTarget` explicitly when choosing an arrow.

   ```typescript
   const btn = document.getElementById('btn');
   btn?.addEventListener('click', function(this: HTMLElement, event) {
       console.log(this === event.currentTarget); // true for this regular listener call
   });
   btn?.addEventListener('click', (event) => {
       console.log(event.currentTarget === btn); // use the event explicitly with an arrow
   });
   ```

2. **Call form and lexical `this`**: An ordinary function's receiver comes from its call; an arrow uses its enclosing context's receiver.

   ```javascript
   function f1() {
       console.log(this); // depends on how f1 is called and whether it is strict
   }

   const f2 = () => {
       console.log(this); // refers to the lexical scope's context
   };
   ```

### `arguments` Object and Rest Parameters
Arrow functions do not have an `arguments` object, unlike regular functions. This limitation can be circumvented using rest parameters.

```javascript
function f1() {
   // A regular function has its own `arguments` object.
}

const f2 = (...args) => {
   // An arrow uses this explicit list instead of its own `arguments`.
};
```

### Object and Prototype Methods
An arrow method does not receive the object or instance as its `this` value.

1. **Object Methods**:
   ```javascript
   const obj = {
       name: 'aaa',
       getName: () => this.name // uses the surrounding `this`, not `obj`
   };

   obj.getName(); // Does not read obj.name; outcome depends on the surrounding context
   ```

2. **Prototype Methods**:
   ```javascript
   function MyObject() {
       this.name = 'aaa';
   }

   MyObject.prototype.getName = () => this.name; // `this` is lexical, not the instance

   const myObj = new MyObject();
   myObj.getName(); // Does not read myObj.name
   ```

### Constructors
Arrow functions are not constructable and cannot be called with `new`; they have neither a constructor `prototype` property nor a `new.target` of their own.

```javascript
const Foo = (name, age) => {
    this.name = name;
    this.age = age;
};

const f = new Foo('aa', 20); // TypeError: Foo is not a constructor
```

**Summary**  
Choose an arrow when lexical `this` and no constructor behavior are intended. Use an ordinary method or function when the call site must supply `this`.

## Understanding Function Parameters and Arguments in JavaScript

JavaScript passes every argument by value. When the value is an object reference, the parameter receives a copy of that reference: property mutation is visible through the caller's reference, but rebinding the parameter is not.

### Formal and Actual Parameters
- **Formal parameters** are the parameters defined in a function's declaration.
- **Actual parameters** are the arguments passed to the function at call time.

### Primitive Types and Value Passing
- Reassigning a parameter that received a primitive does not change the caller's binding.
- **Example**:
  ```javascript
  function modifyPrimitive(value) {
      value = "changed";
      console.log("Inside function:", value); // Outputs: "Inside function: changed"
  }

  let originalValue = "original";
  modifyPrimitive(originalValue);
  console.log("Outside function:", originalValue); // Outputs: "Outside function: original"
  ```

### Reference Types and Reference Passing
- **Example**:
  ```javascript
  function setName(obj) {
    obj.name = "Nicholas";
    obj = new Object();
    obj.name = "Greg";
  }

  let person = new Object();
  setName(person);
  console.log(person.name); // Outputs: "Nicholas"
  ```

### Detailed Behavior Explanation
The function receives a copy of the object reference. Mutating the referenced object is visible to the caller; assigning a different object to the local parameter does not reassign the caller's variable.

### Best Practices
- Document whether a function mutates an object argument or returns a changed copy; choose cloning depth according to the data contract.

## Constructor Functions and Prototype Properties with the Same Name
```javascript
function Foo(){
    Foo.a = function(){
        console.log(1)
    }
    this.a = function(){
        console.log(2)
    }
}
Foo.prototype.a = function(){
    console.log(3)
}
Foo.a = function(){
    console.log(4)
}
Foo.a(); // Output: 4
let obj = new Foo(); 
obj.a(); // Output: 2
Foo.a(); // Output: 1
```

### Step-by-Step Breakdown

1. **Function Definition and Static Property Initialization**

   Initially, a function `Foo` is defined. Following its definition, `Foo.a` is assigned a function that logs `4`. This is a static property of the `Foo` function itself, not of its instances.

2. **Static Method Invocation**

   Invoking `Foo.a()` at this point outputs `4`, as it calls the function assigned to `Foo.a` before any instances of `Foo` are created.

3. **Instance Creation**

   When a new instance of `Foo` is created (`let obj = new Foo()`), several things happen inside the constructor function:
   
   - `Foo.a` is redefined to a function that logs `1`. This redefinition overwrites the initial static definition of `Foo.a` that logged `4`.
   - `this.a` is defined as a function that logs `2`. This assigns an `a` function to the newly created instance, which is separate from `Foo`'s static properties and its prototype.

4. **Instance Method Invocation**

   Invoking `obj.a()` now outputs `2`. This is because the instance (`obj`) has its own `a` property, which takes precedence over the `Foo` prototype's `a` property.

5. **Static Method Post-Instance Invocation**

   Calling `Foo.a()` after creating an instance of `Foo` outputs `1`. This is because the creation of an instance (`new Foo()`) redefined `Foo.a` to a new function that logs `1`.

**Key Takeaways**  
- **Static vs. Instance Properties**: Static properties defined on a constructor function itself (`Foo.a`) are separate from instance properties defined within the constructor using `this` keyword (`this.a`).
- **Prototype Properties**: Properties defined on the prototype (`Foo.prototype.a`) are shared across all instances. However, they have lower precedence compared to instance-specific properties.
- **Precedence and Overwriting**: When accessing a property, instance properties take precedence over prototype properties. Static properties can be redefined, affecting their behavior when accessed before and after instance creation.

## Write a `curry` function to curry other functions
Currying lets calls supply a function's arguments in stages. This version accepts any number of arguments at each stage, waits until `fn.length` arguments have arrived, and uses the receiver from the call that supplies enough arguments. It assumes a function with simple required parameters; default and rest parameters change what `fn.length` means.

```ts
function curry(fn: Function) {
    function collect(this: any, args: any[]): any {
        if (args.length >= fn.length) {
            return Reflect.apply(fn, this, args);
        }
        return function(this: any, ...nextArgs: any[]) {
            return collect.apply(this, [[...args, ...nextArgs]]);
        };
    }
    return function(this: any, ...args: any[]) {
        return collect.apply(this, [args]);
    };
}

function sum(a: number, b: number, c: number) {
    return a + b + c;
}

const curriedSum = curry(sum);
console.log(curriedSum(1)(2)(3)); // Output: 6
console.log(curriedSum(1, 2)(3)); // Output: 6
console.log(curriedSum(1)(2, 3)); // Output: 6

function addToBase(this: { base: number }, value: number, increment: number) {
    return this.base + value + increment;
}
const partial = curry(addToBase).call({ base: 1 }, 2);
console.log(partial.call({ base: 10 }, 3)); // 15: receiver from the completing call
```

## Understanding `['1', '2', '3'].map(parseInt)` Output
The `parseInt` function converts a string argument to an integer of the specified radix (base). Its signature is `parseInt(string, radix)`, where:
- `string` is the string to be parsed.
- `radix` (optional) specifies the base of the numeral system to be used. It can be between 2 and 36.

If `radix` is omitted or 0, `parseInt` uses decimal by default and recognizes a `0x`/`0X` prefix as hexadecimal. Specify a radix when the intended base is known:

- Hexadecimal (base 16) if the string starts with "0x" or "0X".
- Decimal (base 10) for all other cases.

The supplied radix must be 2 through 36 (or 0 for the inference rule above).

### Examples of `parseInt` Usage:

```typescript
parseInt('11', 2); // Returns 3. ('11' in binary equals 3 in decimal)
parseInt('3', 2); // Returns NaN. ('3' is not a valid binary number)
parseInt('A', 16); // Returns 10. ('A' in hexadecimal equals 10 in decimal)
parseInt('0x2F'); // Returns 47. Implicitly detects hexadecimal.
parseInt('1', 0); // Returns 1. (0 or unspecified radix defaults to base 10)
```

### Why `['1', '2', '3'].map(parseInt)` Returns `[1, NaN, NaN]`

When using `map` with `parseInt`, each element of the array is passed to `parseInt` along with its index. The `map` method calls the callback with three arguments: the current element, its index, and the entire array. In the case of `parseInt`, this means the second argument (the index) is used as the radix.

Breaking it down:

- `parseInt('1', 0)`: The radix is `0`, so `parseInt` treats it as base 10. The result is `1`.
- `parseInt('2', 1)`: The radix is `1`, which is not a valid radix, leading to `NaN`.
- `parseInt('3', 2)`: The radix is `2` (binary), and since '3' is not a valid binary digit, the result is `NaN`.

```typescript
const arr = ['1', '2', '3'];
const res = arr.map((item, index) => {
    // For '1', index is 0: parseInt('1', 0) => 1, since 0 is treated as base 10.
    // For '2', index is 1: parseInt('2', 1) => NaN, since 1 is not a valid radix.
    // For '3', index is 2: parseInt('3', 2) => NaN, since '3' is not a valid binary digit.
    return parseInt(item, index);
});
const decimalValues = arr.map(item => parseInt(item, 10));
```

The `map` callback receives `(value, index, array)`, so passing `parseInt` directly accidentally treats the index as its radix. For decimal integer strings, pass a callback with an explicit radix.

## New Methods Introduced in ES6
This retained heading is historical: `Object.is`, `Object.assign`, `Array.from`, and `Array.of` are ES2015 additions; `Object.keys` predates ES2015, while `Object.values` and `Object.entries` were added in ES2017.

### Object Methods
**Object Manipulation Functions**
- **`Object.is(value1, value2)`**: Compares any two values using SameValue semantics: `NaN` equals itself, while `+0` and `-0` differ.
- **`Object.assign(target, ...sources)`**: Shallowly copies enumerable own string and Symbol properties. It reads source values and writes to the target, so getters/setters can run; it does not deep-clone.

**Retrieval Functions**
- **`Object.keys(obj)`**: Returns own enumerable string keys.
- **`Object.values(obj)`**: Returns values for own enumerable string keys.
- **`Object.entries(obj)`**: Returns `[key, value]` pairs for own enumerable string keys; Symbol keys are omitted.

### Array Methods
**Creation Functions**
- **Array.from(obj, mapFn?, thisArg?)**: Creates a new, shallow-copied Array instance from an array-like or iterable object. Optional parameters allow mapping each element through a function, transforming them during creation.
- **Array.of(...elements)**: Creates a new Array instance with a variable number of elements, regardless of number or type of the arguments. This method is especially useful when you want to create an array from a set of elements.

#### Practical Examples

**Using Object.assign to merge objects:**
```javascript
const obj1 = { a: 1 };
const obj2 = { b: 2 };
const mergedObj = Object.assign({}, obj1, obj2);
console.log(mergedObj); // Output: { a: 1, b: 2 }
```

**Using Array.from to convert a NodeList to an Array:**
```javascript
const nodeList = document.querySelectorAll('div'); // NodeList of div elements
const nodesArray = Array.from(nodeList);
console.log(nodesArray); // Output: [div, div, ...]
```

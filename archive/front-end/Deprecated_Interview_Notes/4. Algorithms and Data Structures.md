## Linked Lists in Front-End Systems / 前端系统中的链表

A linked list can insert after a known node in a singly linked list, or insert/remove a known node in a doubly linked list, in constant time when the needed links are available. Removing an arbitrary known node from a singly linked list normally also requires its predecessor; locating a node is linear. Each node adds allocation and pointer-traversal overhead. Arrays often perform better for small or scan-heavy workloads because of compact storage and locality; measure the actual operation mix.

React's Fiber reconciler uses a node structure with links such as `child`, `sibling`, and `return` to represent and traverse work. This implementation detail helps explain how React can organize reconciliation work, but it is not a general claim that linked lists make rendering faster or that applications should implement a Fiber tree themselves. React's scheduling and rendering behavior can change between versions.

### Queue with a Linked List / 使用链表实现队列

Keep references to the head and tail. Enqueue appends at the tail; dequeue removes from the head. Both are O(1) when those references are maintained. An empty dequeue needs a defined result, and removing the last node must clear both references.

A linked-list queue is not automatically faster than an array queue. `shift()` typically has to preserve the indexed sequence; a head-index or circular-buffer queue can avoid repeated shifting while retaining array locality.

## implement a queue with linkedlist
```ts
interface ILinkedListNode {
    val: number;
    next: ILinkedListNode | null;
}

class Queue {
    // undefined usually used for uninitialized value, null for empty values, here null is better
    private head: ILinkedListNode | null;
    private tail: ILinkedListNode | null;
    private len: number;

    // use constructor instead of set values above, make code more readable
    // Inside class methods, use this to refer to instance variables 
    constructor(){
        this.head = null;
        this.tail = null;
        this.len = 0;
    }

    // for better clarity, mention return type void if return nothing
    offer(val: number): void {
        const temp: ILinkedListNode = {val: val, next: null};
        // in case the queue is empty, use === check value and type
        if (this.head === null) {
            this.head = temp;
            this.tail = temp;
        } 
        // normal case
        else {
            // avoid non-null assertions to avoid legitimate null/undefined errors, i.e. try avoid below commented code
            // this.tail!.next = temp;
            if (this.tail) {
                this.tail.next = temp;
            }
            this.tail = temp;
        }
        this.len += 1;
    }

    poll(): number | null {
        if (this.head === null) {
            return null;
        } 
        if (this.head.next === null) {
            this.tail = null;
        }
        // here use const instead of let, since it never changes
        const temp = this.head.val;
        this.head = this.head.next;
        this.len -= 1;
        return temp;
    }

    // with get keyword, we can use the return value as an attribute, e.g. const queue = new Queue(); const len = queue.size;
    get size(): number {
        return this.len;
    }
}
```

## Stack
Stack is a Last In, First Out (LIFO) data structure, commonly used in computing for various tasks such as managing function calls and evaluating expressions. It supports two primary operations: `push` and `pop`. The `push` operation adds an element to the top of the stack, while `pop` removes and returns the top element.

### Operations
**Push**: Adds an element to the top of the stack. 
**Pop**: Removes the top element from the stack.
**Peek**: Returns the top element without removing it.
**IsEmpty**: Checks if the stack is empty.

```js
function Stack() {
  this.stack = [];
}

Stack.prototype.push = function(value) {
  this.stack.push(value);
}

Stack.prototype.pop = function() {
  return this.stack.pop();
}

Stack.prototype.peek = function() {
  return this.stack[this.stack.length - 1];
}

Stack.prototype.isEmpty = function() {
  return this.stack.length === 0;
}

const stack = new Stack();
stack.push(1);
stack.push(2);
stack.push(3);
console.log(stack.pop()); // Output: 3
console.log(stack.peek()); // Output: 2
console.log(stack.isEmpty()); // Output: false
```

### Applications
Stacks are versatile structures used in various programming scenarios:
- **Webpack Loader**: Manages the transformations applied to modules.
- **Browser History**: Tracks the pages visited in a session for backward navigation.
- **Depth-First Search (DFS)**: Utilized in traversing graphs or trees where nodes are explored as deep as possible before backtracking.

Each application leverages the LIFO property of the stack to manage data efficiently in scenarios where the last entered item needs to be accessed first.

## In-order, Pre-order, and Post-order / 中序、前序与后序遍历
In the context of binary trees, in-order, pre-order, and post-order refer to the three primary ways to traverse the nodes of the tree, each with a different order for visiting the nodes.
**In-Order Traversal**: Left, Root, Right.
**Pre-Order Traversal**: Root, Left, Right.
**Post-Order Traversal**: Left, Right, Root.

## Find the kth Smallest Value in a BST / 查找二叉搜索树中的第 k 小值

An in-order traversal visits BST values in nondecreasing order. This iterative version returns `null` when `k` is invalid or exceeds the number of nodes; duplicate values occupy separate positions in that order.

```ts
interface TreeNode {
    val: number;
    left: TreeNode | null;
    right: TreeNode | null;
}

function findKthSmallest(root: TreeNode | null, k: number): number | null {
    if (!Number.isInteger(k) || k < 1) return null;
    const stack: TreeNode[] = [];
    let node = root;
    let visited = 0;

    while (node !== null || stack.length > 0) {
        while (node !== null) {
            stack.push(node);
            node = node.left;
        }
        const current = stack.pop();
        if (current === undefined) break;
        if (++visited === k) return current.val;
        node = current.right;
    }
    return null;
}
```

Time is O(h + k) for a tree of height `h`; the explicit stack uses O(h) space. An unbalanced BST can have `h = n`.

## Binary Trees, Balance, and Multiway Trees / 二叉树、平衡与多路树

Binary search trees are not universally faster than arrays or linked lists. A balanced search tree can provide O(log n) search, insert, and delete; a plain BST can degenerate to O(n). An array offers O(1) indexed access, while a linked list requires O(n) to locate an arbitrary position.

Binary trees are common because their operations and implementations are comparatively simple, not because binary branching is always optimal. A balanced `b`-way search tree can have height O(log_b n), with per-node search cost depending on its key layout. B-trees and B+ trees use high fan-out to reduce page reads in storage systems; B+ tree leaves are commonly linked for ordered range scans. Red-black trees maintain logarithmic height with color invariants and are used for ordered in-memory maps and sets. Exact implementation details depend on the library or database.

“Balanced” must refer to a structure with a bound on height, such as AVL or red-black trees. Balance makes search and updates logarithmic only when the tree maintains its invariants; a generic binary tree does not provide that guarantee. Updating an already-found value is O(log n) only when the lookup path is bounded by the balanced height.

## Identify whether a string is prefix of a word in dictionary
A trie (prefix tree) is useful when many prefix queries share a dictionary. Each edge represents a character, the root represents the empty prefix, and a node can mark the end of a stored word. Other indexes or a direct scan may be simpler for small dictionaries or few queries.

To check if a string is a prefix of any word in the dictionary, we insert each word into the Trie. Then, for the given string, we traverse the Trie from the root. If we can traverse the Trie following the characters of the string without any breaks, and reach a node (not necessarily a leaf node), then the string is a valid prefix in the dictionary.

With expected O(1) child lookup (for example, a hash map per node), inserting all words takes O(L) expected time for total input length `L`, and a prefix lookup takes O(m) expected time for prefix length `m`. Memory use and alphabet/child-map representation are important trade-offs.

For `apple`, one possible path is `root → a → p → p → l → e`; mark the final node as a word end. The prefix `app` exists even though it is not a complete stored word.

## Depth-First Search (DFS) of a DOM Tree / DOM 深度优先遍历
Depth-First Search (DFS) is a method used to traverse or search a tree or graph data structure. The algorithm starts at the root node and explores as far as possible along each branch before backtracking. When applied to a DOM tree, DFS will visit each node in a manner that deeply explores a node's children before moving to its siblings.

The given TypeScript function `dfs` illustrates how DFS can be applied to a DOM tree. The `visitNode` function is used to log different types of nodes (Comment, Text, HTMLElement). In the `dfs` function, recursion is utilized to visit each node starting from the root, exploring all its child nodes deeply before moving to the next sibling.

```typescript
function visitNode(node: Node) {
    if (node instanceof Comment) {
        console.log('comment', node.textContent);
    }
    if (node instanceof Text) {
        const t = node.textContent.trim();
        if (t) {
            console.log('text', t);
        }
    }
    if (node instanceof HTMLElement) {
        console.log('element', node.tagName);
    }
}

function dfs(node: Node) {
    visitNode(node);
    node.childNodes.forEach((child) => {
        dfs(child);
    });
}
```

### Without Recursion
DFS can be implemented without recursion by using a stack to simulate the call stack of recursion. This approach avoids potential stack overflow errors that may occur with deep recursion. While recursion is more straightforward and readable, using a stack can be more efficient and safer for deep trees.

```typescript
function dfsWithoutRecursion(node: Node) {
    const stack = [node];
    while (stack.length) {
        const n = stack.pop();
        if (n === undefined) continue;
        visitNode(n);
        Array.from(n.childNodes).reverse().forEach((child) => {
            stack.push(child);
        });
    }
}
```

## Breadth-First Search (BFS) of a DOM Tree / DOM 广度优先遍历
Breadth-First Search (BFS) is another method to traverse or search a tree or graph data structure. Unlike DFS, BFS explores all the neighbor nodes at the present depth prior to moving on to the nodes at the next depth level. Applied to a DOM tree, BFS will visit each node level by level.

The `bfs` function demonstrates how BFS can be applied to a DOM tree. It uses a queue to visit each node at the current level before moving to the nodes at the next level. This approach ensures that nodes are visited in a breadth-wise manner.

```typescript
function bfs(root: Node) {
    const queue: Node[] = [root];
    for (let head = 0; head < queue.length; head++) {
        const node = queue[head];
        if (node === undefined) continue;
        visitNode(node);
        node.childNodes.forEach(child => queue.push(child));
    }
}
```

### Key Differences Between DFS and BFS
- **DFS** dives as deep as possible into the tree's branches before backtracking, which can be implemented either recursively or using a stack.
- **BFS** visits all nodes at the current level before moving to the next level, using a queue to keep track of the order.

## Array to Tree and Tree to Array / 数组与树互转

A parent-ID list can represent a forest. Build a node map first, then attach each node to its parent; sorting by `parentId` does not guarantee that a parent appears before its descendants. This version rejects duplicate IDs, missing parents, and cycles, and it does not mutate the input. `treeToArray` assumes its input is already a valid forest.

```ts
interface TreeNode {
    id: number;
    name: string;
    children: TreeNode[];
}

interface ArrayItem {
    id: number;
    parentId: number | null;
    name: string;
}

function arrayToForest(items: ArrayItem[]): TreeNode[] {
    const nodes = new Map<number, TreeNode>();
    for (const item of items) {
        if (nodes.has(item.id)) throw new Error(`Duplicate id: ${item.id}`);
        nodes.set(item.id, { id: item.id, name: item.name, children: [] });
    }

    const roots: TreeNode[] = [];
    for (const item of items) {
        const node = nodes.get(item.id);
        if (!node) throw new Error(`Missing node: ${item.id}`);
        if (item.parentId === null) {
            roots.push(node);
        } else {
            const parent = nodes.get(item.parentId);
            if (!parent) throw new Error(`Missing parent: ${item.parentId}`);
            parent.children.push(node);
        }
    }

    const seen = new Set<number>();
    const stack = roots.slice();
    while (stack.length > 0) {
        const node = stack.pop();
        if (!node) continue;
        if (seen.has(node.id)) throw new Error(`Cycle or repeated node: ${node.id}`);
        seen.add(node.id);
        for (const child of node.children) stack.push(child);
    }
    if (seen.size !== nodes.size) throw new Error('Cycle detected');
    return roots;
}

function treeToArray(roots: TreeNode[]): ArrayItem[] {
    const result: ArrayItem[] = [];
    const stack = roots.map(node => ({ node, parentId: null as number | null })).reverse();
    while (stack.length > 0) {
        const entry = stack.pop();
        if (!entry) continue;
        result.push({ id: entry.node.id, parentId: entry.parentId, name: entry.node.name });
        for (let i = entry.node.children.length - 1; i >= 0; i--) {
            stack.push({ node: entry.node.children[i], parentId: entry.node.id });
        }
    }
    return result;
}
```

The conversion is O(n) expected time with a hash map, plus the cost of producing the result. A tree is only one representation: relational schemas can store parent keys or other hierarchy relations, while document stores can nest records. Choose based on query and update patterns rather than assuming a database model must mirror an in-memory tree.

## Dynamic Programming and Fibonacci / 动态规划与斐波那契数列

Dynamic programming applies when a problem has overlapping subproblems and an optimal substructure or count recurrence. Memoization stores recursive results; tabulation fills results iteratively. The state definition and transition determine correctness.

The naive recursive Fibonacci function repeats the same subproblems: its time is exponential (O(φⁿ), bounded by O(2ⁿ)) while its maximum call depth is O(n). It can become impractically slow long before call-stack depth is the limiting factor.

```ts
function fibonacciNaive(n: number): number {
    if (!Number.isInteger(n) || n < 0) throw new RangeError('n must be a non-negative integer');
    if (n < 2) return n;
    return fibonacciNaive(n - 1) + fibonacciNaive(n - 2);
}
```

An iterative solution keeps only the previous two states, so it uses O(n) arithmetic operations and O(1) extra space. With JavaScript `number`, exact integer results are guaranteed only while the result is at most `Number.MAX_SAFE_INTEGER`; use `bigint` when larger exact results are required.

```ts
function fibonacciDP(n: number): number {
    if (!Number.isSafeInteger(n) || n < 0) throw new RangeError('n must be a non-negative safe integer');
    if (n < 2) return n;
    let previous = 0;
    let current = 1;
    for (let i = 2; i <= n; i++) {
        [previous, current] = [current, previous + current];
    }
    return current;
}
```

The loop is O(n) time and O(1) extra space. For exact larger values, use the same recurrence with `0n`, `1n`, and a `bigint` return type.

## Staircase Counting / 爬楼梯计数

If a frog may jump one or two steps, let `dp[i]` be the number of ordered jump sequences that reach step `i`. Then `dp[i] = dp[i - 1] + dp[i - 2]`, with one way to stay at step zero. Counts can exceed JavaScript's safe integer range.

```ts
function frogJumpDP(n: number): number {
    if (!Number.isSafeInteger(n) || n < 0) throw new RangeError('n must be a non-negative safe integer');
    if (n === 0) return 1;
    let previous = 1; // dp[0]
    let current = 1;  // dp[1]
    for (let i = 2; i <= n; i++) {
        [previous, current] = [current, previous + current];
    }
    return current;
}
```

For allowed step sizes such as `[1, 3, 5]`, this tabulation counts ordered sequences and permits reusing a step size. Duplicate entries are removed so one jump size is not counted twice. All step sizes must be positive integers.

```ts
function frogJumpVariadic(n: number, steps: number[]): number {
    if (!Number.isSafeInteger(n) || n < 0) throw new RangeError('n must be non-negative');
    if (steps.some(step => !Number.isSafeInteger(step) || step <= 0)) {
        throw new RangeError('step sizes must be positive safe integers');
    }
    const allowed = [...new Set(steps)];
    const dp = new Array<number>(n + 1).fill(0);
    dp[0] = 1;
    for (let i = 1; i <= n; i++) {
        for (const step of allowed) {
            if (i >= step) dp[i] += dp[i - step];
        }
    }
    return dp[n];
}
```

The second solution uses O(n) space and O(n × number-of-step-sizes) time. If the problem asks for combinations where jump order does not matter, the loop order and state transition must change.

## 01 Knapsack Problem
In the 0-1 Knapsack problem, you are given a set of items, each with a weight and a value. The goal is to determine the maximum value of items that can be packed into a knapsack with a limited carrying capacity. Each item can either be included in its entirety or excluded; partial items are not allowed.

```java
public class Knapsack01 {

    /**
     * Calculates the maximum value that can be packed into the knapsack.
     *
     * @param W the maximum weight capacity of the knapsack
     * @param weights array of item weights
     * @param values array of item values
     * @param n number of items
     * @return the maximum value that fits in the knapsack
     */
    public static int knapsack(int W, int[] weights, int[] values, int n) {
        // dp[w] will hold the maximum value that can be attained with a knapsack capacity of w
        int[] dp = new int[W + 1];

        // Process each item
        for (int i = 0; i < n; i++) {
            // Iterate through all capacities from max to the weight of the current item
            for (int w = W; w >= weights[i]; w--) {
                // Update dp[w] to the maximum of itself and the value of taking item i
                dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
            }
        }

        return dp[W];
    }

    public static void main(String[] args) {
        int[] weights = {1, 3, 4};
        int[] values = {1500, 2000, 3000};
        int W = 4; // Maximum weight capacity of the knapsack
        int n = weights.length; // Number of items

        int maxVal = knapsack(W, weights, values, n);
        System.out.println("Maximum value that can be packed: " + maxVal); // 3500 for the sample above
    }
}
```

#### Key Concepts Explained

- **Dynamic Programming Array (`dp`)**: The `dp` array is central to the solution, where `dp[w]` represents the maximum value that can be achieved with a knapsack capacity of `w`.
- **Iteration Order**: It's crucial to iterate the weights in reverse when considering each item, as this ensures that each item is only considered once per capacity.
- **Item Processing**: For each item, we compare the maximum value of not taking the item (`dp[w]`) versus taking the item (`dp[w - weights[i]] + values[i]`), thus ensuring that we always store the best solution for every capacity.

## Implement binary search and describe time complexity
```ts
// assume input nums is in ascending order, return the index or null if not found
function binarySearch(nums: number[], target: number): number | null {
    let left: number = 0;
    let right: number = nums.length - 1;
    // use <= for case length = 1
    while (left <= right) {
        // Use Math.floor to avoid floating point values for the mid index.
        let mid: number = Math.floor((left + right) / 2);
        if (nums[mid] === target) {
            return mid;
        }
        if (nums[mid] > target) {
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    return null;
}
```
Binary search has a time complexity of O(log n), where n is the number of elements in the array. This is because the algorithm divides the search interval in half with each step.

function twoSumsAscending(nums: number[], target: number): number[]{
    let left: number = 0;
    let right: number = nums.length - 1;

    while (left < right) {

        if (nums[left] + nums[right] < target) {
            left++;
        } else {
            right--;
        }

## Identify the longest sequence of a continuous character in a given string. 
For example, for the string 'aabaacceee', the function should return 'e'.
```ts
interface IRes {
    char: string;
    len: number;
}

function findLongest(s: string): IRes {
    if (s.length === 0) return { char: '', len: 0 }; // Handle empty string

    let longestChar: string = s.charAt(0);
    let longest: number = 1;
    let currentChar: string = s.charAt(0);
    let currentLength: number = 1;

    for (let i = 1; i < s.length; i++) {
        if (s.charAt(i) === currentChar) {
            currentLength++;
        } else {
            if (currentLength > longest) {
                longest = currentLength;
                longestChar = currentChar;
            }
            currentChar = s.charAt(i);
            currentLength = 1;
        }
    }

    // Check and update for the last character sequence
    if (currentLength > longest) {
        longest = currentLength;
        longestChar = currentChar;
    }

    return { char: longestChar, len: longest };
}

```

## Quicksort / 快速排序

This in-place Hoare-style partition uses the middle-position value as a pivot. It avoids allocating new partitions and handles repeated values without sending every equal item into one recursive side. Balanced partitions cost O(n log n); an O(n log n) average-cost claim assumes an input distribution that yields reasonably balanced partitions on average. Choosing the middle index is deterministic and does not itself provide that distribution. Worst-case time is O(n²), and stack use is O(log n) on balanced partitions but O(n) in the worst case. It mutates the input array.

```ts
function quickSort(nums: number[], left = 0, right = nums.length - 1): number[] {
    if (left >= right) return nums;
    const pivot = nums[Math.floor((left + right) / 2)];
    let i = left;
    let j = right;

    while (i <= j) {
        while (nums[i] < pivot) i++;
        while (nums[j] > pivot) j--;
        if (i <= j) {
            [nums[i], nums[j]] = [nums[j], nums[i]];
            i++;
            j--;
        }
    }

    if (left < j) quickSort(nums, left, j);
    if (i < right) quickSort(nums, i, right);
    return nums;
}
```

For adversarial inputs or a hard stack bound, use a well-tested library sort or an iterative/introspective variant rather than relying on one pivot rule.

## Palindrome Numbers / 回文数

These examples list non-negative integer palindromes up to and including `max`. The string version is easy to inspect; the numeric reversal shows the arithmetic approach. Inputs outside the safe-integer range need a different representation.

```ts
function findPalindromesByString(max: number): number[] {
    if (!Number.isSafeInteger(max) || max < 0) throw new RangeError('max must be a non-negative safe integer');
    const result: number[] = [];
    for (let value = 0; value <= max; value++) {
        const text = String(value);
        if (text === [...text].reverse().join('')) result.push(value);
    }
    return result;
}

function findPalindromesByReversing(max: number): number[] {
    if (!Number.isSafeInteger(max) || max < 0) throw new RangeError('max must be a non-negative safe integer');
    const result: number[] = [];
    for (let value = 0; value <= max; value++) {
        let remaining = value;
        let reversed = 0;
        while (remaining > 0) {
            reversed = reversed * 10 + (remaining % 10);
            remaining = Math.floor(remaining / 10);
        }
        if (reversed === value) result.push(value);
    }
    return result;
}
```

Both include `0`; for a very large `max`, producing every result itself requires substantial time and memory.

## Format Integer Thousands / 整数千位分隔

For general locale-aware formatting, use `Intl.NumberFormat`. This small exercise handles safe integers and groups decimal digits in threes without counting a minus sign as a digit.

```ts
function formatIntegerThousands(value: number): string {
    if (!Number.isSafeInteger(value)) throw new RangeError('value must be a safe integer');
    const digits = String(Math.abs(value));
    let grouped = '';
    for (let i = 0; i < digits.length; i++) {
        if (i > 0 && (digits.length - i) % 3 === 0) grouped += ',';
        grouped += digits.charAt(i);
    }
    return value < 0 ? `-${grouped}` : grouped;
}
```

Examples: `1000 → "1,000"`, `-12000000 → "-12,000,000"`. Decimal, exponent, and locale-specific formatting are outside this exercise.

## Switch letter case, e.g. aBc123D -> AbC123d
```ts
function switchLetterCase(s: string): string {
    let res = ""

    // according to ascii table, A-Z is 65-90, a-z is 97-122
    const UPPER_CASE_A = 65;
    const UPPER_CASE_Z = 90;
    const LOWER_CASE_A = 97;
    const LOWER_CASE_Z = 122;

    for (let i = 0; i < s.length; i++) {
        const code = s.charCodeAt(i);
        if (code >= UPPER_CASE_A && code <= UPPER_CASE_Z) {
            // Convert to lower case
            res += String.fromCharCode(code + 32); 
        } else if (code >= LOWER_CASE_A && code <= LOWER_CASE_Z) {
            // Convert to upper case
            res += String.fromCharCode(code - 32); 
        } else {
            // Non-alphabetic characters are unchanged
            res += s.charAt(i); 
        }
    }

    return res
}
```

## Deadlock / 死锁

A classic resource deadlock requires a cycle of participants waiting for resources held by one another; the usual necessary conditions are mutual exclusion, hold-and-wait, no preemption, and circular wait. These are general operating-system/concurrency concepts, not a description of ordinary browser JavaScript's single-threaded DOM access.

A pending Promise or two async functions waiting on one another can remain unresolved, but that is a dependency cycle or liveness failure rather than automatically an OS resource deadlock. Worker threads, locks over shared memory, database locks, and external resources need their own concurrency analysis; see [processes, threads, and concurrency](../../../engineering-foundations/operating-systems/processes-threads-and-concurrency.md).

## Java HashMap / Java 哈希表

A hash table maps keys to buckets using a hash function. Collisions are expected; the implementation must resolve them, and lookup performance depends on hash distribution, resizing, and the key's equality/hash contract.

For OpenJDK 25, `HashMap` first spreads a key hash with `h ^ (h >>> 16)` before indexing its bucket array. Its source defines `TREEIFY_THRESHOLD` as 8 and `MIN_TREEIFY_CAPACITY` as 64. In the ordinary `putVal` path, the bin-count check runs while a new node is appended; when the table is below the minimum capacity, the treeification helper resizes instead. Thus a bin length of eight alone is not an unconditional treeification rule. The default load factor is 0.75; the implementation resizes when its threshold is exceeded. These are implementation details, not guarantees of the Java `Map` interface.

When implementing a hash-based map, preserve the invariant that equal keys have equal hash codes, and expect collisions. When using Java's `HashMap`, consult the Javadoc for its API-level complexity guidance and the matching JDK source only when an implementation detail matters.

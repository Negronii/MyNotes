# TypeScript Utility Types / TypeScript 工具类型

**Core / 核心：** Utility types transform static types for checking and editor feedback; they do not validate or reshape runtime values. 工具类型转换静态类型以供检查与编辑器提示；它们不会在运行时校验或重塑值。

**Key terms / 关键词：** type transformation 类型转换 · union 联合类型 · mapped type 映射类型 · erasure 擦除 · contextual `this` 上下文 `this`

Type annotations, interfaces, and type aliases are erased from emitted JavaScript. Some TypeScript constructs do emit JavaScript, so “types are erased” does not mean every TypeScript-only syntax disappears without runtime output. The examples below are independent snippets and may repeat names.

`Readonly<T>` only constrains writes through that static type, and only at the top level; it does not freeze an object at runtime or prevent mutation through another alias. Likewise, utility types do not prove that untrusted input has the described shape.

### Utility Types in TypeScript

TypeScript provides several built-in utility types that help in transforming types in useful ways. Below are some commonly used utility types:

1. **Partial<Type>**

   The `Partial` utility type constructs a type with all properties of `Type` set to optional. This is useful when you want to work with objects that may not have all properties defined.

   ```typescript
   interface User {
       id: number;
       name: string;
       email: string;
   }

   const updateUser = (user: Partial<User>) => {
       // user can have any or all properties of User
   };

   updateUser({ name: "Alice" }); // Valid
   ```

2. **Required<Type>**

   The `Required` utility type constructs a type with all properties of `Type` set to required. This is the opposite of `Partial`.

   ```typescript
   interface User {
       id?: number;
       name?: string;
       email?: string;
   }

   const createUser = (user: Required<User>) => {
       // user must have all properties of User
   };

   createUser({ id: 1, name: "Alice", email: "alice@example.com" }); // Valid
   ```

3. **Readonly<Type>**

   The `Readonly` utility type constructs a type with all properties of `Type` set to readonly. This prevents properties from being modified.

   ```typescript
   interface User {
       id: number;
       name: string;
       email: string;
   }

   const getUser = (): Readonly<User> => {
       return { id: 1, name: "Alice", email: "alice@example.com" };
   };

   const user = getUser();
   user.name = "Bob"; // Error: Cannot assign to 'name' because it is a read-only property.
   ```

4. **Pick<Type, Keys>**

   The `Pick` utility type constructs a type by picking a set of properties from `Type`.

   ```typescript
   interface User {
       id: number;
       name: string;
       email: string;
   }

   type UserSummary = Pick<User, "id" | "name">;

   const user: UserSummary = {
       id: 1,
       name: "Alice",
   };
   ```

5. **Omit<Type, Keys>**

   The `Omit` utility type constructs a type by excluding a set of properties from `Type`.

   ```typescript
   interface User {
       id: number;
       name: string;
       email: string;
   }

   type UserWithoutEmail = Omit<User, "email">;

   const user: UserWithoutEmail = {
       id: 1,
       name: "Alice",
   };
   ```

6. **Record<Keys, Type>**

   The `Record` utility type constructs an object type whose property keys are `Keys` and whose property values are `Type`.

   ```typescript
   type Role = "admin" | "user" | "guest";

   const userRoles: Record<Role, number> = {
       admin: 1,
       user: 2,
       guest: 3,
   };
   ```

7. **Exclude<UnionType, ExcludedMembers>**

   The `Exclude` utility type constructs a type by excluding from `UnionType` all union members that are assignable to `ExcludedMembers`.

   ```typescript
   type T = Exclude<"a" | "b" | "c", "a">; // "b" | "c"
   ```

8. **Extract<UnionType, ExtractedMembers>**

   The `Extract` utility type constructs a type by extracting from `UnionType` all union members that are assignable to `ExtractedMembers`.

   ```typescript
   type T = Extract<"a" | "b" | "c", "a" | "b">; // "a" | "b"
   ```

9. **NonNullable<Type>**

   The `NonNullable` utility type constructs a type by excluding `null` and `undefined` from `Type`.

   ```typescript
   type T = NonNullable<string | number | undefined>; // string | number
   ```

10. **ReturnType<Type>**

    The `ReturnType` utility type constructs a type consisting of the return type of function `Type`.

    ```typescript
    function getUser() {
        return { id: 1, name: "Alice", email: "alice@example.com" };
    }

    type User = ReturnType<typeof getUser>;
    ```

11. **InstanceType<Type>**

    The `InstanceType` utility type constructs a type consisting of the instance type of a constructor function `Type`.

    ```typescript
    class User {
        id: number;
        name: string;
        email: string;

        constructor(id: number, name: string, email: string) {
            this.id = id;
            this.name = name;
            this.email = email;
        }
    }

    type UserType = InstanceType<typeof User>;
    ```

12. **Parameters<Type>**

    The `Parameters` utility type constructs a tuple type consisting of the parameter types of function `Type`.

    ```typescript
    function createUser(id: number, name: string, email: string) {
        return { id, name, email };
    }

    type CreateUserParams = Parameters<typeof createUser>; // [number, string, string]
    ```

13. **ConstructorParameters<Type>**

    The `ConstructorParameters` utility type constructs a tuple or array type consisting of the parameter types of a constructor function `Type`.

    ```typescript
    class User {
        constructor(public id: number, public name: string, public email: string) {}
    }

    type UserConstructorParams = ConstructorParameters<typeof User>; // [number, string, string]
    ```

14. **ThisType<Type>**

    `ThisType<T>` is a contextual-typing marker for the `this` value inside an object literal. It requires `noImplicitThis`; it does not add a runtime property or bind `this`. An explicit `this: Person` parameter, shown afterward, is a separate TypeScript feature.

    ```typescript
    type ObjectDescriptor<Data, Methods> = {
        data: Data;
        methods: Methods & ThisType<Data & Methods>;
    };

    function makeObject<Data, Methods>(
        descriptor: ObjectDescriptor<Data, Methods>
    ): Data & Methods {
        return { ...descriptor.data, ...descriptor.methods };
    }

    const counter = makeObject({
        data: { value: 0 },
        methods: {
            increment() {
                this.value += 1; // contextually typed as number
            }
        }
    });
    counter.increment();
    ```

    An explicit `this` parameter can type one function's receiver directly:

    ```typescript
    interface Person {
        name: string;
        greet(this: Person): void;
    }

    const person: Person = {
        name: "Alice",
        greet() {
            console.log(`Hello, my name is ${this.name}`);
        }
    };
    ```

# Which ahooks contracts matter when maintaining an existing React app? / 维护已有 React 应用时，哪些 ahooks 契约需要核对？

Identify what the Hook owns, then check what arguments and results the installed version promises. Pay particular attention to cancellation, what a list service returns on each page, and which key survives insertion or deletion. / 先确定 Hook 管什么，再核对已安装版本的参数与返回契约。重点看取消、分页服务每次返回的数据，以及插入或删除后哪个 key 仍稳定。

The [current ahooks chapter](../../../frontend/libraries/ahooks.md) explains when a helper is a good fit. The contract examples below show what can break in an existing call site. The v2.6 sizing example is a version-specific maintenance reference.

## Request controls and cancellation / 请求控制与取消

useRequest runs its Promise-returning service on mount by default; manual mode starts only when run or runAsync is called. run reports failures through the Hook's error callbacks, while runAsync returns a Promise for the caller to handle. cancel ignores the current result and can stop polling or queued work, but it does not abort a request already sent by the transport. / useRequest 默认在挂载时执行返回 Promise 的服务；manual 模式下只有调用 run 或 runAsync 才会开始。run 通过 Hook 的错误回调处理失败，runAsync 则返回 Promise 供调用方处理。cancel 会忽略当前结果并可停止轮询或排队工作，但不会中止已经发出的网络请求。

| Control | Contract in the archived v3.10.0 reference |
|---|---|
| manual | Skip automatic execution; wait for run or runAsync. |
| defaultParams | Parameters for the first automatic execution. |
| data, error, loading, params | Most recent request state; params is the argument array for the latest service call. |
| run(...params) | Start the request and return void; errors go through onError. |
| runAsync(...params) | Start the request and return a Promise; an ignored or superseded request rejects with ahooks CancelledError. |
| refresh / refreshAsync | Repeat the request using the last parameters. |
| mutate(data or updater) | Replace request data or derive it from the previous data. |
| onBefore / onSuccess / onError / onFinally | Observe service start, resolution, failure, and completion; cancelled work may be ignored before onFinally. |
| retryCount / retryInterval | In v3.10.0, configure retry count and delay. |

Call run from an event handler or a real Effect; calling it during render starts a side effect in the wrong lifecycle phase. This cancellation contract is separate from transport abort: pass an AbortSignal into the request service when the network operation itself must stop.

Version boundary: ahooks v2 used debounceInterval and throttleInterval request options; the v3.10.0 reference uses debounceWait and throttleWait. The v3 upgrade guide removed request options such as pagination, loadMore, formatResult, and fetchKey; use the dedicated list Hooks for those cases. Check the installed package version before relying on defaults or removed options.

**Sources checked 2026-10-15:** [ahooks useRequest guide](https://ahooks.js.org/hooks/use-request), [v3.10.0 request option types](https://raw.githubusercontent.com/alibaba/hooks/v3.10.0/packages/hooks/src/useRequest/src/types.ts), [v3.10.0 Fetch implementation](https://raw.githubusercontent.com/alibaba/hooks/v3.10.0/packages/hooks/src/useRequest/src/Fetch.ts), [v2-to-v3 upgrade guide](https://ahooks.js.org/guide/upgrade/). See the maintained [ahooks note](../../../frontend/libraries/ahooks.md) for the canonical current summary.

## List-loading service contracts / 列表加载的服务契约

usePagination models a numbered page: its service receives current and pageSize and resolves to list plus total. useInfiniteScroll models an accumulated list: for downward loading the service receives current data, returns the next page, and the Hook merges its list. Both need an explicit service contract and visible loading, error, and continuation states. / usePagination 表示编号分页：服务接收 current 和 pageSize，返回 list 与 total。useInfiniteScroll 表示累积列表：向下加载时服务接收当前数据并返回下一页，由 Hook 合并 list。两者都需要明确服务契约，并呈现加载、错误和继续状态。

The pagination result exposes current, pageSize, total, totalPage, and change methods such as changeCurrent and changePageSize. Infinite-scroll state includes data, loading, loadingMore, error, noMore, loadMore, reload, mutate, and cancel. Its target selects a scroll container, threshold controls how near the edge to load, and isNoMore defines the stopping condition.

~~~jsx
const { data, loading, pagination } = usePagination(
  ({ current, pageSize }) => fetchUsers({ current, pageSize }),
  { defaultPageSize: 20 }
);

pagination.changeCurrent(2);
~~~

A complete infinite-scroll example makes the accumulated-data contract explicit:

~~~jsx
import { useInfiniteScroll } from 'ahooks';
import { useRef } from 'react';

const loadItems = async currentData => {
  const page = currentData?.nextPage ?? 1;
  const response = await fetch('/api/items?page=' + page);
  if (!response.ok) throw new Error('Request failed');
  const next = await response.json(); // { list: Item[], nextPage: number | null }
  return { list: next.list, nextPage: next.nextPage };
};

function InfiniteList() {
  const containerRef = useRef(null);
  const { data, loading, loadingMore, noMore, loadMore, error } =
    useInfiniteScroll(loadItems, {
      isNoMore: currentData => currentData != null && currentData.nextPage == null,
      target: containerRef,
      threshold: 100,
    });

  return (
    <div ref={containerRef} style={{ height: 400, overflow: 'auto' }}>
      {data?.list.map(item => <div key={item.id}>{item.name}</div>)}
      {loading && <p>Loading…</p>}
      {loadingMore && <p>Loading more…</p>}
      {error && <p>Could not load more items.</p>}
      <button disabled={loadingMore || noMore} onClick={loadMore}>Load more</button>
    </div>
  );
}
~~~

Render stable item IDs as keys and guard loadMore while a page is in flight or noMore is true. A scroll threshold does not define the product's pagination or authorization rules.

**Source checked 2026-10-15:** [ahooks usePagination](https://ahooks.js.org/hooks/use-pagination) and [useInfiniteScroll](https://ahooks.js.org/hooks/use-infinite-scroll). See [ahooks](../../../frontend/libraries/ahooks.md) and [Advanced React](../../../frontend/frameworks/advanced-react.md) for current Hook and Effect guidance.

## Stable row identity and edits / 列表行身份与编辑

Use getKey(index) as the React key for hook-managed rows so insertions, removals, and moves do not make identity depend on the current position. Callbacks receive current indices; stable item identity and list position are separate concepts. / 对 Hook 管理的行使用 getKey(index) 作为 React key，使插入、删除和移动时的身份不依赖当前位置。回调接收当前索引；稳定项目身份与列表位置是不同概念。

The v3.10.0 reference lists these operations:

| Method | Arguments and behavior |
|---|---|
| insert | (index, item) inserts one item. |
| remove | (index) removes one item. |
| move | (oldIndex, newIndex) moves an item. |
| push / unshift | (item) adds at the end or beginning. |
| pop / shift | () removes the last or first item. |
| replace | (index, item) replaces one item. |
| merge | (index, items) inserts items at that position in this documented API. |
| resetList | (list) replaces the current list. |
| getKey / getIndex | Convert between a current index and the stable key. |
| sortList | Reorders supplied items to match the Hook's stable-key order, as used by the documented Ant Design integration. In v3.10.0 it also filtered all falsey values; v3.11.0 preserves `0`, `false`, and `''` while still removing `null` and `undefined`. |

The maintained [ahooks note](../../../frontend/libraries/ahooks.md) includes a runnable React example and the current key guidance; this page retains the full method catalog and version boundary omitted from its compact summary.

**Versioned sources / 版本来源:** [ahooks v3.10.0 source](https://github.com/alibaba/hooks/blob/v3.10.0/packages/hooks/src/useDynamicList/index.ts) and [API reference](https://github.com/alibaba/hooks/blob/v3.10.0/packages/hooks/src/useDynamicList/index.en-US.md) confirm that `merge(index, items)` inserts the supplied items at that position; [v3.11.0 source](https://github.com/alibaba/hooks/blob/v3.11.0/packages/hooks/src/useDynamicList/index.ts) and [release notes](https://github.com/alibaba/hooks/releases/tag/v3.11.0) confirm the `sortList` falsey-value fix.

## Debounce and throttle signatures / 防抖与节流签名

Value Hooks return a delayed or rate-limited value; function Hooks return controls for invoking and managing a callback. The defaults and return shape differ, so state them explicitly when porting an example. / 值型 Hook 返回延迟或限频后的值；函数型 Hook 返回调用和管理回调的控制方法。默认值和返回结构各不相同，移植示例时应明确说明。

| Hook | Return and documented defaults in the checked reference |
|---|---|
| useDebounce(value, options) | Debounced value; wait defaults to 1000 ms, leading false, trailing true, maxWait optional. |
| useThrottle(value, options) | Throttled value; wait defaults to 1000 ms, leading true, trailing true. |
| useDebounceFn(fn, options) | { run, cancel, flush }; same timing options as useDebounce. |
| useThrottleFn(fn, options) | { run, cancel, flush }; wait defaults to 1000 ms, leading and trailing true. |

~~~jsx
const { run, cancel, flush } = useDebounceFn(search, {
  wait: 500,
  maxWait: 2000,
});
// Call run from an event; cancel drops a pending call, flush invokes it now.
~~~

Specify wait and edge behavior when timing matters. Debounce and throttle do not imply network cancellation; canceling a pending callback does not stop a request that has already started.

**Source checked 2026-10-15:** [ahooks debounce Hooks](https://ahooks.js.org/hooks/use-debounce/) and [useThrottle](https://ahooks.js.org/hooks/use-throttle). See the maintained [ahooks note](../../../frontend/libraries/ahooks.md) for its short guidance.

## Small state helpers / 轻量状态工具

Use a helper when its state shape matches the UI: useBoolean for explicit boolean actions, useToggle for two values, useMap/useSet for collections, and useCreation for a dependency-based stable value. Use the Hook's action methods to update collections so React receives the intended state update. / 状态形状符合界面需求时再选工具：useBoolean 提供显式布尔操作，useToggle 管理两个值，useMap/useSet 管理集合，useCreation 按依赖复用稳定值。使用 Hook 的操作方法更新集合，以触发预期的 React 状态更新。

| Hook | Return shape and behavior in the archived reference |
|---|---|
| useBoolean(initialValue = false) | [state, { toggle, set, setTrue, setFalse }]. |
| useToggle(defaultValue, reverseValue?) | [state, { toggle, set, setLeft, setRight }]; setRight uses reverseValue or the inverse of defaultValue. |
| useMap(initialEntries?) | [map, { set, get, setAll, remove, reset }]; reset restores initial entries. |
| useSet(initialValues?) | [set, { add, remove, reset }]; reset restores initial values. |
| useCreation(factory, deps) | Reuses a created value until deps change; not a resource-lifecycle primitive or semantic cache guarantee. |

React documents useMemo as a performance optimization rather than a permanent semantic guarantee. Keep side effects out of a useCreation factory. For server-side persistence, see [Browser Storage and Communication](../../../frontend/browser-apis/browser-storage-and-communication.md); for React state ownership, see [Advanced React](../../../frontend/frameworks/advanced-react.md).

**Source checked 2026-10-15:** [ahooks useBoolean](https://ahooks.js.org/hooks/use-boolean), [useToggle](https://ahooks.js.org/hooks/use-toggle), [useMap](https://ahooks.js.org/hooks/use-map), [useSet](https://ahooks.js.org/hooks/use-set), and [useCreation](https://ahooks.js.org/hooks/use-creation).

## Variable row sizing in ahooks v2.6 / ahooks v2.6 的变高行

In ahooks v2.6.0, useVirtualList accepts itemHeight as either a fixed pixel value or a function of the source index. For variable-height rows, the returned height must match the rendered row; this version has no separate estimateSize option. / ahooks v2.6.0 的 useVirtualList 支持用固定像素值或按源索引计算的函数设置 itemHeight。变高列表项的返回尺寸必须与实际渲染高度一致；此版本没有单独的 estimateSize 选项。

This preserves the v2.6.0 contract from the archived reference. Its object result (list, containerProps, wrapperProps, scrollTo) changed in v3; use the versioned examples in the [maintained ahooks note](../../../frontend/libraries/ahooks.md) for the current tuple/ref shape. Virtualization reduces mounted rows, not source-data memory; see [rendering and computation optimization](../../../frontend/performance/rendering-and-computation-optimization.md).

**Version sources / 版本来源:** [ahooks v2.6.0 useVirtualList documentation](https://ahooks-v2.js.org/hooks/ui/use-virtual-list/) and [v2.6.0 implementation](https://raw.githubusercontent.com/alibaba/hooks/v2.6.0/packages/hooks/src/useVirtualList/index.ts), checked 2026-10-15.

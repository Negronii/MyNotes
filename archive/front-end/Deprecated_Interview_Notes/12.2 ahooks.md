# ahooks Reference / ahooks参考

ahooks provides React Hooks for request state, collections, list management, and timing patterns. The current API and cancellation semantics below are checked against ahooks v3.10.0 documentation and source on 2026-10-15; do not infer these semantics for every v3 release. The virtual-list props example is specifically the older v2.6.0 API; v3 redesigned that hook.

**Core answer / 核心回答：** ahooks packages recurring React state and request patterns into Hooks, but the calls still follow React's render and Effect rules. Match each signature to the installed ahooks version, and start manual work from an event handler or Effect. / ahooks 把常见的 React 状态和请求模式封装成 Hook，但调用仍须遵循 React 的 render 与 Effect 规则。每个签名都应匹配项目安装的 ahooks 版本，手动请求应从事件处理器或 Effect 中触发。

## Request state / 请求状态

### useRequest

useRequest accepts a Promise-returning service. It runs on mount by default; with manual: true, call run or runAsync when the request should start. Do not call run during render.

~~~jsx
const fetchUser = async (id) => {
  const response = await fetch('/api/users/' + id);
  if (!response.ok) throw new Error('Request failed: ' + response.status);
  return response.json();
};

function UserButton({ userId }) {
  const { data, error, loading, run, cancel } = useRequest(fetchUser, {
    manual: true,
  });

  return (
    <>
      <button disabled={loading} onClick={() => run(userId)}>
        Load user
      </button>
      <button onClick={cancel}>Ignore current result</button>
      {loading && <p>Loading…</p>}
      {error && <p>{error.message}</p>}
      {data && <pre>{JSON.stringify(data, null, 2)}</pre>}
    </>
  );
}
~~~

Common controls and options:

| Name | Contract |
|---|---|
| **manual** | When true, skip automatic execution and wait for run or runAsync. |
| **defaultParams** | Parameters for the first automatic execution. |
| **data, error, loading, params** | Most recent request state; params is the argument array used for the latest service call. |
| **run(...params)** | Start a request and return void; the Hook handles a rejected service through onError. |
| **runAsync(...params)** | Start a request and return a Promise; the caller handles rejection. An ignored or superseded request rejects with ahooks' CancelledError. |
| **refresh / refreshAsync** | Repeat the request with the last parameters. |
| **mutate(data | (oldData) => newData)** | Replace the request data or derive it from the previous data. |
| **cancel()** | Ignore the current Promise result/error and stop polling or queued debounce/throttle calls; it does not abort an already-sent network request by itself. |
| **onBefore(params)** | Runs before the service starts. |
| **onSuccess(data, params)** | Runs when the service resolves. |
| **onError(error, params)** | Runs when the service rejects or `run` handles an error. |
| **onFinally(params, data?, error?)** | Runs after an active service execution resolves or rejects; cancelled or superseded work may be ignored before this callback. |
| **retryCount / retryInterval** | In v3.10.0, configure how many times a failed request is retried and the delay between retries. |

A manual run belongs in an event handler or an Effect that responds to a real dependency. Starting the request directly in the component body would repeat a side effect during rendering.

The v3 `useRequest` guide also documents polling, debounce and throttle scheduling, refresh-on-focus, `ready` gating, dependency refresh, delayed loading, error retry, and cache/SWR behavior. These are request options or plugins; use the installed version's exact names and defaults. In v3, examples include `pollingInterval`, `debounceWait`, `throttleWait`, `refreshDeps`, `ready`, `loadingDelay`, and `cacheKey`. The polling interval is waited after each request completes. Debounce defaults to trailing execution; the throttle guide enables both leading and trailing execution by default. In manual mode, start the request with `run`/`runAsync`; changing `refreshDeps` does not start a manual request.

This is a version boundary: ahooks v2 used request options such as `debounceInterval` and `throttleInterval`; v3.10.0 instead uses `debounceWait` and `throttleWait`. The v3.10.0 request types still include `retryCount` and `retryInterval`. The v3 upgrade guide says the request API was rewritten and removed the `pagination`, `loadMore`, `formatResult`, and `fetchKey` options; use `usePagination` or `useInfiniteScroll` for those scenarios. A v2 option should not be copied into a v3 call without checking its versioned documentation.

### usePagination

The current usePagination service receives an object containing current page and pageSize and resolves to an object with list and total. The result contains data, loading, and a pagination object.

~~~jsx
const fetchPage = ({ current, pageSize }) =>
  fetch('/api/items?page=' + current + '&size=' + pageSize).then((response) => {
    if (!response.ok) throw new Error('Request failed');
    return response.json(); // { list: Item[], total: number }
  });

function ItemList() {
  const { data, loading, pagination } = usePagination(fetchPage, {
    defaultCurrent: 1,
    defaultPageSize: 10,
  });

  return (
    <>
      {loading ? <p>Loading…</p> : data?.list.map(item => <div key={item.id}>{item.name}</div>)}
      <button
        disabled={pagination.current >= pagination.totalPage}
        onClick={() => pagination.changeCurrent(pagination.current + 1)}
      >
        Next
      </button>
      <span>Page {pagination.current} of {pagination.totalPage}</span>
    </>
  );
}
~~~

The pagination state also exposes pageSize, total, onChange, and changePageSize. The current documented page-count property is totalPage.

### useInfiniteScroll

The service receives the current accumulated data, if any, but for downward scrolling it returns only the new page; the Hook merges that page's list with the accumulated list. The result includes data, loading, loadingMore, error, noMore, loadMore, reload, mutate, and cancel. An optional target selects a scroll container; threshold controls how near the edge loading starts, and isNoMore defines when loading should stop.

~~~jsx
import { useInfiniteScroll } from 'ahooks';
import { useRef } from 'react';

const loadItems = async (currentData) => {
  const page = currentData?.nextPage ?? 1;
  const response = await fetch('/api/items?page=' + page);
  if (!response.ok) throw new Error('Request failed');
  const next = await response.json(); // { list: Item[], nextPage: number | null }

  return {
    list: next.list,
    nextPage: next.nextPage,
  };
};

function InfiniteList() {
  const containerRef = useRef(null);
  const { data, loading, loadingMore, noMore, loadMore, error } = useInfiniteScroll(loadItems, {
    isNoMore: currentData => currentData != null && currentData.nextPage == null,
    target: containerRef,
    threshold: 100,
  });

  return (
    <div ref={containerRef} style={{ height: 400, overflow: 'auto' }}>
      {data?.list.map(item => <div key={item.id}>{item.name}</div>)}
      {loading && <p>Loading…</p>}
      {loadingMore && <p>Loading…</p>}
      {error && <p>Could not load more items.</p>}
      <button disabled={loadingMore || noMore} onClick={loadMore}>Load more</button>
    </div>
  );
}
~~~

Use stable item identifiers as React keys when displaying the accumulated data. Infinite scrolling still needs an explicit loading/error state and a stopping condition.

## Stable callbacks and latest values / 稳定回调与最新值

### useMemoizedFn

useMemoizedFn returns a stable function reference that calls the latest function body. Unlike useCallback, it does not take a dependency array. This can be useful for a callback passed to a long-lived listener; it does not by itself prevent every component render.

~~~jsx
function Counter() {
  const [count, setCount] = useState(0);
  const increment = useMemoizedFn(() => setCount(value => value + 1));

  return <button onClick={increment}>Count: {count}</button>;
}
~~~

### useLatest

useLatest returns a ref whose current value tracks the latest value passed to the Hook. It can help a long-lived callback read current props or state without reinstalling the callback on each render. For state increments, a functional updater is simpler and avoids capturing a stale value.

~~~jsx
function Timer() {
  const [count, setCount] = useState(0);
  const latestCount = useLatest(count);

  useEffect(() => {
    const id = setInterval(() => {
      // This ref tracks the latest value passed to useLatest.
      setCount(latestCount.current + 1);
    }, 1000);

    return () => clearInterval(id);
  }, []);

  return <p>{count}</p>;
}
~~~

For an update based only on previous state, use setCount(value => value + 1) instead. An Effect with [count] restarts its interval after each count change; it does not keep a stale callback indefinitely.

## Dynamic and virtual lists / 动态列表与虚拟列表

### useDynamicList

useDynamicList keeps an array and provides operations such as push, insert, remove, move, replace, merge, resetList, and sortList. getKey(index) returns the stable key associated with that list position; use it when rendering the hook-managed items.

~~~jsx
function DynamicList() {
  const { list, push, remove, getKey } = useDynamicList(['Ada', 'Grace']);

  return (
    <>
      <button onClick={() => push('Lin')}>Add</button>
      <ul>
        {list.map((name, index) => (
          <li key={getKey(index)}>
            {name}
            <button onClick={() => remove(index)}>Remove</button>
          </li>
        ))}
      </ul>
    </>
  );
}
~~~

Current v3 method signatures include:

| Method | Arguments and result |
|---|---|
| **insert** | (index, item) inserts an item. |
| **remove** | (index) removes an item. |
| **move** | (oldIndex, newIndex) moves an item. |
| **push / unshift** | (item) adds one item at the end or beginning. |
| **pop / shift** | () removes the last or first item. |
| **replace / merge** | (index, item) replaces one item; (index, items) inserts items at that position. |
| **resetList** | (list) replaces the list. |
| **getKey / getIndex** | (index) returns a key; (key) returns its current index. |
| **sortList** | (list) returns items reordered to match the Hook's stable key order, as used by the documented Ant Design integration. |

### useVirtualList: ahooks v2.6.0 / ahooks v2.6.0 虚拟列表

This is the archived v2.6.0 object shape: the Hook returns list, containerProps, wrapperProps, and scrollTo. Each rendered item has a data field; keep the container bounded and preserve the Hook's style props so it can measure the scrolling viewport and position the visible window.

~~~jsx
const { list, containerProps, wrapperProps, scrollTo } = useVirtualList(items, {
  itemHeight: 50,
  overscan: 5,
});

return (
  <>
    <button onClick={() => scrollTo(5000)}>Jump to item 5000</button>
    <div
      {...containerProps}
      style={{ ...containerProps.style, height: 500, overflow: 'auto' }}
    >
      <div {...wrapperProps}>
        {list.map(item => (
          <div key={item.data.id} style={{ height: 50 }}>
            {item.data.name}
          </div>
        ))}
      </div>
    </div>
  </>
);
~~~

In v2.6.0, itemHeight accepts either a fixed pixel height or a function of the source index. For variable-height rows, return the row's height and render the same height; this version does not use a separate estimateSize option.

### useVirtualList: current v3 shape / 当前 v3 接口

The v3 API was redesigned. It takes containerTarget and wrapperTarget references and returns the visible items plus scrollTo; it does not return the v2 containerProps/wrapperProps shape.

~~~jsx
const containerRef = useRef(null);
const wrapperRef = useRef(null);
const [list, scrollTo] = useVirtualList(items, {
  containerTarget: containerRef,
  wrapperTarget: wrapperRef,
  itemHeight: 50,
  overscan: 5,
});

return (
  <div ref={containerRef} style={{ height: 500, overflow: 'auto' }}>
    <div ref={wrapperRef}>
      {list.map(item => (
        <div key={item.index} style={{ height: 50 }}>
          {item.data.name}
        </div>
      ))}
    </div>
  </div>
);
~~~

For example, a 10,000-item source list with 50px rows and a 500px viewport keeps the full scroll range but renders only visible rows plus the 5-row overscan. The virtual list keeps the full scrollable extent while rendering a window of rows at the corresponding source offsets. If the wrapper extent or row offsets are wrong, the scrollbar and visible rows drift. Fixed `itemHeight` (or, in the v2.6.0 API, `itemHeight(index)` for variable rows) must match the rendered size; `overscan` adds nearby rows to reduce gaps at the viewport edge. The source list should keep a stable reference between renders unless it intentionally changes. Virtualization reduces mounted rows, not the memory required to hold the source data.

## Debounce and throttle / 防抖与节流

The value Hooks return delayed or rate-limited values. Function Hooks return controls for invoking and managing a callback.

| Hook | Return shape | Main use |
|---|---|---|
| **useDebounce(value, options)** | A debounced value. `wait` defaults to 1000ms, `leading` to false, and `trailing` to true; `maxWait` is optional. | Update after a quiet interval. |
| **useThrottle(value, options)** | A throttled value. `wait` defaults to 1000ms; `leading` and `trailing` default to true. | Update at most once per interval. |
| **useDebounceFn(fn, options)** | `{ run, cancel, flush }`; accepts the same timing options as `useDebounce`. | Delay a function until calls pause. |
| **useThrottleFn(fn, options)** | `{ run, cancel, flush }`; `wait` defaults to 1000ms, and `leading`/`trailing` to true. | Limit how often a function runs. |

~~~jsx
function SearchBox({ search }) {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query, { wait: 500 });

  useEffect(() => {
    if (debouncedQuery) search(debouncedQuery);
  }, [debouncedQuery, search]);

  return <input value={query} onChange={event => setQuery(event.target.value)} />;
}
~~~

For a function call, `useDebounceFn` exposes explicit controls:

~~~jsx
function SearchButton({ search }) {
  const { run, cancel, flush } = useDebounceFn(search, { wait: 500, maxWait: 2000 });

  return (
    <>
      <button onClick={() => run('current query')}>Search</button>
      <button onClick={cancel}>Cancel pending search</button>
      <button onClick={flush}>Run pending search now</button>
    </>
  );
}
~~~

Specify wait explicitly when timing matters. Leading and trailing options change when a callback runs; the debounce and throttle Hooks have different defaults.

## Small state helpers / 小型状态工具

| Hook | Signature and return shape |
|---|---|
| **useBoolean(initialValue = false)** | `[state, { toggle, set, setTrue, setFalse }]`; boolean state and explicit actions. |
| **useToggle<T, U>(defaultValue, reverseValue?)** | `[state, { toggle, set, setLeft, setRight }]`; `setRight` uses `reverseValue`, or the inverse of the default when it is omitted. |
| **useMap<K, V>(initialValue?: Iterable<[K, V]>)** | `[map, { set(key, value), get(key), setAll(entries), remove(key), reset() }]`; reset restores the initial entries. Use the action helpers for writes so React receives a new Map. |
| **useSet<K>(initialValue?: Iterable<K>)** | `[set, { add(value), remove(value), reset() }]`; reset restores the initial values. Use the action helpers for writes so React receives a new Set. |
| **useCreation<T>(factory, deps)** | Returns a stable created value until `deps` change; useful for ref-like instances that should not be recreated on every render. |

~~~jsx
function ThemeControls() {
  const [enabled, { setTrue, setFalse, toggle }] = useBoolean(false);
  const [map, { set, get, reset }] = useMap([['theme', 'dark']]);
  const theme = get('theme');

  return (
    <>
      <p>{theme} ({map.size} setting)</p>
      <button onClick={() => set('theme', 'light')}>Use light theme</button>
      <button onClick={reset}>Reset theme</button>
      <button onClick={toggle}>{enabled ? 'Disable' : 'Enable'}</button>
      <button onClick={setTrue}>Enable</button>
      <button onClick={setFalse}>Disable</button>
    </>
  );
}
~~~

React documents useMemo as a performance optimization, not a semantic guarantee that a cached value can never be discarded. Use useCreation for the specific stable-instance use case its documentation describes, and keep side effects out of its factory.

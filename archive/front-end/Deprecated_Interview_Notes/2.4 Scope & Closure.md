# JavaScript Scope, Closures, and Declarations / JavaScript 作用域、闭包与声明

**Core / 核心：** Scope is determined by where bindings are declared; a closure keeps access to the lexical bindings its function uses. `var` is function-scoped, while `let` and `const` are block-scoped and have a temporal dead zone. 作用域由绑定的声明位置决定；闭包使函数能访问其使用的词法绑定。`var` 是函数作用域，`let` 与 `const` 是块作用域，并有暂时性死区。

**Key terms / 关键词：** lexical scope 词法作用域 · environment record 环境记录 · closure 闭包 · hoisting 提升 · temporal dead zone 暂时性死区 · module scope 模块作用域

## What is Scope in JavaScript?
Scope determines where a declared binding can be resolved. JavaScript has global, module, function, and block environments; a function's lexical location determines the outer environments it can access.

### Types of Scope in JavaScript
These environments can be nested. “Global” behavior also depends on whether code runs as a classic script, an ECMAScript module, or inside a host wrapper such as a Node.js CommonJS module.

### Global Scope
Global bindings are visible from code in their global environment. In a browser classic script, top-level `var` and function declarations are associated with the global object; top-level `let` and `const` are not its properties. Modules have module scope and do not add top-level declarations to the global object.

**Example of Global Scope**:
```javascript
var globalVariable = 'I am a global variable';
console.log(globalVariable); // Output: I am a global variable
```

**Browser global object**:
In a browser, the global object is available as `globalThis` and is commonly the `Window` object. Only some classic-script declarations become its properties; the blanket rule does not apply to `let`, `const`, or modules.

The browser `Window` global exposes host APIs such as `document`, `location`, storage, timers, `fetch`, and event handlers; these APIs are supplied by the host, not by JavaScript scope itself.

### Local Scope (Function Scope)
`var` bindings are function-scoped; scope describes name visibility, not by itself a security or memory-management boundary.

**Example of Local Scope**:
```javascript
function localScopeExample() {
    var localVariable = 'I am a local variable';
    console.log(localVariable); // Output: I am a local variable
}
localScopeExample();
console.log(localVariable); // Error: localVariable is not defined
```

### Block Scope
Introduced with ES6, `let` and `const` provide block-level scope, which restricts variable access to the specific block where they are declared, such as within `if` statements or loops.

**Example of Block Scope**:
```javascript
if (true) {
    let blockScopedVariable = 'I am block scoped';
    console.log(blockScopedVariable); // Output: I am block scoped
}
console.log(blockScopedVariable); // Error: blockScopedVariable is not defined
```

### Lexical Scope
JavaScript employs lexical scoping where a function enclosed within another function has access to the outer function's scope.

**Example of Lexical Scope**:
```javascript
function outerFunction() {
    var outerVariable = 'I exist in the outer function';
    function innerFunction() {
        console.log(outerVariable); // Output: I exist in the outer function
    }
    innerFunction();
}
outerFunction();
```

### Module Scope
Each ECMAScript module has its own top-level bindings. Imported and exported bindings connect modules explicitly; top-level declarations do not become global-object properties.

### Scope Linking in JavaScript
JavaScript's scope chaining enables variable resolution along the scope chain, ensuring variables defined in outer scopes are accessible in inner scopes.

**Example of Scope Linking**:
```javascript
var globalVar = 'accessible everywhere';

function outerFunc() {
    var outerVar = 'accessible in this function and its inner functions';
    function innerFunc() {
        var innerVar = 'only accessible in this function';
        console.log(globalVar);  // Output: this script's outer binding is visible here
        console.log(outerVar);  // Output: the outer function's binding is visible here
        console.log(innerVar);  // Output: only accessible in this function
    }
    innerFunc();
}
outerFunc();
```

## What is Closure

A closure is a function combined with its lexical environment, which allows it to access variables from the outer function’s scope even after the outer function has returned. This feature is crucial in JavaScript and enables powerful programming patterns.

```javascript
function outerFunction() {
    var outerVariable = 'I am outside!';
    function innerFunction() {
        console.log(outerVariable);
    };
    return innerFunction;
}

var innerFunc = outerFunction();
innerFunc(); // Output: 'I am outside!'
```

### Practical Applications of Closures

**Event Handlers**  
Closures enable JavaScript developers to manage changes in state in a controlled manner. For example, adjusting the font size of a text element upon a button click is a typical use case:

```html
<div id="text">Hello, World!</div>
<button id="button">Change Font Size</button>
<script>
    function changeFontSize(size) {
        return function() {
            document.getElementById('text').style.fontSize = size + 'px';
        }
    }

    document.getElementById('button').addEventListener('click', changeFontSize(20));
</script>
```

**Creating Private Variables**  
Closures facilitate the creation of private variables that cannot be accessed directly from outside the function, thereby emulating private methods and properties:

```javascript
function makeCounter() {
    var count = 0;
    return {
        increment: function() {
            count++;
            console.log(count);
        },
        decrement: function() {
            count--;
            console.log(count);
        }
    }
}

var counter1 = makeCounter();
var counter2 = makeCounter();
counter1.increment(); // Output: 1
counter1.increment(); // Output: 2
counter2.increment(); // Output: 1
```

**Event Binding within Loops**  
Using closures within loops to bind event listeners avoids common pitfalls related to JavaScript’s lexical scoping:

```html
<div>0</div>
<div>1</div>
<div>2</div>
<div>3</div>
<div>4</div>
<script>
    var divs = document.getElementsByTagName('div');
    for (var i = 0; i < divs.length; i++) {
        (function(i) {
            divs[i].addEventListener('click', function() {
                console.log('You clicked on element #' + i);
            });
        })(i);
    }
</script>
```

The IIFE gives each callback its own parameter binding. A `for (let i = 0; ...)` loop is the modern alternative: each iteration receives its own `i` binding.

### Memory Management and Closures

**Reachability and retained data**
A closure does not inherently leak memory. If a reachable closure can still read a value, the runtime must keep that value available; once the closure and other references become unreachable, the value is eligible for collection. Collection timing and algorithm are engine-specific.

```javascript
function makeReader(record) {
    return () => record.id;
}

let readId = makeReader({ id: 7, payload: new Uint8Array(1024) });
console.log(readId()); // 7; the reachable closure can still read record
readId = null; // if no other references remain, the closure and record are eligible for collection
```

The ECMAScript specification does not prescribe a garbage-collection algorithm or when collection runs. Retaining an event listener or callback can keep reachable state alive; remove long-lived handlers when their owner is finished with them.

## JavaScript Variable Declarations: `var`, `let`, and `const`
### `var` Declaration
**Function Scope and Initialization**

`var` bindings are created when their variable environment is instantiated and initialized to `undefined`; the assignment in the declaration runs where the statement appears. In a function, `var` is function-scoped. At classic-script top level it is associated with the global object; module top-level declarations have module scope.

```javascript
console.log(a); // Outputs: undefined
var a = 10;
console.log(a); // Outputs: 10
function foo() {
    console.log(a); // Outputs: undefined
    var a = 20;
    console.log(a); // Outputs: 20
}
```

**Key Characteristics:**
- Bindings are initialized to `undefined` before the declaration's assignment runs.
- Can be redeclared in the same `var` scope when it does not conflict with a lexical declaration.

### `let` Declaration
**Block Scope and Temporal Dead Zone**

`let` is block-scoped. Its binding exists from the start of the block but remains uninitialized until its declaration is evaluated; access earlier in that interval throws `ReferenceError` (the temporal dead zone, or TDZ).

```javascript
let a = 10;
function foo() {
    try {
        console.log(a); // Throws: the local binding shadows outer a in the TDZ
    } catch (error) {
        console.log(error instanceof ReferenceError); // true
    }
    let a = 20;
    console.log(a); // Outputs: 20
}
foo();
console.log(a); // Outputs: 10
```

**Key Characteristics:**
- Block-scoped: accessible only within the block where declared. (note `var` is function-scoped, so `var` can be used outside `if` or `for` blocks, but `let` cannot)
- Access before initialization throws `ReferenceError`, which exposes use-before-declaration mistakes.
- Cannot be redeclared in the same lexical scope; an inner block may shadow an outer binding.

### `const` Declaration
**Block Scope and Immutable Binding**

`const` has the same block scope and TDZ as `let`, and requires an initializer. The binding cannot be reassigned; an object held by the binding can still be mutated.

```javascript
// const a; // SyntaxError: Missing initializer in const declaration
const a = 10;
console.log(a); // Outputs: 10
try {
    a = 20; // Runtime illustration: reassigning a const binding throws.
} catch (error) {
    console.log(error instanceof TypeError); // true
}

const b = [];
b[0] = 10; // Allowed: modifying an object's content
// b = [10]; // SyntaxError: Assignment to constant variable
```

**Key Characteristics:**
- Block-scoped and requires initial value.
- The binding cannot be reassigned; `const` does not freeze the referenced object.

### Best Practices
For new code, use `const` when a binding is not reassigned and `let` when it is. Recognize `var`'s function scope when maintaining older code.

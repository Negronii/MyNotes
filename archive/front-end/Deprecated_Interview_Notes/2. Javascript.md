# JavaScript Language Notes / JavaScript 语言笔记

**Core / 核心：** JavaScript’s semantics depend on the language mode and the operation being performed; strict mode turns several silent failures into errors. JavaScript 的语义取决于语言模式和具体操作；严格模式会把若干静默失败改为抛错。

**Key terms / 关键词：** strict mode 严格模式 · primitive 原始值 · property key 属性键 · `Symbol` 符号 · `BigInt` 大整数

## JavaScript's Strict Mode Features

Strict mode changes parsing and runtime behavior. A script or function can opt in with a leading `'use strict';` directive; ECMAScript modules and class bodies are strict automatically. It is a semantic mode, not a performance guarantee.

### Features of Strict Mode

1. **Unresolved assignments**: Strict code throws `ReferenceError` when an assignment targets an unresolvable name instead of creating a global property. Declaration hoisting and the temporal dead zone are separate rules.

2. **Disallows the `with` Statement**: The `with` statement is not allowed in strict code; it makes name resolution harder to reason about by adding an object environment to the scope chain.

3. **Direct `eval()` declarations**: Declarations made by direct `eval()` in strict code do not leak into the caller's variable environment. The evaluated code can still read or change bindings it can access; `eval()` is not a security boundary.

4. **`this` in an ordinary function call**: A strict ordinary function invoked as a plain call receives `undefined` as `this`; a non-strict ordinary function converts `null` or `undefined` to the function's realm global object and boxes other primitive values. Arrow functions capture `this` lexically. Method calls and explicit `call`/`apply` use different call forms.

5. **Prohibits Duplicate Parameter Names**: Functions cannot have multiple parameters with the same name, which eliminates potential errors from duplicated identifiers and enhances code clarity.

6. **Non-writable properties**: Assigning to a non-writable property throws `TypeError` in strict code. In non-strict code the failed assignment normally returns without changing the property. `const` bindings are a separate mechanism.

7. **Deleting properties**: Deleting a non-configurable property through a property reference throws `TypeError` in strict code; in non-strict code the delete expression returns `false`. Deleting an unqualified identifier is a syntax error.

8. **Legacy octal syntax**: Legacy octal numeric literals such as `010` and octal escape sequences such as `'\141'` are syntax errors in strict code. Use `0o10` for the number 8 and `'\u0061'` for the character `a`.

Strict mode rejects duplicate parameter names in strict functions. These rules do not make object properties immutable.

### Conclusion
Strict mode changes specific parsing and runtime rules. It does not guarantee faster code or make arbitrary operations safe.

## Primitive Types
Primitive values are immutable values; variables may be reassigned to different values. JavaScript has seven primitive types:

1. **`undefined`**:
   - Represents an undefined value.
   - A binding initialized without an explicit value reads as `undefined`; an uninitialized lexical binding is in its temporal dead zone and throws if read. An absent object property also reads as `undefined`.
   - Example: `let x; console.log(x); // undefined`

2. **`null`**:
   - Represents an intentional absence of a value.
   - Often used to indicate a deliberate non-value.
   - `typeof null` returns `'object'` for historical compatibility; `null` is not an object value.
   - Example: `let y = null; console.log(y); // null`

3. **`boolean`**:
   - Represents a logical entity and can have two values: `true` and `false`.
   - Type conversion to boolean:
     - Strings: Only an empty string (`''`) is `false`; all other strings are `true`.
     - The falsy values are `false`, `+0`, `-0`, `0n`, `NaN`, `''`, `null`, and `undefined`.
     - Ordinary objects are truthy (e.g. `{}` and `[]`); browser `document.all` is a legacy web-compatibility exception.
   - Example: `let isTrue = true; let isFalse = false;`

4. **`number`**:
   - Represents numeric values, following the IEEE 754 standard.
   - Special values: `Infinity`, `-Infinity`, and `NaN` (Not-a-Number).
   - `NaN` is unique: `NaN !== NaN`. Use `Number.isNaN()` to check for `NaN`.
   - Type conversion to number:
     - `Number('')` is `0`.
     - `Number('123')` is `123`.
     - `Number('abc')` is `NaN`.
     - `Number(true)` is `1`.
     - `Number(false)` is `0`.
     - `Number(null)` is `0`.
     - `Number(undefined)` is `NaN`.
     - `Number({})` is `NaN`.
   - Example: `let num = 42; let inf = 1/0; // Infinity`

5. **`string`**:
   - Represents a sequence of characters.
   - Immutable: once created, they cannot be changed.
   - Example: `let str = 'Hello, world!';`

6. **`symbol`** (added in ES6):
   - Represents a unique identifier.
   - Created using the `Symbol()` function.
   - Example: `let sym = Symbol('description');`
   - It can be used as an object property key. The built-in function methods `call`, `apply`, and `bind` are string-named properties, not Symbols.

7. **`bigint`** (standardized in ECMAScript 2020):
   - Represents integers beyond the exact range of `number` as well as smaller integers.
   - Created by appending `n` to the end of an integer or using the `BigInt` function.
   - Example: `let big = 123456789012345678901234567890n;`
   - Arithmetic does not implicitly mix `bigint` and `number`; convert deliberately when the operation is valid.

Property keys are strings or Symbols. Other values are converted with the language's property-key conversion (which may call user-defined coercion hooks), not simply by calling `toString()` in every case. Use `Map` when keys must retain arbitrary values such as object identity.

# Design Patterns / 设计模式

> This archived reference keeps practical JavaScript examples of common patterns. A pattern is a vocabulary for a recurring trade-off, not a rule that every codebase must follow. 本文保留常见模式的 JavaScript 示例；模式用于描述反复出现的设计取舍，不是必须照搬的规则。
>
> **Key terms / 关键词:** factory 工厂、singleton 单例、strategy 策略、proxy 代理、observer 观察者、publish–subscribe 发布订阅、decorator 装饰器、iterator 迭代器。
>
> For current reusable explanations, see [Design Patterns in Practice](../../../engineering-foundations/architecture/design-patterns-in-practice.md) and [Software Design Principles](../../../engineering-foundations/architecture/software-design-principles.md).

## Open/Closed Principle / 开闭原则

The Open/Closed Principle says that a module should be open to useful extension while limiting changes to stable behavior. It is a design goal, not a ban on editing existing code: an abstraction that makes a simple change harder can cost more than it saves.

开闭原则强调：稳定模块应便于扩展，同时尽量减少对既有行为的修改。这是设计目标，不是禁止修改旧代码；若抽象让简单变更更困难，成本可能高于收益。

## Factory Function / 工厂函数

A factory centralizes object creation when construction needs selection, validation, or setup. Hiding `new` by itself is not enough reason to add one.

```js
class JsonStore {
  constructor(storage) {
    this.storage = storage;
  }
}

function createStore(kind, storage) {
  if (kind !== 'json') throw new Error(`Unsupported store: ${kind}`);
  return new JsonStore(storage);
}

const store = createStore('json', window.localStorage);
```

## Singleton / 单例

A singleton limits a service to one instance within a defined scope. A module-level instance is usually simpler in JavaScript than a static class getter. The scope matters: separate workers, processes, bundled copies, or isolated module loaders can each have their own instance. JavaScript code in one agent runs to completion, but workers and processes mean a singleton is not automatically application-wide.

```js
let instance;

export function getLogger() {
  if (!instance) {
    instance = { log: message => console.log(message) };
  }
  return instance;
}
```

Use this only when shared identity is useful; global mutable state can make tests and lifecycle management harder.

## Strategy / 策略

Strategy puts interchangeable behavior behind a small contract. It can replace conditionals when several algorithms have the same inputs and result shape; a short conditional is often clearer when there are only one or two cases.

```js
const shipping = {
  ground: parcel => Math.round(parcel.weightKg * 156),
  air: parcel => Math.round(parcel.weightKg * 245),
};

function quoteShipping(parcel, strategy) {
  if (typeof strategy !== 'function') throw new TypeError('Unknown strategy');
  return strategy(parcel); // illustrative integer cents
}

const parcel = { weightKg: 5 };
console.log(quoteShipping(parcel, shipping.ground)); // 780
console.log(quoteShipping(parcel, shipping.air));    // 1225
```

The strategy selection belongs at the boundary that knows the customer's choice; the calculation can then be tested independently.

## Proxy / 代理

A Proxy intercepts selected object operations through traps. It is useful for validation, instrumentation, and some reactive systems, but it changes observable behavior and should not be treated as a transparent performance optimization.

```js
const product = new Proxy({ price: 10 }, {
  get(target, property, receiver) {
    console.log(`read ${String(property)}`);
    return Reflect.get(target, property, receiver);
  },
  set(target, property, value, receiver) {
    if (property === 'price' && (!Number.isFinite(value) || value < 0)) {
      throw new RangeError('price must be a non-negative finite number');
    }
    return Reflect.set(target, property, value, receiver);
  },
});

product.price = 12;
console.log(product.price); // 12
```

For arrays, one operation such as `push()` may trigger several traps (index assignment and length changes). Array behavior and Proxy invariants are defined by ECMAScript; test the exact operations an application relies on.

### Accessor properties are not Proxies / Getter 属性不是 Proxy

An accessor can compute a value when a property is read. This browser/Node global example is intentionally stateful and illustrates why getters with side effects are surprising; it is not a recommended application pattern.

```js
let readCount = 0;
Object.defineProperty(globalThis, 'demoReadCount', {
  configurable: true,
  get() { return ++readCount; },
});

console.log(globalThis.demoReadCount); // 1
console.log(globalThis.demoReadCount); // 2
delete globalThis.demoReadCount;
```

## Observer and Publish–Subscribe / 观察者与发布订阅

In a direct observer arrangement, a subject holds or calls registered observers when its state changes. DOM `EventTarget` is a familiar event-listener interface with registration and removal:

```js
const button = document.querySelector('button');
function onClick() { console.log('click'); }

button.addEventListener('click', onClick);
// Remove the same function when its owner no longer needs the subscription.
button.removeEventListener('click', onClick);
```

Publish–subscribe adds an event channel or broker: publishers emit a topic without naming each subscriber, and subscribers listen by topic. The boundary is not absolute—many libraries mix both ideas—but the broker adds indirection and lifecycle work.

```js
const listeners = new Map();
const bus = {
  on(topic, fn) {
    if (!listeners.has(topic)) listeners.set(topic, new Set());
    listeners.get(topic).add(fn);
    return () => listeners.get(topic)?.delete(fn);
  },
  emit(topic, value) {
    for (const fn of listeners.get(topic) ?? []) fn(value);
  },
};

const unsubscribe = bus.on('saved', id => console.log('saved', id));
bus.emit('saved', 42);
unsubscribe();
```

Direct observers suit a local relationship. A channel helps when producers and consumers should not know each other's identities. Either way, define who owns subscriptions and how they are removed.

## Decorator / 装饰器

The Decorator pattern wraps an object or function to add behavior without changing the wrapped implementation. The pattern is broader than `@decorator` syntax; syntax and type signatures differ between language versions and toolchains.

```js
function withTiming(fn) {
  return function (...args) {
    const start = performance.now();
    try {
      return fn.apply(this, args);
    } finally {
      console.log(`${fn.name || 'operation'}: ${performance.now() - start} ms`);
    }
  };
}

const saveWithTiming = withTiming(function save(value) {
  return value.id;
});
```

TypeScript 5.0 added support for the Stage 3 ECMAScript decorators proposal, which remains on the proposal track and uses a different calling convention from legacy experimental decorators. Check the compiler configuration and toolchain before adopting decorator syntax. See the [TypeScript 5.0 decorator notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-0.html#decorators) and the [TC39 proposal](https://github.com/tc39/proposal-decorators).

## Iterator / 迭代器

The iterator protocol gives consumers a common way to request values without exposing a collection's internal representation. An iterable's `Symbol.iterator` method returns an iterator whose `next()` method returns an iteration result.

```js
const range = {
  start: 1,
  end: 5,
  [Symbol.iterator]() {
    let current = this.start;
    const end = this.end;
    return {
      next() {
        if (current <= end) return { value: current++, done: false };
        return { value: undefined, done: true };
      },
    };
  },
};

console.log([...range]); // [1, 2, 3, 4, 5]
```

Arrays, strings, Maps, and Sets are built-in iterables. Generators provide a concise way to implement the same protocol when a custom iterator is useful.

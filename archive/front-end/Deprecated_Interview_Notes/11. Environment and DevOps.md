## Webpack Overview / Webpack 概览

Webpack is a configurable static module bundler. Starting from one or more entry points, it resolves dependencies, runs matching loaders, builds a module and chunk graph, applies plugins, and emits assets. Code splitting may produce multiple files. A bundle does not automatically make a page faster or reduce requests; measure the output and consider caching, compression, HTTP version, and the application's loading path.

Webpack 从一个或多个入口解析依赖、执行匹配的 loader、构建模块与 chunk 图、运行插件并输出资源。代码分割可能产生多个文件。打包本身不保证页面更快或请求更少；还要结合缓存、压缩、HTTP 版本和页面加载路径测量结果。

### Loaders / Loader

A loader transforms a module's source so Webpack can include it in the dependency graph. Normal loaders run from right to left in a `use` array; pitch functions run in the other direction. Loaders should return the transformed source and, when relevant, a source map.

| Need | Typical tool | Scope |
|---|---|---|
| Transpile JavaScript syntax | `babel-loader` | Requires a Babel configuration and target policy. |
| Compile TypeScript | `ts-loader` or Babel with TypeScript support | Type checking and transpilation are separate decisions. |
| Process CSS imports and `url()` references | `css-loader` | Resolves CSS dependencies. |
| Put CSS in development pages | `style-loader` | Injects style elements; production often extracts CSS instead. |
| Compile Sass or Less | `sass-loader`, `less-loader` | Usually paired with the relevant compiler and CSS loader. |
| Import assets in Webpack 5 | built-in asset modules | `file-loader` and `url-loader` belong to older Webpack setups. |

Older collections also listed `eslint-loader`, `awesome-typescript-loader`, `raw-loader`, and `file-loader`/`url-loader`. Treat those names as historical configuration examples; check each package's maintenance state and the project's Webpack major before adopting them. Linting is commonly run as a separate check or through a current plugin.

```js
module.exports = {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        use: ['babel-loader', 'ts-loader'], // ts-loader runs first
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'], // css-loader runs first
      },
    ],
  },
};
```

For a focused custom-loader example, replace an explicit build token. This is a teaching example, not a general-purpose source-code parser:

```js
// loaders/build-label-loader.js
module.exports = function buildLabelLoader(source) {
  const { label = 'local' } = this.getOptions();
  return source.replaceAll('__BUILD_LABEL__', JSON.stringify(label));
};
```

```js
// webpack.config.js
module.exports = {
  module: {
    rules: [{
      test: /\.label\.js$/,
      use: [{ loader: './loaders/build-label-loader.js', options: { label: 'demo' } }],
    }],
  },
};
```

### Plugins / Plugin

A plugin can observe or alter the build by registering callbacks on compiler or compilation hooks. It can handle tasks that are broader than transforming one source file. Plugin code runs at the hook it subscribes to; listing plugins in a config does not mean every plugin executes one after another at the same point.

Common examples include `HtmlWebpackPlugin` for generated HTML, `MiniCssExtractPlugin` for extracted CSS, `DefinePlugin` for compile-time constants, `TerserWebpackPlugin` for JavaScript minimization, `CompressionWebpackPlugin` for producing compressed assets, `HotModuleReplacementPlugin` for development updates, `ProvidePlugin` for configured implicit imports, and `DllPlugin`/`DllReferencePlugin` for an older prebuilt-vendor workflow. Confirm current package maintenance and whether Webpack already provides the feature before adding a dependency. Emitting a `.gz` or `.br` asset does not configure the production server to serve it.

Webpack exposes `done` as an `AsyncSeriesHook`. A callback that finishes immediately can use `tap`; an asynchronous callback can use `tapAsync` or `tapPromise`:

```js
const fs = require('node:fs');

class BuildStatsPlugin {
  constructor(outputPath) {
    this.outputPath = outputPath;
  }

  apply(compiler) {
    compiler.hooks.done.tap('BuildStatsPlugin', stats => {
      fs.writeFileSync(this.outputPath, JSON.stringify(stats.toJson(), null, 2));
    });
  }
}

module.exports = BuildStatsPlugin;
```

The output path should be writable, and the stats object can be large; use `stats.toJson()` options when only a subset is needed.

### Build Stages / 构建阶段

A useful mental model for a normal compilation is:

1. Webpack resolves configuration and creates the compiler.
2. Plugins register for lifecycle hooks.
3. Entry modules and their dependencies are resolved into a graph.
4. Matching loaders transform source modules.
5. Webpack creates and optimizes chunks, then emits assets.
6. In watch mode, a changed dependency can trigger a new compilation; caching and invalidation affect how much work is repeated.

This is a model, not a guarantee that every plugin or build uses the same internal sequence. Consult the versioned hooks when a plugin depends on a particular stage.

### Source Maps / Source Map

A source map maps generated code locations back to source locations. Webpack's `devtool` option trades build and rebuild time, map detail, output size, and exposure of source content. There is no universal fastest or safest setting.

- Development options such as `eval-source-map` favor fast rebuilds and detailed debugging, with larger/evaluated output.
- A separate `source-map` is detailed but emits a `.map` file, normally referenced by the bundle.
- `inline-source-map` embeds the map as a data URL in the generated output instead of a separate file.
- `cheap-source-map` keeps line-level mappings but omits columns and loader-generated maps; `cheap-module-source-map` includes loader maps simplified to line-level mappings.
- `eval-cheap-module-source-map` evaluates modules and includes loader maps simplified to line-level mappings, a development trade-off rather than a universal speed ranking.
- `hidden-source-map` emits a map without a public reference; keep the map off the public server and upload it to the error-reporting system.
- `nosources-source-map` omits `sourcesContent` but can still expose filenames and project structure.

Choose policy by who needs to debug production errors and who may fetch the map. A source map is not access control: if a public map contains sources, treat those sources as public. Loader-generated maps also need to be passed through so stack traces map to the original source.

## Package Managers and Corepack / 包管理器与 Corepack

The `packageManager` field in `package.json` can record the expected package manager and version. Corepack provides shims that can select a project-pinned manager when that Corepack installation is available. The exact enable/install steps depend on how Node.js was installed.

Corepack was bundled with some Node.js distributions starting in Node 14.19/16.9, but Node.js 25 no longer distributes it. On Node 25 or later, do not assume `corepack enable` exists; use the separately installed Corepack package or the package manager's documented setup. Check `node --version`, `corepack --version`, and the official docs for the chosen distribution before following an old setup guide.

## Hosted Functions / 托管函数

The archived example refers to Google Cloud Functions. Current Google product documentation uses **Cloud Run functions**, with distinct first-generation and newer deployment/runtime options. A function can be invoked by HTTP or events and can reduce routine server administration, but it is still backend compute; it does not replace the need to design an API or separate a front end from trusted server-side work.

Potential benefits include event-driven integration, scaling managed by the platform, and usage-based billing. These are conditional: cost can also include provisioned minimum instances, builds, networking, storage, and logs; cold starts and scale limits affect latency; runtime duration, concurrency, region, and trigger behavior vary by generation/configuration. Event sources can retry deliveries, so handlers should be designed for duplicate events when the provider documents at-least-once delivery. Compare the specific product generation, limits, failure behavior, observability, and deployment workflow with a long-running service before choosing.

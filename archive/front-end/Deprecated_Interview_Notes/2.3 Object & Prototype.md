# JavaScript Objects, Prototypes, and Copying / JavaScript 对象、原型与复制

**Core / 核心：** Ordinary-object property lookup follows `[[Prototype]]` links; construction uses a constructor's `prototype` only when that value is an object. 普通对象的属性查找沿 `[[Prototype]]` 链进行；构造时只有构造器的 `prototype` 是对象才会用作新对象的原型。

**Key terms / 关键词：** `[[Prototype]]` 原型链接 · constructor 构造器 · own property 自有属性 · property key 属性键 · shallow copy 浅拷贝 · graph clone 图复制

## What is the JavaScript Prototype Chain? How is it Formed?
Ordinary objects can inherit properties through a prototype chain. `[[Prototype]]` is an internal link; `Object.getPrototypeOf` reports it for ordinary objects, while a Proxy can provide a `getPrototypeOf` trap. `__proto__` is a legacy accessor available on many ordinary objects, not a universal own property.

For an ordinary object, property access checks the object itself first, then follows its prototype chain until the property is found or the chain reaches `null`.

Many ordinary objects eventually inherit from `Object.prototype`, which supplies methods such as `toString` and `valueOf`. This is not universal: `Object.create(null)` creates an object whose prototype is `null`.

### Distinction Between Functions and Objects
JavaScript treats functions as first-class objects, meaning that every function in JavaScript is actually a special type of object. This distinction is crucial for understanding the prototype chain. There are two key properties involved in the prototype chain mechanism: `prototype` and `__proto__`.

- **Constructor `prototype` property**: Constructable functions generally have this property; it supplies the prototype for instances created with `new` when its value is an object. It is not the shared `Function.prototype` object. Arrow functions are callable but not constructable and have no own `prototype` property.
- **Object `[[Prototype]]`**: Each ordinary object has an internal prototype link, which may be `null`. Use `Object.getPrototypeOf` and `Object.setPrototypeOf` for inspection or deliberate changes.

### Formation of the Prototype Chain

The prototype chain is primarily established through constructor functions and the `new` keyword. Here's how it works step by step:

1. **Constructor Function Creation**: A constructor function is defined by the user. This function has a `prototype` property pointing to an object that will serve as the prototype for instances created from this constructor.

2. **Instance Creation**: When a new instance is created using the `new` keyword, JavaScript automatically sets the instance's internal `[[Prototype]]` property (accessible in most environments as `__proto__`) to the prototype object of the constructor function. This links the new object to its prototype.

3. **Chain Linking**: Lookup follows these links until the requested property is found or the link is `null`. A constructor created with the default function prototype commonly has a chain through `Constructor.prototype` and `Object.prototype`.

Let's explore a concise example to illustrate these concepts:

```javascript
function Person(name) {
  this.name = name; // Instance property
}

// Adding a method to the Person prototype
Person.prototype.sayHello = function() {
  console.log(`Hello, my name is ${this.name}`);
};

// Creating an instance of Person
const alice = new Person('Alice');

// Invoking the sayHello method inherited from Person.prototype
alice.sayHello(); // Outputs: Hello, my name is Alice

// Examining the prototype chain of alice
console.log(Object.getPrototypeOf(alice) === Person.prototype); // true
console.log(Object.getPrototypeOf(Person.prototype) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype)); // null
```

In this example:
- The `alice` instance is linked to `Person.prototype`, and through it, to `Object.prototype`, finally reaching `null`.
- This chain allows `alice.sayHello()` to execute successfully. Although `sayHello` is not a direct property of `alice`, JavaScript engine finds it up the chain in `Person.prototype`.

## Differences between `Object.create` and `{}`
1. **Using `{}` (Object Literals)**: This is the most common way to create an object. The created object inherits from `Object.prototype`, making it an instance of Object.

    ```typescript
    const obj1 = {};
    console.log(Object.getPrototypeOf(obj1) === Object.prototype); // true
    ```

2. **Using `Object.create(proto)`**: This method creates a new object with the specified object as its prototype. This allows for more flexibility in setting up the prototype chain.

    - **`Object.create(Object.prototype)`**: Creates a new object with `Object.prototype` as its prototype, similar to `{}`.
    - **`Object.create({name: 'Tom'})`**: Creates a new object with a custom object (`{name: 'Tom'}`) as its prototype, diverging from `Object.prototype`.

    ```typescript
    const obj2 = Object.create(Object.prototype);
    const obj3 = Object.create({name: 'Tom'});
    console.log(Object.getPrototypeOf(obj2) === Object.prototype); // true
    console.log(Object.getPrototypeOf(obj3) === Object.prototype); // false
    console.log(obj3.name, Object.hasOwn(obj3, 'name')); // 'Tom', false: name is inherited
    ```

## How to Simulate the `new` Operator in JavaScript

For an ordinary constructor, `new` creates an object using the constructor's object-valued `prototype` (or a default prototype), calls the constructor with that object as `this`, and returns an object-valued constructor result in preference to the created object. A primitive return value is ignored.

1. **Create an empty object** that inherits from the constructor function's prototype.
2. **Execute the constructor function** with the newly created object assigned to `this`.
3. **Return the new object** unless the constructor explicitly returns a different object.

The method to simulate the `new` process can be represented as follows:

```typescript
function _new(fn: Function, ...args: any[]): any {
    const candidate = (fn as any).prototype;
    const proto = candidate !== null &&
        (typeof candidate === 'object' || typeof candidate === 'function')
        ? candidate
        : Object.prototype;
    const instance = Object.create(proto);
    const result = Reflect.apply(fn, instance, args);
    return result !== null &&
        (typeof result === 'object' || typeof result === 'function')
        ? result
        : instance;
}

// Test example
function Person(this: { name: string }, name: string) {
    this.name = name;
}
const person = _new(Person, 'Tom');
console.log(person.name); // Tom
```

This teaching `_new` helper covers ordinary constructable functions only. It does not reproduce `new.target`, class constructors, bound constructors, built-in constructors, proxies, or subclass construction. A callable function is an object, so a function-valued `fn.prototype` is also a valid prototype.

### `class` is Syntactic Sugar for Constructor Functions

Despite the historical wording of this heading, classes are not merely constructor-function syntax. They use prototype-based inheritance and `typeof SomeClass` is `'function'`, but a class constructor cannot be called without `new`; class bodies are strict, and class methods have defined property attributes and `super` behavior.

## Determining Variable Types in JavaScript

Understanding the type of a variable is crucial in JavaScript due to its dynamically typed nature. This section explores various methods to ascertain the type of variables effectively.

### `typeof` Operator
**Overview:**
The `typeof` operator is a straightforward tool used to determine the primitive type of a variable. Note that `typeof` is an operator, like `+` or `-`, not a function.

**Examples and Usage:**
```javascript
console.log(typeof 1); // Output: 'number'
console.log(typeof 'test'); // Output: 'string'
console.log(typeof true); // Output: 'boolean'
console.log(typeof null); // 'object' for historical compatibility; null is a primitive value
```

**Advantages:**
- Simple and quick to use for identifying primitive types.

**Limitations:**
- Inadequate for non-primitive types, as it returns `'object'` for arrays, null, and plain objects, which can be misleading.

### `Object.prototype.toString.call()`
**Overview:**
A useful diagnostic tag for built-in values; it is not an unspoofable type test. Objects can customize the tag with `Symbol.toStringTag`, and proxies or getters can throw during inspection.

**Examples and Usage:**
```javascript
console.log(Object.prototype.toString.call([1, 2, 3])); // Output: '[object Array]'
console.log(Object.prototype.toString.call(null)); // Output: '[object Null]'
const tagged = { [Symbol.toStringTag]: 'Array' };
console.log(Object.prototype.toString.call(tagged)); // '[object Array]' — a user-defined tag
```

**Advantages:**
- Provides a built-in tag useful in diagnostics, but should not be treated as runtime validation for untrusted values.

**Limitations:**
- More verbose and complex compared to `typeof`, potentially increasing code complexity for simple checks.

### `instanceof` Operator
**Overview:**
The default behavior checks whether the constructor's object-valued `prototype` appears in the value's prototype chain. `Symbol.hasInstance` can customize the test. Cross-realm values can surprise when the constructor identity differs, such as using this realm's `Array` with an array created in another realm.

**Symbol.hasInstance**
It use Symbol.hasInstance method to determine if a constructor object recognizes an object as its instance.
```javascript
function Foo() {}
let f = new Foo();
console.log(Foo[Symbol.hasInstance](f)); // Output: true
```
The default `Function.prototype[Symbol.hasInstance]` implementation is inherited by functions.

**Examples and Usage:**
```javascript
console.log([] instanceof Array); // Output: true
console.log({} instanceof Object); // Output: true
```

**Limitations:**
- The default check returns `false` for primitives and depends on prototype identity; `Array.isArray` is the direct array test and works across realms.

### Custom `getType` Function
**Overview:**
A helper can combine common JavaScript tags for diagnostics, but it cannot recognize every value reliably or replace validation at a trust boundary.

**Function Definition and Usage:**
```javascript
function getType(val) {
    const type = typeof val;
    if (type !== 'object') {
        return type; // Directly return the type of primitives.
    } else if (val === null) {
        return 'null'; // Correctly identify null.
    }
    // Use Object.prototype.toString for detailed object type identification.
    return Object.prototype.toString.call(val).slice(8, -1).toLowerCase();
}

console.log(getType(null)); // Output: 'null'
console.log(getType([1, 2, 3])); // Output: 'array'
```

**Limitations:**
- The tag can be customized, and distinct user-defined classes may report only `object`; use explicit predicates or schema validation when the distinction matters.

This helper is for inspection, not comprehensive validation.

## Object Key Data Types in JavaScript

Object property keys are strings or Symbols. Other key values go through `ToPropertyKey`: JavaScript first requests a primitive with a string hint, then keeps a Symbol or converts the result to a string. User-defined coercion can therefore affect the key or throw.

### Principles of Key Conversion

1. **Allowed Key Types**: Only strings and symbols can be used directly as keys. This limitation is designed to ensure property keys have a predictable format.
2. **Conversion of Other Types**: Numbers and other non-Symbol primitives are converted to strings; objects may use `Symbol.toPrimitive`, `toString`, or `valueOf` during conversion.
3. **Ordinary object example**: A plain object usually converts to `"[object Object]"` through its inherited methods, so two such objects can collide as property keys. An override can change that result.
4. **Map keys**: A `Map` retains arbitrary key values. It compares keys with SameValueZero; object keys are distinct by identity.

### Examples and Explanations

**Example 1: Numeric and String Key Equivalence**

```javascript
let a = {}, b = '123', c = 123;
a[b] = 'b';
a[c] = 'c';
console.log(a[b]); // Outputs: 'c'
```
- In this example, both `b` (a string) and `c` (a number) are used as keys. Since `c` is converted to a string, it overwrites the value associated with the string `'123'`, demonstrating how numeric keys are treated as their string equivalents.

**Example 2: Symbol Uniqueness**

```javascript
let a = {}, b = Symbol('123'), c = Symbol('123');
a[b] = 'b';
a[c] = 'c';
console.log(a[b]); // Outputs: 'b'
```
- Symbols are unique, so even if `b` and `c` have the same description (`'123'`), they are considered different keys. This example illustrates the utility of symbols for creating distinct key-value pairs.

**Example 3: Plain Object Conversion to String**

```javascript
let a = {}, b = {key: '123'}, c = {key: '456'};
a[b] = 'b';
a[c] = 'c';
console.log(a[b]); // Outputs: 'c'
```
- Here, `b` and `c` are both plain objects. Despite having different properties, they are converted to the same string (`"[object Object]"`) when used as keys, causing `c` to overwrite `b`'s associated value. This highlights the importance of careful key selection to avoid unintended overwrites.

## Value Types vs. Reference Types
**What is the output of the following code, and why?**

```javascript
let a = {n: 1}
let b = a
a.x = a = {n: 2}
console.log(a.x)
console.log(b.x)
```

To read the result, distinguish assignment associativity from evaluation of the property reference:

1. **Assignment is right-associative**

   In `b = a = 200`, the inner assignment produces the value `200`, which is then assigned to `b`:

   ```javascript
   let a = 100;
   let b = a = 200;
   // This is processed as:
   // 1. a = 200
   // 2. b = a (where a is now 200)
   ```

2. **The left-hand property reference keeps its base object**

   In `a.x = a = {n: 2}`, JavaScript evaluates the left-hand reference to `a.x` while `a` still points to the original object. It then evaluates the right-hand assignment, updates `a`, and writes the resulting object through the already-evaluated reference.

   ```javascript
   let a = {};
   a.x = 100;
   // The property value changes only when the assignment is performed.
   ```

With these principles in mind, let's dissect the initial example:

```javascript
let a = {n: 1}
let b = a;
// At this point, both 'a' and 'b' reference the same object: {n: 1}

a.x = a = {n: 2};
// The left-hand reference has the original object as its base.
// The right-hand assignment makes `a` point to a new object.
// The final write stores that new object in `x` on the original object.
```

Here's a visual representation of the state changes:

1. After declaring `a` and `b`:

```
a, b -> {n: 1}
```

2. Reassigning `a` does not change the base object already captured for `a.x`:

```
a -> {n: 2}
b -> {n: 1}
```

3. The final write updates the original object:

```
a -> {n: 2}
b -> {n: 1, x: {n: 2}}
```

### Outputs:

- `console.log(a.x)` prints `undefined`, because 'a' now points to `{n: 2}`, which does not have an 'x' property.
- `console.log(b.x)` prints `{n: 2}`, because 'b' still points to the original object, which now includes `x: {n: 2}`.

## Implement a Deep Copy Function

Cloning is a policy decision: which values, properties, and identities should be duplicated? JSON round-tripping is suitable only for JSON-serializable data; it does not preserve Maps, Sets, dates, functions, or cycles.

### Why Not `JSON.stringify` and `JSON.parse`?

For nested JSON-compatible data, `JSON.stringify` followed by `JSON.parse` is a concise copy. It has important limits:

- **Loses Map and Set entries:** By default, their entries are not represented as JSON data.
- **Fails with circular references by default:** A cycle makes ordinary `JSON.stringify` throw; a replacer or `toJSON` hook can change what is serialized.
- **Changes or rejects values:** Functions and `undefined` are omitted or transformed depending on where they occur; dates serialize to strings, and a `BigInt` value throws unless serialization is customized.

### Handling Maps, Sets, and Circular References

This illustrative TypeScript helper copies arrays, same-realm plain objects, and same-realm built-in `Date`, `RegExp`, `Map`, and `Set` values, including cycles and shared references. It copies enumerable own string-keyed data properties, leaves functions shared, and rejects enumerable own string-keyed accessors, custom prototypes, and built-in subclasses rather than silently turning them into base instances. Array subclasses with a custom prototype are also rejected. For built-in values, assume the methods, getters, and iterators used below have not been overridden on the instance or its prototype chain; for example, `d.getTime = () => 2` can make a Date with internal time 1 copy as 2.

```typescript
function deepCopy(obj: any, seen = new WeakMap<object, any>()): any {
  if (obj === null || (typeof obj !== 'object' && typeof obj !== 'function')) {
    return obj;
  }
  if (typeof obj === 'function') return obj; // Functions are shared, not cloned.

  if (seen.has(obj)) return seen.get(obj);

  let copy: any;
  const copyEnumerableData = (source: object, target: any) => {
    for (const key of Object.keys(source)) {
      const descriptor = Object.getOwnPropertyDescriptor(source, key)!;
      if (!('value' in descriptor)) {
        throw new TypeError('Accessor properties are outside this clone exercise');
      }
      Object.defineProperty(target, key, {
        value: deepCopy(descriptor.value, seen),
        enumerable: true,
        configurable: true,
        writable: true
      });
    }
  };

  if (obj instanceof Date) {
    if (Object.getPrototypeOf(obj) !== Date.prototype) {
      throw new TypeError('Built-in subclasses are outside this clone exercise');
    }
    copy = new Date(obj.getTime());
    seen.set(obj, copy);
    copyEnumerableData(obj, copy);
  } else if (obj instanceof RegExp) {
    if (Object.getPrototypeOf(obj) !== RegExp.prototype) {
      throw new TypeError('Built-in subclasses are outside this clone exercise');
    }
    copy = new RegExp(obj.source, obj.flags);
    copy.lastIndex = obj.lastIndex;
    seen.set(obj, copy);
    copyEnumerableData(obj, copy);
  } else if (obj instanceof Map) {
    if (Object.getPrototypeOf(obj) !== Map.prototype) {
      throw new TypeError('Built-in subclasses are outside this clone exercise');
    }
    copy = new Map();
    seen.set(obj, copy);
    for (const [key, value] of obj) {
      copy.set(deepCopy(key, seen), deepCopy(value, seen));
    }
    copyEnumerableData(obj, copy);
  } else if (obj instanceof Set) {
    if (Object.getPrototypeOf(obj) !== Set.prototype) {
      throw new TypeError('Built-in subclasses are outside this clone exercise');
    }
    copy = new Set();
    seen.set(obj, copy);
    for (const value of obj) copy.add(deepCopy(value, seen));
    copyEnumerableData(obj, copy);
  } else {
    const proto = Object.getPrototypeOf(obj);
    if (Array.isArray(obj) ? proto !== Array.prototype : proto !== Object.prototype && proto !== null) {
      throw new TypeError('Custom prototypes are outside this clone exercise');
    }
    copy = Array.isArray(obj) ? new Array(obj.length) : Object.create(proto);
    seen.set(obj, copy); // Register before recursion so cycles and shared references work.
    copyEnumerableData(obj, copy);
  }

  return copy;
}
```

```typescript
const shared = { id: 1 };
const source: any = { shared, list: [shared], map: new Map([[shared, 'value']]) };
source.self = source;
const cloned = deepCopy(source);
console.log(cloned !== source, cloned.self === cloned); // true, true
console.log(cloned.shared === cloned.list[0]); // true: shared identity is preserved
console.log(cloned.map.get(cloned.shared)); // 'value': the Map key was cloned too
```

### Key Points

- **Identity handling:** The `WeakMap` is populated before recursive work; this preserves cycles and shared references, including Map keys and values.
- **Supported built-ins:** `Date`, `RegExp` (including `lastIndex`), `Map`, and `Set` receive type-specific copies.
- **Deliberate limits:** Symbols, non-enumerable properties, original property descriptors, functions' internals, weak collections, typed arrays, DOM nodes, custom class instances, built-in subclasses, and cross-realm built-ins are not cloned. Enumerable own string-keyed accessors are rejected; proxy traps can run or throw. Deep nesting can still exhaust the call stack.

### Special Object Cloning - `Date` and `RegExp`
`Date` and `RegExp` store their primary state in built-in internal slots, so enumerable-property copying alone cannot reproduce them. This helper explicitly copies the date time value, regular-expression source and flags, and `lastIndex`.

## Why Define Class Functions in Constructor Prototype?

In JavaScript, using the prototype property of constructor functions to define methods offers substantial benefits in terms of efficiency, inheritance, and code manageability. This section delves into these advantages, supported by a structured, example-driven approach.

### Memory Efficiency
**Utilizing Prototypes**: A method stored on the prototype is one function shared by instances, while a function created in each constructor call is a separate per-instance property. Sharing can avoid per-instance method allocations; it does not by itself guarantee a measurable speedup.

### Inheritance Support
**Enabling Polymorphism**: Methods defined on the prototype facilitate inheritance across instances and derived classes. This capability is crucial for implementing polymorphic behaviors where methods can be overridden or extended in subclasses, enhancing code reusability and flexibility.

### Dynamic Updates
**Streamlining Code Maintenance**: Adding or replacing a prototype method affects lookups by existing instances that do not shadow that property with an own one.

### Practical Example: Implementing the `Animal` Class

Consider an `Animal` constructor where instances share a common method. Defining that method on the prototype avoids storing a separate function property on every instance.

```javascript
function Animal(name) {
    this.name = name;
}

// Adding a method to the prototype
Animal.prototype.makeSound = function() {
    console.log(`${this.name} makes a sound.`);
};

// Creating instances
const dog = new Animal('Dog');
const cat = new Animal('Cat');

// Testing the method
dog.makeSound(); // Output: Dog makes a sound.
cat.makeSound(); // Output: Cat makes a sound.
```

### Key Takeaways
- **Shared method**: `makeSound` is one function found through each instance's prototype chain.
- **Lookup behavior**: Changing `Animal.prototype.makeSound` affects existing instances unless an instance has its own `makeSound` property.

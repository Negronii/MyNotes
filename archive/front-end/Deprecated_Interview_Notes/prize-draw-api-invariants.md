# 抽奖接口不变量入口

本节记录一个具体抽奖 API 契约，包含公开规则读取、已认证参与、每个 (campaign_id, principal_id) 唯一参与结果、有限奖品条件扣减、本人结果查询和独立领奖。

在该例中，重试先验证当前主体权限；如果同一操作键、同一请求参数已有完成的参与结果，就返回原抽取结果与当前领奖状态。没有查到该键的已完成结果时，先检查活动状态：已关闭则返回 `campaign-closed`；活动开放时，换键重复报名才针对已有参与记录返回 `conflict`。中奖结果所有者通过独立 `claim` 操作领奖。这是该示例的契约，不代表所有抽奖系统。详见[同一库存不变量怎样用于抽奖？](../../../engineering-foundations/databases/database-fundamentals.md#%E5%90%8C%E4%B8%80%E5%BA%93%E5%AD%98%E4%B8%8D%E5%8F%98%E9%87%8F%E6%80%8E%E6%A0%B7%E7%94%A8%E4%BA%8E%E6%8A%BD%E5%A5%96%EF%BC%9F)。归档页保留为导航入口。

# [2623. Memoize](https://leetcode.com/problems/memoize/) / 记忆化缓存

Given a function `fn`, return a **memoized** version of that function.

A **memoized** function is a function that will never be called twice with the same inputs. Instead it will return a cached value.

You can assume there are 3 possible input functions: `sum`, `fib`, and `factorial`.

- `sum` accepts two integers `a` and `b` and returns `a + b`.
- `fib` accepts a single integer `n` and returns `1` if `n <= 1` or `fib(n - 1) + fib(n - 2)` otherwise.
- `factorial` accepts a single integer `n` and returns `1` if `n <= 1` or `factorial(n - 1) * n` otherwise.

**Example 1:**

```
Input:
fnName = "sum"
actions = ["call","call","getCallCount","call","getCallCount"]
values = [[2,2],[2,2],[],[1,2],[]]
Output: [4,4,1,3,2]
Explanation:
const sum = (a, b) => a + b;
const memoizedSum = memoize(sum);
memoizedSum(2, 2); // "call" - returns 4. sum() was called as (2, 2) was not seen before.
memoizedSum(2, 2); // "call" - returns 4. However sum() was not called because the same inputs were seen before.
// "getCallCount" - total call count: 1
memoizedSum(1, 2); // "call" - returns 3. sum() was called as (1, 2) was not seen before.
// "getCallCount" - total call count: 2
```

**Example 2:**

```
Input:
fnName = "factorial"
actions = ["call","call","call","getCallCount","call","getCallCount"]
values = [[2],[3],[2],[],[3],[]]
Output: [2,6,2,2,6,2]
Explanation:
const factorial = (n) => (n <= 1) ? 1 : (n * factorial(n - 1));
const memoFactorial = memoize(factorial);
memoFactorial(2); // "call" - returns 2.
memoFactorial(3); // "call" - returns 6.
memoFactorial(2); // "call" - returns 2. However factorial was not called because 2 was seen before.
// "getCallCount" - total call count: 2
memoFactorial(3); // "call" - returns 6. However factorial was not called because 3 was seen before.
// "getCallCount" - total call count: 2
```

**Example 3:**

```
Input:
fnName = "fib"
actions = ["call","getCallCount"]
values = [[5],[]]
Output: [8,1]
Explanation:
fib(5) = 8 // "call"
// "getCallCount" - total call count: 1
```

**Constraints:**

- `0 <= a, b <= 10^5`
- `1 <= n <= 10`
- `1 <= actions.length <= 10^5`
- `actions.length === values.length`
- `actions[i]` is one of "call" and "getCallCount"
- `fnName` is one of "sum", "factorial" and "fib"

## Core idea / 核心思路

Serialize the complete, ordered argument tuple as one key, then use `Map.has` to distinguish a cache hit from a missing entry. The problem treats `(a, b)` and `(b, a)` as separate inputs even when `sum` returns the same result. Under its finite-number inputs, `[1, 23]` and `[12, 3]` also remain distinct, and a cached `undefined` would still be recognized because the code checks presence rather than the value. / 将有序的完整参数元组序列化为一个键，再用 `Map.has` 区分缓存命中与键不存在。题目将 `(a, b)` 和 `(b, a)` 视为不同输入，即使 `sum` 的结果相同也要分别缓存。在题目的有限数字输入范围内，`[1, 23]` 和 `[12, 3]` 也不会混淆；即使缓存值是 `undefined`，按键是否存在判断仍可识别命中。

This key is intentionally scoped to the listed numeric functions. For general JavaScript inputs, JSON serialization can collide (for example, `[undefined]` and `[null]` both stringify as `"[null]"`), collapses object identity, and neither forwards nor includes the receiver `this`. A general-purpose memoizer must define those semantics, preserve a relevant receiver, and key it and each argument appropriately. ([ECMAScript `JSON.stringify`](https://tc39.es/ecma262/#sec-json.stringify), [ECMAScript `Map.has`](https://tc39.es/ecma262/#sec-map.prototype.has), [Map and Set reference](../../../../../../frontend/javascript/map-and-set.md))

## Solutions

```ts
type Fn = (...params: number[]) => number;

function memoize(fn: Fn): Fn {
  const map = new Map<string, number>();

  return function (...args) {
    const key = JSON.stringify(args);
    if (map.has(key)) {
      return map.get(key)!;
    }
    const res = fn(...args);
    map.set(key, res);
    return res;
  };
}

/**
 * let callCount = 0;
 * const memoizedFn = memoize(function (a, b) {
 *	 callCount += 1;
 *   return a + b;
 * })
 * memoizedFn(2, 3) // 5
 * memoizedFn(2, 3) // 5
 * console.log(callCount) // 1
 */
```

**Complexity / 复杂度:** For `k` arguments, building the serialized key takes `O(k)` time; a cache hit avoids invoking `fn`. Space grows with the number of distinct input tuples. Memoizing the outer `fib` call does not memoize recursive calls made directly inside `fn`. / 对 `k` 个参数，生成序列化键需要 `O(k)` 时间；命中缓存时不会调用 `fn`。空间随不同参数元组的数量增长。仅记忆化外层 `fib` 调用，并不会自动缓存 `fn` 内部直接发起的递归调用。

# LeetCode 2715：怎样取消尚未执行的一次性回调？

每个题例由两个计时器决定 `fn` 是否会被调用：`cancellable` 按 `t` 安排目标回调，题例按 `cancelT` 安排调用 `cancel` 的回调。哪个回调先运行，就决定目标回调是否开始。

调用 `cancellable(fn, args, t)` 时，代码立刻安排目标回调并返回无参、无返回值的取消函数。它保存该计时器的 id；调用 `cancel()` 会同步执行 `clearTimeout`，阻止尚未开始的目标回调执行。目标回调开始后，清除计时器不会撤回 `fn` 的调用或回滚副作用。这里没有 Promise；若 `fn` 自己启动异步工作，取消函数也不负责中止那项工作。实现写作普通调用 `fn(...args)`，不会保留方法调用时的 `this`。

## 原题与输入约束

**Difficulty:** Easy

Given a function `fn`, an array of arguments `args`, and a timeout `t` in milliseconds, return a cancel function `cancelFn`.

After a delay of `t`, `fn` should be called with `args` passed as parameters **unless** `cancelFn` was invoked before the delay of `t` milliseconds elapses, specifically at `cancelT` ms. In that case, `fn` should never be called.

**Example 1:**

```
Input: fn = (x) => x * 5, args = [2], t = 20, cancelT = 50
Output: [{"time": 20, "returned": 10}]
Explanation:
const result = []

const fn = (x) => x * 5

const start = performance.now()

const log = (...argsArr) => {
    const diff = Math.floor(performance.now() - start);
    result.push({"time": diff, "returned": fn(...argsArr)})
}

const cancel = cancellable(log, [2], 20);

const maxT = Math.max(t, 50)

setTimeout(cancel, cancelT)

setTimeout(() => {
    console.log(result) // [{"time":20,"returned":10}]
}, 65)
```

The cancellation was scheduled to occur after a delay of `cancelT` (50ms), which happened after the execution of `fn(2)` at 20ms.

**Example 2:**

```
Input: fn = (x) => x**2, args = [2], t = 100, cancelT = 50
Output: []
Explanation: The cancellation was scheduled to occur after a delay of `cancelT` (50ms), which happened before the execution of `fn(2)` at 100ms, resulting in `fn(2)` never being called.
```

**Example 3:**

```
Input: fn = (x1, x2) => x1 * x2, args = [2,4], t = 30, cancelT = 100
Output: [{"time": 30, "returned": 8}]
Explanation: The cancellation was scheduled to occur after a delay of `cancelT` (100ms), which happened after the execution of `fn(2,4)` at 30ms.
```

**Constraints:**

- `fn` is a function
- `args` is a valid JSON array
- 1 <= `args.length` <= 10
- 20 <= `t` <= 1000
- 10 <= `cancelT` <= 1000

The current problem page names the cancellation delay `cancelTimeMs`; these examples use `cancelT` for the same parameter. ([LeetCode statement, checked 2026-10-15](https://leetcode.com/problems/timeout-cancellation/))

## Solution

```ts
type JSONValue =
  | null
  | boolean
  | number
  | string
  | JSONValue[]
  | { [key: string]: JSONValue };
type Fn<Args extends JSONValue[]> = (...args: Args) => unknown;

function cancellable<Args extends JSONValue[]>(fn: Fn<Args>, args: Args, t: number): () => void {
  const timeoutId = setTimeout(() => {
    fn(...args);
  }, t);

  return () => clearTimeout(timeoutId);
}

/**
 *  const result = []
 *
 *  const fn = (x) => x * 5
 *  const args = [2], t = 20, cancelT = 50
 *
 *  const start = performance.now()
 *
 *  const log = (...argsArr) => {
 *      const diff = Math.floor(performance.now() - start);
 *      result.push({"time": diff, "returned": fn(...argsArr)})
 *  }
 *
 *  const cancel = cancellable(log, args, t);
 *
 *  const maxT = Math.max(t, cancelT)
 *
 *  setTimeout(() => {
 *     cancel()
 *  }, cancelT)
 *
 *  setTimeout(() => {
 *     console.log(result) // [{"time":20,"returned":10}]
 *  }, maxT + 15)
 */
```

## 取消与目标回调的先后

`cancellable` 不等待 `fn` 返回，也不把 `fn` 的返回值交给调用方。归档例 1 的代码片段没有声明 `t` 和 `cancelT`，单独复制会因变量未定义而无法运行；按题面输入分别是 `t = 20` 和 `cancelT = 50`。片段最后的第三个计时器只负责稍后打印结果，不参与取消顺序。当前 LeetCode 页面把取消延迟称为 `cancelTimeMs`。

| 题例 | 按示例调度发生的顺序 | 记录结果 |
| --- | --- | --- |
| 1：`t = 20`，`cancelT = 50` | 目标回调先在约 20 ms 调用 `fn(2)`；约 50 ms 时才调用取消函数。 | `fn(2)` 返回 `10`，记录为 `[{"time": 20, "returned": 10}]`。之后取消已无待执行目标回调可移除。 |
| 2：`t = 100`，`cancelT = 50` | 取消函数先运行并清除目标计时器。 | `fn` 从未开始，结果为空数组 `[]`。 |
| 3：`t = 30`，`cancelT = 100` | 目标回调先调用 `fn(2, 4)`；取消函数稍后运行。 | `fn` 返回 `8`，记录为 `[{"time": 30, "returned": 8}]`。之后取消不会撤销这次调用。 |

表中时间是理想化示例。真实事件循环会在延迟达到后安排回调；如果主线程忙碌，两个定时器都可能晚于指定时间。关键边界是取消函数是否在目标回调开始前被调用，而不是是否在计时器名义到期时刻前调用 `clearTimeout`。目标回调若已开始，普通 JavaScript 不会被 `clearTimeout` 抢占。

`JSONValue` 描述题目 JSON 实参的递归静态类型形状，本身不会验证运行时值确为有效 JSON；例如 TypeScript 的 `number` 也包含 `NaN`，而有效 JSON 输入由题目约束另行保证。泛型元组 `Args` 保留实参数量、顺序和各位置类型，所以严格检查下 `(x: number) => number` 可以和 `[2]` 配对。旧签名把 `fn` 写成可接收任意 `JSONValue` 的函数，按参数逆变规则，它无法接收只接受 `number` 的函数。`Fn` 的返回类型是 `unknown`，因为解法不使用 `fn` 的返回值；取消函数的签名则是 `() => void`。

## 普通函数调用与 this

计时器回调中执行的是 `fn(...args)`，相当于先取出函数再普通调用，不会自动沿用一个对象方法的接收者。例如 `const obj = { value: 3, run() { return this.value; } }; cancellable(obj.run, [], 20)` 不会因此把 `this` 绑定到 `obj`；如函数依赖 `this`，调用者应显式绑定函数或传入闭包。题目原解法只处理函数和 JSON 实参，不包含 `this` 绑定行为。

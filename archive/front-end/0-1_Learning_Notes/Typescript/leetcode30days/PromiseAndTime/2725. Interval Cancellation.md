# LeetCode 2725：怎样重复调用函数直到取消？

`cancellable(fn, args, t)` 在当前调用栈中同步调用一次 `fn(...args)`。只有这次调用正常返回后，它才登记每隔 `t` 毫秒重复调用的重复定时器（interval），并返回取消函数 `cancelFn`。题目测试器拿到 `cancelFn` 后，才用 `setTimeout(cancelFn, cancelTimeMs)` 安排取消。`cancellable` 本身返回的是取消函数，不是 `fn` 的返回值；题例测试器另用 `log` 包装 `fn` 来记录值。

## 第一次调用、重复调用与取消

以题例 1 为例，测试器先执行 `start = performance.now()`，随后调用 `cancellable(log, [4], 35)`。`log(4)` 调用 `fn(4)` 得到 8，并把这次结果记在 `result` 中。接着的登记顺序如下：

| 顺序 | 实际动作 | 记录或状态 |
| --- | --- | --- |
| 1 | 同步执行首次 `log(4)`；内层 `fn(4)` 返回 8 | 题例的预期首条记录是 `{ time: 0, returned: 8 }` |
| 2 | 首次 `log(4)` 正常返回后，`setInterval` 登记重复回调并返回 `intervalId` | `cancellable` 随后返回 `() => clearInterval(intervalId)`；该箭头函数通过闭包记住这一次调用创建的 `intervalId` |
| 3 | 测试器收到 `cancelFn` 后执行 `setTimeout(cancelFn, 190)` | `cancelTimeMs` 的延迟从这次 `setTimeout` 登记时开始计算 |
| 4 | interval 首次和后续回调按 `t=35` ms 重复调用 `log(4)`，每次内层 `fn(4)` 得到 8 | 题目预期记录约在 35、70、105、140、175 ms；实际时间可能晚于这些名义时刻 |
| 5 | 上述取消 timer 到期后调用 `cancelFn`，它以捕获的 `intervalId` 调用 `clearInterval` | 已完成的记录保留；后续 interval 回调不再开始。下一次题目模型中的调用本应约在 210 ms |

题面示例用一个 `start` 测量记录时间，而两个 timer 的延迟分别从各自登记时起算：`setInterval` 在同步首调返回后才登记；测试器在 `cancellable` 返回后才登记 `setTimeout`。示例里的首调很快，所以理想时间轴把它们近似当作从 `start` 同时起步；这些时刻不是从进入 `cancellable` 起算的精确保证。比如首调若同步占用约 40 ms、`t=35`，interval 要到首调返回后才登记，第一次重复调用约在 `start+75` ms；取消延迟也要到测试器拿到 `cancelFn` 并登记 `setTimeout` 后才开始。

原题三组输入都遵循“0 时同步调用一次，再按间隔重复，取消后停止未来调用”的规则。下表列出三个算例的完整期望记录：

| 参数 `args`、间隔 `t`、取消延迟 `cancelTimeMs` | 题目模型中的调用时刻（ms） | 每次调用结果 |
| --- | --- | --- |
| `[4]`，35，190 | 0、35、70、105、140、175 | 8 |
| `[2, 5]`，30，165 | 0、30、60、90、120、150 | 10 |
| `[5, 1, 3]`，50，180 | 0、50、100、150 | 9 |

题目允许 `cancelTimeMs` 小于 `t`，例如 `t=35`、`cancelTimeMs=10`。测试器在 `cancellable` 返回后很快登记取消 timer，于是取消先于第一次 interval 回调到期；同步首调仍发生，因此结果只有这一条记录。

取消函数只阻止未来的重复回调，不能撤销首次调用及已有记录、副作用，也不能中断已开始运行的 JavaScript 回调。若取消与某次回调接近同时，结果取决于宿主先运行哪一段：先取消则该回调不会开始；回调已经开始则继续执行。若 `fn` 在首次同步调用中直接抛错，异常向外传播，执行在 `setInterval` 登记前就中止，因此 `cancellable` 不会返回取消函数；题例均假定正常返回。

`fn` 也可能返回Promise，但实现不等待、保存或处理这个返回值。假设每次异步工作需 80 ms、`t=30`，约 0、30、60 ms 可分别启动三次，前一次尚未完成就开始下一次。取消只阻止之后的新调用，已启动的异步工作仍会继续；如果它们拒绝，`cancellable` 不会替这些 Promise 处理拒绝，`fn` 需要自行处理，或改用会追踪并协调异步工作的实现。

类型签名用泛型参数 `Args` 把回调形参与传入的参数数组关联起来。严格模式下可直接传 `cancellable((x: number) => x * 2, [4], 35)`；若先写 `const args = [4]`，TypeScript 会把它推断为 `number[]`，而不是“恰好一个数字”的元组，因而不保证能配对单参数回调。可以直接传 `[4]`，或声明 `const args: [number] = [4]` 保留单元素元组。这个类型关联只影响编译检查，不改变下方实现的运行逻辑。

更多异步组合与取消方式见[回调、Promise 与 async 函数怎样组合异步工作？](../../../../../../frontend/javascript/asynchronous-javascript.md#%E5%8F%96%E6%B6%88%E4%B8%80%E6%AC%A1%E6%88%96%E9%87%8D%E5%A4%8D%E5%AE%9A%E6%97%B6%E5%99%A8%E6%97%B6%EF%BC%8C%E5%93%AA%E4%BA%9B%E8%B0%83%E7%94%A8%E8%BF%98%E4%BC%9A%E5%8F%91%E7%94%9F%EF%BC%9F)。

## Solution

```typescript
type JSONValue =
  | null
  | boolean
  | number
  | string
  | JSONValue[]
  | { [key: string]: JSONValue };
type Fn<Args extends JSONValue[]> = (...args: Args) => unknown;

function cancellable<Args extends JSONValue[]>(fn: Fn<Args>, args: Args, t: number): () => void {
  fn(...args);
  const intervalId = setInterval(() => {
    fn(...args);
  }, t);

  return () => clearInterval(intervalId);
}

/**
 *  const result = []
 *
 *  const fn = (x) => x * 2
 *  const args = [4], t = 35, cancelT = 190
 *
 *  const start = performance.now()
 *
 *  const log = (...argsArr) => {
 *      const diff = Math.floor(performance.now() - start)
 *      result.push({"time": diff, "returned": fn(...argsArr)})
 *  }
 *
 *  const cancel = cancellable(log, args, t);
 *
 *  setTimeout(() => {
 *     cancel()
 *  }, cancelT)
 *
 *  setTimeout(() => {
 *    console.log(result)  // [
 *                         //      {"time":0,"returned":8},
 *                         //      {"time":35,"returned":8},
 *                         //      {"time":70,"returned":8},
 *                         //      {"time":105,"returned":8},
 *                         //      {"time":140,"returned":8},
 *                         //      {"time":175,"returned":8}
 *                         //  ]
 *  }, cancelT + t + 15)
 */
```

## 原题与输入约束

Given a function `fn`, an array of arguments `args`, and an interval time `t`, return a cancel function `cancelFn`.

The function `fn` should be called with `args` immediately and then called again every `t` milliseconds until `cancelFn` is called at `cancelT` ms.

**Example 1:**

```typescript
Input: (fn = (x) => x * 2), (args = [4]), (t = 35), (cancelT = 190);
Output: [
  { time: 0, returned: 8 },
  { time: 35, returned: 8 },
  { time: 70, returned: 8 },
  { time: 105, returned: 8 },
  { time: 140, returned: 8 },
  { time: 175, returned: 8 },
];
```

**Explanation:**

```typescript
const result = [];
const fn = (x) => x * 2;
const args = [4],
  t = 35,
  cancelT = 190;

const start = performance.now();

const log = (...argsArr) => {
  const diff = Math.floor(performance.now() - start);
  result.push({ time: diff, returned: fn(...argsArr) });
};

const cancel = cancellable(log, args, t);
setTimeout(cancel, cancelT);

setTimeout(() => {
  console.log(result); // Output
}, cancelT + 15);
```

Every 35ms, `fn(4)` is requested. Cancellation is scheduled for 190ms. The example shows the expected sequence; real timer callbacks can be late. The calls and their results are:

- 1st `fn` call is at 0ms. `fn(4)` returns 8.
- 2nd `fn` call is requested at 35ms. `fn(4)` returns 8.
- ...
- Cancellation is requested at 190ms.

**Example 2:**

```typescript
Input: fn = (x1, x2) => (x1 * x2), args = [2, 5], t = 30, cancelT = 165
Output:
[
    {"time": 0, "returned": 10},
    {"time": 30, "returned": 10},
    ...
]
```

**Explanation:**

Every 30ms, `fn(2, 5)` is called. Until t=165ms, then it is cancelled. The function calls and their results are as follows:

- 1st `fn` call is at 0ms.
- 2nd `fn` call is at 30ms.
- ...
- Cancelled at 165ms

**Example 3:**

```typescript
Input: fn = (x1, x2, x3) => (x1 + x2 + x3), args = [5, 1, 3], t = 50, cancelT = 180
Output:
[
    {"time": 0, "returned": 9},
    ...
]
```

**Explanation:**

Every 50ms, `fn(5, 1, 3)` is called. Until t=180ms, then it is cancelled. The function calls and their results are as follows:

- 1st `fn` call is at 0ms.
- 2nd `fn` call is at 50ms.
- ...
- Cancelled at 180ms

**Constraints:**

- `fn` is a function
- `args` is a valid JSON array
- 1 <= `args.length` <= 10
- 30 <= `t` <= 100
- 10 <= `cancelT` <= 500

# LeetCode 2621：如何把计时器延迟包装成 Promise？

原题要求 `sleep(millis)` 返回一个约 `millis` 毫秒后兑现的 Promise，兑现成什么值都可以。本实现用 `setTimeout` 计时，到期后不带参数调用 `resolve()`，所以兑现值是 `undefined`。题例输出的 `100`、`200` 是测得的耗时，不是兑现值：例 1 在 `.then` 里用 `Date.now() - t` 计算经过的毫秒数。原题允许实际耗时有小幅偏差。

实现和例子的机制解释见[回调、Promise 与 async 函数怎样组合异步工作？](../../../../../../frontend/javascript/asynchronous-javascript.md#%E6%80%8E%E6%A0%B7%E6%8A%8A%E5%AE%9A%E6%97%B6%E5%99%A8%E5%BB%B6%E8%BF%9F%E5%8C%85%E8%A3%85%E6%88%90%20Promise%EF%BC%9F)。该章用代码说明计时器回调怎样调用 `resolve`，并说明它与“超时竞速”“取消尚未执行的计时器”有何不同。

## 原题与输入约束

**Difficulty:** Easy

Given a positive integer `millis`, write an asynchronous function that sleeps for `millis` milliseconds. It can resolve any value.

**Example 1:**

```
Input: millis = 100
Output: 100
Explanation: It should return a promise that resolves after 100ms.
let t = Date.now();
sleep(100).then(() => {
    console.log(Date.now() - t); // 100
});
```

**Example 2:**

```
Input: millis = 200
Output: 200
Explanation: It should return a promise that resolves after 200ms.
```

**Constraints:**

- 1 <= `millis` <= 1000

## Solution

```ts
function sleep(millis: number): Promise<void> {
  return new Promise((resolve) => {
    setTimeout(resolve, millis);
  });
}

/**
 * let t = Date.now()
 * sleep(100).then(() => console.log(Date.now() - t)) // 100
 */
```

## 调用顺序

| 时点 | 发生什么 | Promise 状态 |
| --- | --- | --- |
| 调用 `sleep(millis)` 时 | `new Promise` 的执行器同步运行，`setTimeout` 登记计时器，然后 `sleep` 立即返回 Promise。 | `pending` |
| 等待期间 | 调用方继续执行后续代码，也可以先登记 `.then` 回调；该回调此时还不会执行。 | `pending` |
| 计时器回调运行时 | `setTimeout` 调用 `resolve()`。没有传入兑现值，所以 Promise 以 `undefined` 成功兑现。 | 已兑现（fulfilled） |
| 计时器回调结束后 | 已登记的 `.then` 回调作为微任务（microtask）运行。 | 已兑现 |

`setTimeout` 的延迟只表示“最早何时可以运行回调”，实际执行还要等宿主调度；事件循环忙碌时会更晚。若要验证调用顺序，可在调用 `sleep(1)` 后立即打一条日志，再在 `.then` 里打另一条：同步日志先出现，Promise 回调稍后出现。

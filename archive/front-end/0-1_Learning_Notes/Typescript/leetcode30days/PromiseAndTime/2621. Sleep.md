# LeetCode 2621：如何把计时器延迟包装成 Promise？

原题要求 `sleep(millis)` 返回一个 Promise，该 Promise 约 `millis` 毫秒后兑现，兑现值不限。这里用计时器作实现，并在计时器回调中调用无参数 `resolve()`，所以本实现实际兑现 `undefined`。原题示例中的 `100`、`200` 是耗时展示，不是兑现值；例 1 在 `.then` 中用 `Date.now() - t` 计算耗时。原题允许实际耗时有小幅偏差。

实现和例子的机制解释见[回调、Promise 与 async 函数怎样组合异步工作？](../../../../../../frontend/javascript/asynchronous-javascript.md#怎样把定时器延迟包装成-promise)。该章用代码说明计时器回调如何调用 resolve，并与超时竞速、取消待执行定时器作区分。

## 原题与输入约束

**Difficulty:** Easy

Given a positive integer `millis`, write an asynchronous function that sleeps for `millis` milliseconds. It can resolve any value.

**Example 1:**

```
Input: millis = 100
Output: 100
Explanation: It should return a promise that resolves after 100ms.
let t = Date.now();
sleep(100).then(() => {
    console.log(Date.now() - t); // 100
});
```

**Example 2:**

```
Input: millis = 200
Output: 200
Explanation: It should return a promise that resolves after 200ms.
```

**Constraints:**

- 1 <= `millis` <= 1000

## Solution

```ts
function sleep(millis: number): Promise<void> {
  return new Promise((resolve) => {
    setTimeout(resolve, millis);
  });
}

/**
 * let t = Date.now()
 * sleep(100).then(() => console.log(Date.now() - t)) // 100
 */
```

## 调用顺序

| 时点 | 发生什么 | Promise 状态 |
| --- | --- | --- |
| 调用 `sleep(millis)` 时 | `new Promise` 的执行器同步运行，`setTimeout` 登记计时器，然后 `sleep` 立即返回 Promise。 | `pending` |
| 等待期间 | 调用方可以继续执行，也可以先登记 `.then` 回调；它还没有执行。 | `pending` |
| 计时器回调运行时 | `setTimeout` 调用 `resolve()`。没有传入兑现值，所以 Promise 以 `undefined` 成功兑现。 | 已兑现（fulfilled） |
| 计时器回调结束后 | 已登记的 `.then` 回调作为微任务（microtask）运行。 | 已兑现 |

`setTimeout` 让回调在指定延迟结束后具备运行条件，实际执行仍需等宿主调度；事件循环忙碌时会更晚。若要验证调用顺序，可在调用 `sleep(1)` 后立即记录一条日志，再在 `.then` 中记录另一条：同步日志先出现，Promise 回调稍后出现。原题也明确允许实际延迟有小幅偏差。

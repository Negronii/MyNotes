# LeetCode 2637：如何让操作与超时竞速？

`timeLimit(fn, t)` 返回带超时限制的函数 `limited`；调用 `limited(...inputs)` 时才传入实参并得到该次调用的包装 Promise。例子覆盖 100 ms 操作在 50 ms 限时下被拒绝、150 ms 限时下正常返回、多个参数相加，以及 `async` 函数体抛错。例 4 中的 `throw` 会让 `async` 函数返回被拒绝的 Promise，并不是同步异常逃出函数；原约束为参数 0–10 项、`t` 为 0–1000 ms，且 `fn` 返回 Promise。

这些输入情形的机制解释见[回调、Promise 与 async 函数怎样组合异步工作？](../../../../../../frontend/javascript/asynchronous-javascript.md#%E6%80%8E%E6%A0%B7%E8%AE%A9%E5%BC%82%E6%AD%A5%E6%93%8D%E4%BD%9C%E4%B8%8E%E8%AE%A1%E6%97%B6%E5%99%A8%E7%AB%9E%E9%80%9F%EF%BC%9F)。包装函数保留 `this` 与实参，并在工作结束时清除尚未触发的计时器。若超时先发生，调用方的 Promise 会拒绝，但 `fn` 仍继续运行；同步代码也不能被计时器中断。

## 原题与输入约束

Given an asynchronous function `fn` and a time `t` in milliseconds, return a new **time limited** version of the input function. `fn` takes arguments provided to the **time limited** function.

The **time limited** function should follow these rules:

- If the `fn` completes within the time limit of `t` milliseconds, the **time limited** function should resolve with the result.
- If the execution of the `fn` exceeds the time limit, the **time limited** function should reject with the string `"Time Limit Exceeded"`.

**Example 1:**

```javascript
Input:
fn = async (n) => {
    await new Promise(res => setTimeout(res, 100));
    return n * n;
}
inputs = [5]
t = 50
Output: {"rejected":"Time Limit Exceeded","time":50}
Explanation:
const limited = timeLimit(fn, t)
const start = performance.now()
let result;
try {
    const res = await limited(...inputs)
    result = {"resolved": res, "time": Math.floor(performance.now() - start)};
} catch (err) {
    result = {"rejected": err, "time": Math.floor(performance.now() - start)};
}
console.log(result) // Output
```

The provided function is set to resolve after 100ms. However, the time limit is set to 50ms. It is rejected at t=50ms because the time limit was reached.

**Example 2:**

```javascript
Input:
fn = async (n) => {
    await new Promise(res => setTimeout(res, 100));
    return n * n;
}
inputs = [5]
t = 150
Output: {"resolved":25,"time":100}
Explanation:
The function resolved 5 * 5 = 25 at t=100ms. The time limit is never reached.
```

**Example 3:**

```javascript
Input:
fn = async (a, b) => {
    await new Promise(res => setTimeout(res, 120));
    return a + b;
}
inputs = [5,10]
t = 150
Output: {"resolved":15,"time":120}
Explanation:
The function resolved 5 + 10 = 15 at t=120ms. The time limit is never reached.
```

**Example 4:**

```javascript
Input:
fn = async () => {
    throw "Error";
}
inputs = []
t = 1000
Output: {"rejected":"Error","time":0}
Explanation:
The function immediately throws an error.
```

**Constraints:**

- 0 <= `inputs.length` <= 10
- 0 <= `t` <= 1000
- `fn` returns a promise

## Solution

```ts
function timeLimit<This, Args extends unknown[], Result>(
  fn: (this: This, ...args: Args) => Promise<Result>,
  t: number
): (this: This, ...args: Args) => Promise<Result> {
  return function (this: This, ...args: Args) {
    return new Promise<Result>((resolve, reject) => {
      const timeoutId = setTimeout(() => reject("Time Limit Exceeded"), t);
      const clearTimer = () => clearTimeout(timeoutId);

      try {
        Promise.resolve(fn.apply(this, args)).then(
          (value) => {
            clearTimer();
            resolve(value);
          },
          (error) => {
            clearTimer();
            reject(error);
          }
        );
      } catch (error) {
        clearTimer();
        reject(error);
      }
    });
  };
}

/**
 * const limited = timeLimit((t) => new Promise(res => setTimeout(res, t)), 100);
 * limited(150).catch(console.log) // "Time Limit Exceeded" at t=100ms
 */
```

## 调用中谁先结算

调用 `limited(...args)` 时，包装函数创建 Promise、登记超时计时器，再同步调用 `fn.apply(this, args)`。如果 `fn` 返回的 Promise 已结算，且它对应的 `.then` 处理器先于超时计时器回调运行，该处理器先清除计时器，再把成功值或拒绝原因转交给包装 Promise。即使 `t = 0`，若 `fn` 直接返回一个已兑现的 Promise，其处理器微任务仍可先于计时器任务运行。

如果超时回调先运行，它以 `"Time Limit Exceeded"` 拒绝包装 Promise；底层异步工作仍继续，后来运行的 `.then` 处理器无法改写已经结算的包装 Promise。普通函数若在返回 Promise 前同步抛错，由 `try/catch` 清除计时器并拒绝包装 Promise；原题例 4 的 `async` 抛错则走 `.then` 的拒绝处理器。

| 原题例 | 先发生的事件 | 调用方得到的结果 |
| --- | --- | --- |
| 1：工作约 100 ms，`t = 50` | 超时计时器先调用 `reject`。底层工作仍可在约 100 ms 后完成。 | 包装 Promise 拒绝为 `"Time Limit Exceeded"`。 |
| 2：工作约 100 ms，`t = 150` | 工作兑现 `25`，处理器清除 150 ms 的计时器。 | 包装 Promise 兑现为 `25`。 |
| 3：工作约 120 ms，`t = 150` | 工作兑现 `15`，处理器清除计时器。 | 包装 Promise 兑现为 `15`。 |
| 4：`async` 函数体立即抛出 `"Error"`，`t = 1000` | `async` 调用返回一个立即拒绝的 Promise；拒绝处理器转交原因并清除计时器。 | 包装 Promise 拒绝为 `"Error"`。 |

题面 `Output` 中的 JSON 是测试代码捕获结果并附上耗时后的展示格式；实际是 `limited(...inputs)` 返回的 Promise 兑现原始值（如 `25`），或以拒绝原因（如字符串 `"Time Limit Exceeded"`）拒绝。

`t` 是通过计时器任务检查的限时，不是可以抢占 JavaScript 的硬截止时间。计时器到期后仍要等当前同步代码结束才有机会运行；若 `fn` 同步阻塞超过 `t`，然后返回一个已兑现 Promise，其 `.then` 微任务可能先于已过期的计时器任务执行。这里描述的是宿主事件循环的调度顺序，不是超时能暂停或终止同步代码。

# 研究里的自动改进方法，哪些证据能借到工程里？

[选择改动对象](choosing-what-to-change.md)给出了一条工程流水线：产生候选、筛查、开发迭代、冻结、独立验收、人工核验、门槛决定去留。研究界有很多“自动改进”系统，会自动产生候选、给候选排序、改写技能或脚手架、刷新训练任务。本支线按证据强度梳理这些研究：每种方法用一句话说清机制，再说它能给流水线借来什么、证据边界在哪里。

下面的论文结果只适用于各自写明的任务、模型、预算和基线；其中的百分点、费用和比例都不是本地实测，彼此也不能合并成一个“自动改进的平均收益”。很多是 2026 年的 v1 预印本。这条限定这里说一次，后文只保留会改变结论的限定。

## 骨架：按证据来源分级

判断一项研究能借什么，先看它的结论建立在哪种证据上。RSI-Anything v1 按信息来源把候选证据分成四类。它们不是固定的质量排序，也不要求每个领域用同一套标准：

| 级别 | 代表什么 | 还需要什么外部检查 |
|---|---|---|
| E0：确定性规则或程序检查 | verifier (可执行验证器)、单元测试、形式化条件；在锁定测试上执行候选得到的判定也属此类 | 检查器是否覆盖真实任务，会不会被候选投机利用 |
| E1：学习型预测或 rollout | 模型对结果或未来状态的估计；这里的 rollout 是模拟未来，不是实际执行 | 预测不是结果，选中的候选仍要实测 |
| E2：模拟器或高保真模型 | 候选在模拟环境里的实际状态转移与测量，是该模拟环境范围内的结果 | 模拟与实际环境有差异时要外部校验 |
| E3：外部测量 | 真实任务、硬件、用户或实验系统中的观察 | 仍要控制变量、预算和测量噪声 |

对诊断助手来说：行号存在、schema 合法是 E0；“这个提示词可能更好”的模型打分是 E1；在 200 道独立题上按契约判分是 E3。只有 E1 的候选还没有结果证据。

RSI-Anything 还把数据分成三份：update data 用来构造候选，gate data 用来决定保留哪个版本，held-out audit set (留出审计集) 只用于最终报告。系统里有两个可改进的组件：提出候选的 policy (策略)，和预测候选结果的 world model (世界模型，即预测器)。逐个比较时，每次只替换一项，另一项用当前版本；单组件门禁失败就保留该组件的当前版本。至少一项改变后，再把新组合与当前的“策略 + 预测器”组合配对比较，失败则保留原组合。这和[独立验收](holdout-acceptance-and-paired-statistics.md)的划分一致：gate data 参与了选择，是开发证据；只有审计集对应独立验收。

> [!info]- RSI-Anything 的实验结果（各任务互相独立，不可合并）
> | 任务与对照 | 论文报告的观察 | 解读边界 |
> |---|---|---|
> | CodeContests：静态 verifier 排序 / 固定 world model / 允许预测器适应 | 200 题、3 个随机种子、最多 3 轮反馈下，隐藏测试全部通过率分别为 26.3%、29.2%、31.2%；平均每题调用在线测试套件约 3.71–3.72 次 | 特定程序合成设置下的排序与隐藏测试验收；调用次数指测试套件，不是模型或工具 API 调用 |
> | GUI 勾选任务 | 从 51% 到最终 99%，平均动作数由 5.30 降至 3.21；一个适应中的中间版本动作更少，却有 21 个 episode 错误提交 | 动作效率不是正确率；最终任务结果优先于过程看起来简洁 |
> | 实验室规划（F200 Level-2，200 题） | 五个保留的 policy 版本 Final Score 从 21.80% 升至 46.01%，端点差 24.21 个百分点；分数结合动作序列相似度与参数准确度 | 特定协议规划任务上的合成评分，不与其他任务共用单位或基线 |
> | LC–MS 反应选择 | 同一流程下 40 次实验后的平均最佳实测产率：96.15%，Bayesian optimization (贝叶斯优化) 为 82.16% | 受限实验与具体对照下的最佳观察值 |

## 候选从哪来

### 从执行轨迹反思改提示词：GEPA-Curator

**机制。** GEPA 让模型反思执行轨迹，据此逐版改写提示词。GEPA-Curator 在此基础上加了一个任务筛选器（Curator）：执行 Agent 跑题产出轨迹，评估器记录结果；Curator 挑出值得再试的任务，暂时跳过反复稳定成功、受环境限制或评分不稳定的任务；某道训练任务失败时，Curator 在同一任务的历史里找一条结果较一致的成功轨迹，交给反思器（Reflector）对照，找不到就不提供。Curator 和 Reflector 由同一个优化模型担任；Curator 不决定最终保留哪个提示词，也不更新权重。

**能借什么。** 同一开发任务既有可靠的成功轨迹也有失败轨迹时，候选作者可以比较两次运行是否看到了同一行证据、各自怎样判读。只有失败记录时，不要编造成功对照。历史成功能否当参照，取决于它怎样被判定：任务状态由程序记录的，可以核对当时的实际结果；只靠模型评审的，两次一致的判决也可能带着同一种偏差。

**证据边界。** 挑选更有信息量的任务本身有成本。以 WebArena 的四个网站为例，论文估算 GEPA 一次训练加验证约 594 美元，加上 Curator 的效率优化版本约 777 美元，都未计最终测试和网站托管。另外，论文的选版方式是定期在验证集上评分、最后取验证分最高的一版；验证集反复参与选版，按本书的划分属于开发证据，只有最终留出测试对应独立验收。

### 让可执行评估器筛程序：FunSearch 与 AlphaEvolve

**机制。** FunSearch 把预训练模型和系统评估器组成进化搜索：模型提出程序，评估器打分，好的程序留下供后续变异。AlphaEvolve 的程序库兼顾高分与多样性；提示采样器选一个待改的父程序，并可加入其他高分程序作灵感；模型生成的代码差分应用到父程序后，候选先过小规模检查，再按由易到难的评估级联逐层测试，达到前序门槛才进入更重的测试，结果写回程序库供后续采样。

**能借什么。** 评估级联：先用廉价检查淘汰明显违约的候选，再把昂贵评估留给通过的。诊断助手的行号、结构和权限检查就是廉价的第一层；语义是否正确仍要靠独立任务标签。权限、正确性这类不能被性能分补偿的硬约束，要作为独立淘汰门，而不是加权进总分。

**证据边界。** 这类搜索要求目标能由自动评估器检验。结果也有很大运气成分：FunSearch 在 8 维 cap-set 问题上找到规模 512 的构造，只在 140 次实验中的 4 次出现。搜索预算怎样设、何时停，见[选择改动对象](choosing-what-to-change.md)的预算契约部分。

## 用预测省实验，结果必须闭环

**机制。** RSI-Anything 的 world model 根据候选动作预测下一状态，再由领域 readout (读出函数) 把预测转成任务结果或其概率分布，据此排列候选的实测优先级。预测只决定先测哪个：程序题仍要在锁定测试上运行实际候选，模拟题的结果只支持其环境范围内的判断，线上任务要观察实际工作流。

**能借什么。** 实验昂贵时，用预测给候选排队，把预算先花在最有希望的候选上。前提是先固定任务契约：输入输出、限制、预算、程序检查器、成功定义和停止条件，并记录每个候选的证据来自哪一级。

**证据边界。** 模型自评分或世界模型预测再高，也只能用来排序待测候选，不能作为发布结论。

> [!example] 文档问答的工具次数（合成示例）
> 当前文档问答工作流最多调用检索工具 4 次，候选把上限设为 2 次。这只说明调用次数的上界少了两次；如果多数请求第一次就找到答案，平均费用不会少两次调用。“长尾成本可能下降”可以作为一条 E1 级的预测，用来安排实验优先级。两种配置仍要在同一批问题上实际运行，比较真实费用、证据支持和权限结果；少调用却漏掉关键条款，就不能因为上限低而接受。

> [!example] build 73 的程序检查（工程推演）
> 解析器可以保留原日志的时间戳和重试状态，检查连接是否在后续尝试中恢复，并验证行号引用；不要因为最早出现 `ERROR` 就认定它是最终阻塞失败。这些检查提供 E0 证据，可以廉价淘汰候选。它们确认不了第 20、21 行来自同一轮就绪探测，那需要同一构建步骤的探针事件和时间戳关联。模型给候选的排序仍是 E1；候选要在固定任务上实际运行并达到门槛。这个设计不是 RSI-Anything 验证过的预测器。

## 反例：没有任务反馈的自我改写

**机制。** 让模型反复重写给定的技能说明，不给它任何任务结果作反馈。

**能借什么。** 一项覆盖六个模型、三个基准的研究提供了反例：SkillsBench 技能经过 30 轮无反馈重写后，平均通过率下降 14.6 个百分点。另一种做法 SkillDiff 保留技能原文，只标出十份模型自写技能（论文称为 prior，按主题生成的操作性参照）都没覆盖的内容，在同批 SkillsBench 评估中平均提高 4.8 个百分点。对诊断助手，提示词的反复改写只能提出候选；保留与否由来源核对和新任务结果决定。

**证据边界。** 结论限于该研究的模型、基准和重写设置；它说明真实任务反馈是检查自我改写的必要信号，不说明任何改写都会退化。

## 训练任务池什么时候刷新

这类研究改的是训练用的题目，不是提示词，所以它不属于候选 B 那种改动，而是[训练推理能力](reward-based-reasoning-training.md)时的一个调度问题。

**机制。** A-RSI v1 研究多模态模型在没有人工标注时的自我改进：模型在预先生成的任务池上做强化学习，论文用训练日志决定何时换池。它读取的信号记为 `U`。每道题采样 8 个回答，用每个回答的总奖励减去同题 8 个回答的平均奖励，再按组内尺度归一化，得到 advantage（优势）。只要一道题的 8 个优势不全为零，它就给 `U` 加 1。例如奖励为 `[1,0,0,0,0,0,0,0]` 时，均值 0.125，优势不全为零，计入；8 个奖励全相同时优势全为零，不计入。所以 `U` 统计的是“还能提供学习信号的题数”，不是奖励总和或答对题数；格式奖励和停止奖励也会影响它。

换池规则：同一池已累计至少三个通过训练健康检查的连续窗口后，比较当前窗口与两个窗口之前；`U` 降到先前值的 85% 或以下，或记录的正确率上升至少 10 个百分点，就换池。在 Qwen3-VL-8B-Instruct 设置里，`U` 从 239 降到 195（195/239≈0.816），触发换到一个 400 题的新池；同期正确率只升了 7 个百分点，没触发另一条件。换池后权重继续训练。

**能借什么。** 一个可借的思路：用训练日志里“还有多少题能提供学习信号”来决定刷新时机，而不是看模型自评。论文发现四个模型对“自己会不会答错”的自评 AUC 约 0.50，几乎不能排序哪些题会答错，所以控制器读训练日志。

**证据边界。** 在训练进度相同的第六个窗口，新池方案的 Macro11（11 个基准准确率的等权平均）为 60.40%，继续旧池为 58.35%，差 2.05 个百分点；但每个策略臂只训练一次，且混在一起的有换题、刷新时机、池规模从 500 变 400，作者还指出完成/截断的变化参与了得分差异。没有固定三窗换题的随机刷新对照，不能断言自适应时机更好。这个信号负责训练时机，不是发布门禁；阈值依赖论文的奖励与训练设置，不能照搬。

## 改进整个脚手架

**机制。** 候选 B 只改了 harness 里的一条提示词；Harness² 研究自动、反复地改进整个 harness。它固定模型权重，每项任务都从基础脚手架 `H0` 起步，开放八种运行时组件：system prompt、guardrails (防护规则)、memory (记忆)、skills (技能)、tool guidance (工具指引)、scripts (脚本)、subagents (子智能体) 和 middleware (中间件)。流程是 Propose–Probe–Compose：提出编辑；在配对条件下实际执行候选（Probe），比较行为差异；只组合有对照证据支持的变化。可复用的组件或经验存入改进后的脚手架，供后续任务检索；经验怎样被选进当前上下文，见[Agent 记忆的设计与评估](../context/agent-memory-design-and-evaluation.md)。

**能借什么。** 一次只组合有配对对照支持的变化，这与“一次只改一层”是同一原则在多组件上的扩展。生产中给 Probe 限制外部写入权限和费用，否则实验候选可能造成副作用。

**证据边界。** Probe 是一次实际运行，仍受模型方差、共享评审和工具状态影响。在线编辑阶段没有每题真值或可靠 verifier，行为差异只能提示编辑效果，不能认证输出正确；论文在实验后另用 WorkBuddy-Bench、JobBench 和 Harvey Legal Agent Benchmark 评分。四组执行器–脚手架配置中，各基准最高的单步结果为 WorkBuddy-Bench 平均得分 +11.5 分、JobBench +4.5 分、Harvey LAB Partial 评分条目通过率 +11.8 个百分点；前两者是分数点、只有最后一项是比例，都是特定模型和基线下的结果。论文也讨论了额外执行成本、行为波动，以及编辑器与被编辑系统共用模型时的偏差。

**权重分支：Harness-S。** Harness-S 针对 `H0` 上 8 次采样全部失败的任务，改用兄弟脚手架生成“救援”轨迹，训练共享策略的权重。比较时要有按同样规则从 `H0` 重采 8 次的基线；训练结束后回到原始 `H0`，用含新实例的留出任务验收。论文在 `H0` 留出任务和少量外部 harness 上观察到有限迁移，不证明任意 prompt、tool 或 memory 修改都能变成通用能力。

> [!info]- Harness-S 的采样、路由与成本细节
> 离线先从 `H0` 生成兄弟脚手架池，针对失败修改提示词、技能、上下文、记忆、钩子或工具视图；局部测试同时检查原本成功的任务，观察回归，再按变体覆盖的验证任务选择编辑父代。训练开始后固定有效变体池。
>
> 每题先由当前策略在 `H0` 采样 8 条；至少一条成功就保留原 8 条。只有 8 条全失败时，主配置才路由到 8 个不同 sibling，各从任务初始状态运行 1 条，以救援轨迹组替换失败组。论文用二元奖励；本地若用分档奖励，不能只按成功标签推断组内奖励差异是否恢复。路由依据 `H0` 与 sibling 的配对验证轨迹、检查点行为档案、任务描述和相似任务结果汇总后的 LLM 排名。
>
> 更新时在同一脚手架和生成上下文下比较新旧策略对策略生成词元的概率；辅助指令和工具观察是条件上下文，不进入训练损失。H0-rescue 对照也在全失败时从 `H0` 重采 8 条替换旧组，两组都做 40 次更新；但救援触发次数不同，AppWorld Qwen3.5-4B 上 H0-rescue 为 3,616 rollouts / 97.77 GPU 小时，Harness-S 为 3,032 / 67.19，不能称为总算力匹配。

> [!info] 实例：子 Agent 是否并回主循环（Anthropic，2026-10-22）
> Anthropic 的实践文章建议一次只测试合并一个 subagent，比较合并前后的端到端结果并重复运行。它是特定提供方的工程经验，不是“都该移除子 Agent”的定律；结构选择仍要测量。

## 复用记录的三种口径

**机制。** GitSwarm 让多个 worker 在一个持久、可分支的共享产物仓库里工作，观察它们怎样引用、访问和组合前序工作。它用三种记录描述“复用”，回答的是不同问题：

1. **声明依赖**：worker 在提交里把已有贡献列为 Git parent 或 `informed_by` 来源。这是可追溯的声明，不证明内容被用过。
2. **轨迹使用**：执行轨迹里的 accessed (已访问) 只说明读、搜、比较或打开过；actively reused (主动复用) 要求只读材料实际影响了后续贡献，可执行产物被运行、导入、改编或作为另一计算的输入，自愿产物包还要引用提供者。只打开文件不算主动复用。
3. **winner-linked ancestry (胜者关联祖先链)**：最终选中的提交沿 Git parent 和 `informed_by` 边能到达的贡献占比。它说明声明图上的祖先关系，不证明内容被最终代码继承。

> [!example] 一个脚本的三种记录
> worker A 把 `probe.sh` 存入共享仓库。worker B 只打开脚本，是“访问”。B 实际运行它，并据结果改写了自己的补丁，才有轨迹证据说明“主动复用”。最后选中的补丁若通过 parent 或 `informed_by` 追溯到 B 的贡献，那项贡献就在“胜者关联祖先链”上。反过来，声明引用前序贡献，也不证明内容被读过。

**能借什么。** 评估多 Agent 协作或经验复用时，把“声明了”“用了”“最终解里有它”分开计数，各用各的分母。

**证据边界。** 这些比例只说明行为在特定基准和仓库设置中被观察到；复用本身不证明导致了分数提升。具体分母和数字见章末来源。

## 搜索停滞时重启

**机制。** *Scaling Discovery Requires Forgetting* 研究外部评分的开放搜索：停滞时保留最佳候选，清除会话和候选历史后重启。

在 AHC014（一道 AtCoder 启发式编程赛题）的对照里，4 个 agent 的团队从同一个停滞状态出发，分别继续运行或重启；每臂由 4 个 agent 各追加 30 个候选提案，即每次每臂 120 个提案，重复 3 次。收益按“最佳新候选相对起始最佳分”计：

| 实验臂 | 收益（3 次均值 ± 标准差） | 每次费用 |
|---|---|---|
| 继续运行 | +1.4% ± 1.3% | 24.67 美元 |
| 重启 | +9.2% ± 6.9% | 15.32 美元 |

两臂均值相差 7.8 个百分点，费用相差 9.35 美元/次。

**能借什么。** 在受限搜索中，可以把“重启”作为一个待测选项。事先写下保留哪个最佳候选、清除哪些状态、实验预算和继续条件，再从相同起点、按真实成本比较两种方案。

**证据边界。** 比较按提案数匹配，不是按费用、token 或时长匹配；论文没有给出三次重复的配对差分布。重启同时清除了会话与候选历史，不能把差异归因于某一种记忆源，也不能据此定出固定的重置周期。

## 能借到流水线里的部分

| 研究 | 主要证据级别 | 借到流水线的哪一步 |
|---|---|---|
| RSI-Anything | E0–E3 分级，数据三分 | 记录每个候选的证据来自哪一级；gate 与 audit 分开 |
| GEPA-Curator | 验证集选版（开发证据） | 产生候选：对照成功与失败轨迹；记录筛题与反思的全部开销 |
| FunSearch / AlphaEvolve | E0 程序评估 | 筛查：廉价检查在前、昂贵评估在后；硬约束单独淘汰 |
| world model 预测 | E1 | 安排实测顺序；不进入发布结论 |
| SkillsBench / SkillDiff | 基准测量 | 改写必须有任务反馈 |
| A-RSI | 训练日志信号 | 训练调度，不是发布门禁；不依赖模型自评 |
| Harness² / Harness-S | 外部基准 | 多组件只组合有配对对照的变化；Probe 限权限与费用 |
| GitSwarm | 轨迹与声明图计数 | 复用分三种口径统计 |
| AHC014 重启 | 小样本对照 | 停滞时把重启作为待测选项 |

这些方法都只能改进流水线的“产生候选”和“筛查”两段。候选最终能否留下，仍由冻结后的独立任务、人工核验和预设门槛决定，见[选择改动对象](choosing-what-to-change.md)。

# AI 应用怎样选择部署方式，并逐步上线或回滚？

把候选的任务评测结果与真实流量、数据边界、峰值和运维能力放在同一张表里，判断是否已具备部署资格，再制定渐进发布和 rollback（回滚）条件。托管推理可减少自营服务工作，自托管可增加模型与运行位置的控制，但也把容量、更新、安全和 on-call（值班响应）责任转给团队；端侧与混合架构对应特定设备或数据边界。部署标签本身不能证明成本更低、隐私更好或服务更快。

本篇承接[模型选择](../foundations/model-selection-and-ecosystem.md)输出的候选与任务契约，以及[时延和成本测量](ai-latency-and-cost-optimization.md)提供的测量口径与待验证负载。它检查当前证据是否足以选择部署方式，并把模型、API、提示词和应用版本一起纳入验证、上线与回退。

## 先筛掉不满足数据、服务和团队硬约束的方案

| 部署方式 | 适合条件 | 成本、约束与责任 |
|---|---|---|
| **托管 API** | 托管推理、快速迭代符合任务与数据要求。 | 按具体合同与配置检查处理地区、保留行为、功能、限流、可用性、生命周期和用量价格；还要监控依赖供应商的变更。 |
| **自托管** | 控制服务位置、模型版本或基础设施有明确价值，团队有能力运营。 | 自己承担模型许可、硬件容量、服务引擎、扩缩容、安全更新、监控、值班响应和模型升级。 |
| **端侧** | 离线运行、设备本地响应或设备级数据处理是需求。 | 设备算力、内存、电量、机型覆盖、升级机制和模型体积约束质量与可用能力。 |
| **混合部署** | 不同请求类确实需要不同的数据或运行边界。 | routing（请求路由）、策略一致性、回退、故障处理和重复运维带来额外复杂度。 |

自托管的权重许可要按具体模型与用途核验；open-weight（开放权重）不自动授予所有商业用途，也不表示整个训练数据、代码和系统都开源。对托管服务，“云端”也不能替代查看实际合同、区域、保留设置、日志与功能例外。隐私结论来自具体数据流与控制，而不是部署名词。

## 如何估算总拥有成本（total cost of ownership，TCO）？

不要只把 API token（词元）费用与 GPU（图形处理器）租赁价相减。可比较的范围至少包括：

$$
\begin{aligned}
\text{总成本}={}&\text{推理运行成本}+\text{检索与额外存储}\\
&+\text{工程与运维}+\text{评估与风险控制}.
\end{aligned}
$$

其中，同一次推理按实际运行路径计托管调用费或自托管计算与运行存储费用，避免重复计算；混合流程若先后或并行调用多处服务，应逐次合计。检索索引和业务数据存储另列。完整 TCO 还要估算低谷、峰值、冗余、闲置、扩容、支持、更新、故障响应、质量差异和人工复核。明确成本单位是每请求、每成功报告、每用户还是每月，并用时延目标约束容量方案。[时延与成本测量](ai-latency-and-cost-optimization.md)中的 \$2 / \$1 / \$8 教学费率不是报价，真实 API 价格和缓存/区域规则要查部署时的官方价格页。自托管容量需在目标硬件、模型精度、输入/输出长度、并发和批处理条件下回放；平均 token 量不能证明峰值显存足够。

## 月报助手现在能作出什么部署决定？

> [!example] 案例延续：候选进入部署核验，尚未授权试点
> 月报助手目前只有公开合成输入，目标是每月交付 10,000 份通过内容与结构验收的成功报告；这不是请求数。选型预筛的教学设定是候选甲在 200 个合成开发样例上内容通过 198/200、结构有效 200/200；常规负载 p95（第 95 百分位）=1.7 秒和模型 API 直接费 $0.007/成功报告也只是筛选假设，不是运行结果或峰值实测。该直接费按所有模型尝试费用（含失败和重试）除以内容与结构同时通过的报告数，$0.01/成功报告只约束 API 直接费。
>
> 假设每份成功报告的托管 API 直接费为 $0.007，则 10,000 份 × $0.007 = $70/月；$0.01 上限对应 $100/月。这只是一项可变直接费假设，不含数据服务、人工复核、固定/共享基础设施、工程、评估与运维，也不是当前项目的报价。用同一个质量合格报告单位比较人工工作流与 AI 的端到端成本，并把固定费用按月只计一次，才可估算净收益；本例没有人工基线、单位价值或完整 TCO，因此不能声称投资回报率（return on investment，ROI）为正，也不能据此选定托管、自托管或混合方案。
>
> 候选甲只进入下一步核验。可继续公开合成数据的本地/mock准备；但真实 API 提供方和确切端点/模型、凭据、数据使用条件、费用约束及能监控并停止测试的责任人均未指定，因此现在不调用真实端点。真实数据路径、生产权限、监控和值班/故障回退责任、独立最终验收集和代表性峰值负载也未验证，所以不接真实生产载荷、不做线上影子或小流量试点。若使用托管 API，$0.01 直接费用上限只适用于该托管调用路径；自托管等路径另按完整 TCO 比较。若自托管能力和责任团队仍未知，也不能把它假设成可用或不可用的基线。

如果需要自托管，先用[GPU 推理容量](llm-serving-and-kv-cache.md)估计每个活跃序列的 KV 内存和批处理容量，再回放代表性峰值负载并检查满足时延目标的吞吐量。若当前没测过同一工作负载，部署选型就仍未定，不能只凭账单或公开基准做盈亏平衡结论。

## 怎样验收候选、逐步上线并保留回滚能力？

模型发布不是只换一个二进制。将以下配置作为可追溯、可比较的同一版本组合：服务商与 API 端点/SDK 版本；托管模型 ID/修订，或自托管权重摘要、精度与推理运行时；提示词、工具定义、输出 schema 和推理参数；数据/检索/权限与区域配置；应用服务镜像；评估数据版本、评分规则和门槛。用不可变的 release ID（发布标识）记录组合。遇到服务侧模型更新时，记录响应中实际调用到的模型标识；若供应商不提供固定快照，就把每次重要变化当成新候选。

本例需要区分测试请求与生产请求：本地 mock 只验证应用处理，不证明目标模型输出。公开合成数据发给真实 API 端点虽不是生产流量，仍需端点/模型、凭据、数据使用许可和费用约束，并由能监控、停止测试的责任人执行；它本身不需要生产 on-call。真实用户请求或生产载荷（包括影子）则须先有生产授权、线上监控、值班、故障处置与回滚责任。完整阶段与输出见下表。

| 阶段 | 验证或运行内容 | 进入下一阶段的条件 |
|---|---|---|
| 本地 mock 与合成准备 | 用公开合成输入检查应用对正常、拒答、不完整和错误响应的处理。 | 可先开始；不碰真实数据或实际服务端点。mock 不能替代候选模型输出。 |
| 真实端点合成测试 | 用公开合成请求检查准确 API/模型/SDK 的能力、schema、限流和计费。 | 调用前确认端点与模型可用、凭据有效、服务条款允许该数据用途和测试额度；指定能监控并停止测试的责任人。无需因此宣称生产 on-call 已就绪。 |
| 冻结候选的独立最终验收 | 在未参与提示词/候选调优的独立数据集上，让准确冻结组合生成实际输出，再评内容与结构；记录两项比例与交集。mock 输出不能作为模型验收。 | 若使用真实数据先通过相关数据授权；生成输出所需的真实端点请求先满足上一行。独立验收必须在任何生产影子或试点前通过。本例教学门槛为内容至少 99%、结构有效率 100%；最终集未指定，当前不能称通过。 |
| 上线前容量回放 | 在目标硬件/运行时/端点组合上回放代表性峰值负载、目标长度、并发和批处理，记录容量与端到端 p95。 | 测试端点调用仍按合成测试条件管理；如果使用真实数据，先有授权。该回放是上线前容量证据，不是上线后的真实月末表现。 |
| 生产影子或受控小流量 | 影子仅在允许的数据策略下复制真实载荷，且不展示结果或触发写入；小流量让少量获准用户实际使用。 | 两者都要求生产数据/端点授权、监控、值班、故障和回滚责任就绪，并且独立验收与容量回放通过。影子可跳过；若执行失败，停在人工流程，修订复验后才可考虑小流量。 |
| 扩至全面生产 | 在获准的小流量后，测实际代表性月末窗口中的内容、结构、p95、失败/重试、限流与费用。 | 真实月末表现和完整 TCO 门槛都必须通过。TCO 按相同成功报告单位、完整成本与预算比较；未测或未定不扩量，失败则停止候选并回退。 |

任一组件变化即冻结为新组合，并按受影响的门槛复核：

| 变化 | 重查内容 |
|---|---|
| API 提供方、端点、模型或 SDK | 测试凭据、数据用途和费用条件；端点/结构兼容。若可能影响候选输出，重跑受影响的任务验收；若请求路径或负载改变，重跑容量回放。 |
| 提示词、工具定义、schema、应用代码或业务规则 | 工具/API 与拒答、不完整、错误响应兼容；若可能影响候选输出，使用未参与调优的验收样本重验内容与结构。 |
| 数据源、租户权限、保留或区域配置 | 数据契约与访问授权；若格式、语义或分布变化可能影响任务输出，用代表性输入重验内容。未授权前不发真实数据。 |
| 精度、推理运行时、硬件、输入/输出长度、并发或批处理 | 重跑目标环境容量回放；若该变化可能影响候选输出，也重跑受影响的任务验收。 |
| 生产监控、值班责任、停止或回滚流程 | 重查生产流量准入及恢复责任；关键责任未明确前不接真实用户/生产载荷。 |

| 检查项 | 案例门槛 | 触发后的动作 |
|---|---|---|
| 跨租户或越权数据泄漏 | 零容忍 | 立即停止候选请求，转人工月报并调查 |
| 输出结构 | 审核窗口内所有应输出结构化报告的候选结果中，100% 结构有效；应用必须拦截无效结果 | 停止候选流量，修复并重跑兼容性和离线门禁；拦截不能代替结构通过率监控 |
| 内容（严格的变化率筛选、变化额/百分比/总额、行号引用、不臆测原因） | 审核样本通过率至少 99% | 低于门槛即停止候选并退回人工流程；上述错误都计入内容失败率。若具体产品要求某类内容错误零容忍，需在上线前把该项另设硬门槛 |
| 后端完成 p95 | 约定观测窗口内不高于 2 秒；上线前容量回放通过，全面生产前通过真实代表性月末窗口 | 回放失败不启动生产试点；实际时延超限时停止扩量并退回人工或上一个可用版本 |
| 托管 API 直接费用 | 仅托管调用路径：每份成功报告不高于 $0.01；所有尝试费用（含失败和重试）÷ 内容与结构同时通过的报告数 | 超额就暂停托管候选；这是试点调用费保护，不替代部署方式间的完整 TCO 比较 |
| 完整 TCO | 全面生产前设定统一预算及比较口径，并按相同成功报告单位验证 | 未设定或未测出时保持已获准范围、不扩至全面生产；实际超限则停止候选并回退 |

### 失败时回到哪个检查点？

| 发现的问题 | 返回动作 |
|---|---|
| 真实端点合成测试或独立最终验收失败 | 不进生产流量；修订并冻结新组合，另留未用于调优的独立样本，重做实际输出验收。mock 通过不能替代此门槛。 |
| 测试端点、凭据、数据使用或费用条件缺失 | 暂停实际服务请求，可继续本地 mock/合成准备；补齐测试条件并指定测试责任人后再测。 |
| 生产授权、线上监控、值班/故障/回滚责任未就绪 | 不做生产数据请求、影子或小流量；解决对应生产条件后再评估准入。 |
| 上线前容量回放不达标 | 不启动生产试点；调整目标环境或负载方案，重跑容量回放及受影响的兼容/验收检查。 |
| 可选影子检查失败 | 停止复制请求、保持人工流程；调查并修订后重冻，重查相关门槛。不能绕过影子失败直接转小流量。 |
| 受控试点或扩量后触发安全、内容、结构、时延或托管 API 费用停门槛 | 停止候选新请求；切回仍可运行的上一套已验收组合，否则转人工。核对在途任务、已交付结果和外部回执。 |
| 真实月末窗口或完整 TCO 尚无测量 | 不扩大已获准范围或全面上线；先完成代表性观测和同单位 TCO 验证。若测得超限则停止候选并回退。 |

Kubernetes Deployment 可以渐进替换副本并回退 Pod 模板修订；官方文档明确回滚的是 Pod template，外部提示词、供应商模型/API 配置、数据版本和业务状态不会因此自动恢复。若用 Kubernetes，保留有明确变更记录的 Deployment 修订史并确认回退完成；其他平台也需能把流量切回一个完整、兼容的已验收版本组合。

如果生成的报告会发邮件、写入系统或以其他方式对外产生效果，切回旧版本只停止新的候选输出，不会撤回已经发送或写入的内容。按应用侧稳定的 run/report ID（运行/报告标识）查交付记录和外部回执；未完成或结果未知时先查询、对账或转人工，不要把“本地回滚成功”当成“外部效果已取消”，也不要盲目重发。确认已有错误报告交付后，用应用定义的更正/撤回流程处理，并保留原版本和回执以便审计；[生产 AI 运行架构](ai-application-architecture.md)详细说明了运行状态与未知外部副作用的恢复边界。上线后持续将任务反馈与版本关联，见[生产可观测性与反馈](ai-production-observability-and-feedback.md)。

# 新来源怎样融入知识正文

收到一篇论文、文章或相关讨论时，用这份参考决定哪些知识值得保留、证据能支持什么，以及它应进入哪个问题。读者最终看到的章节主线、示例和来源呈现遵循[写作规范](../../../../maintenance/writing-guide.md)。这是一条按证据和内容需要展开的判断路径，不要求固定表格或永久台账。

## 从原文读出可复用的知识

若输入是论文或文章，先读懂指定版本的原文，再对候选结论相关的方法、图表、实验设置和限制逐项核对。若输入是讨论或二手解读，先读懂其中的主张和来源线索，再追溯支持候选结论的一手来源并逐项核对。讨论和二手解读可以指出争议、术语或值得追问的结果，不能代替原始证据。若只能访问摘要、转述或不完整版本，就把核实范围说清楚，不把未读到的细节写成已确认事实。

从材料中挑出可能帮助读者回答问题的知识点。对每一点，确认作者具体主张什么、用什么证据支持、结果依赖哪些模型、任务、数据、基线、版本或假设。把直接观察、论文解释和自己延伸出的工程判断分开。篇幅较长时可做临时摘记，便于逐点核对；完成整合后不需要保留一份重复正文的证据台账。

一篇来源不必对应一篇笔记。只有能回答一个可复用问题的知识才进入正文，原文的目录结构和贡献清单不决定章节边界。

## 用后续一手证据判断哪些结论仍适用

围绕准备保留的知识点，查找直接回应同一问题的后续研究、当前官方文档或参考实现。优先比较任务和条件相符的证据，核对模型或版本、工作负载、对照组和指标。较新的结论若针对不同任务或配置，不足以推翻旧结果，也不能把旧结果推广到新条件。

证据类型要和待判断的问题相配。后续实验能检验经验结果在相近条件下是否成立，当前官方文档或实现能说明某个具体版本公开支持什么。代码检查说明实现路径，不能单独证明运行性能；论文或厂商报告的结果也只适用于其实际测试的设置。若结论取决于代码路径是否真实运行、结果能否复现或性能是否改善，再选择可复现的检查或测量，并记录实际核验的版本和条件。

若正文要提出影响实际选型的当前建议，进一步寻找与待决问题相符的对照结果或可复现实测，说明所测效果、成本及适用条件。若声称一种做法已在业界或真实系统中采用，需提供能够证明实际采用的来源。本地复现只能支持技术可行性或所测效果，不能单独证明业界采用。对准备写进正文的主张，只要说明支持它的后续证据或已核查的证据缺口，并交代适用条件与取舍，就可收束。只有会改变解释或决策的分歧才值得继续追查，不按来源篇数设门槛。

## 按证据决定处置

- 结论在限定条件下仍成立时，保留机制并把条件放在读者需要它的位置。
- 后续证据纠正了原文的结论时，按新证据修正文意。若差异来自模型、接口或版本变化，注明适用范围，不把版本变化写成旧理论从未成立。
- 证据只支持局部情形时，只保留有证据覆盖的情形，并说明外推到其他模型、任务或工作负载的边界。
- 关键细节无法核实或证据仍不足时，不把它写成事实。若不确定性会改变读者的判断，指出缺少哪类证据；若它不影响可复用解释，就省略该细节。
- 内容仅有助于理解设计沿革、兼容旧系统或解释当前假设时，作为必要的历史背景保留，并标清它的作用。
- 与已有解释重复、脱离具体问题也没有可复用价值的内容，融入已有章节或不收入正文。

## 放到读者要回答的问题里

把候选知识点按它们帮助读者回答的问题分组，不按发表顺序或原文章节排列。同一来源可分别帮助回答训练、推理和系统运行问题；把每个观点放到最能解释它的现有章节，并在对应位置保留支持该观点的证据。新建章节按写作规范所述的独立问题和复用条件判断。章节间是否存在真实的前置、因果或输入输出依赖，也按写作规范规划；正文完整性、示例、图解和来源呈现由写作规范统一约束。

引用、版本、段落定位和章节末来源说明遵循写作规范的[来源呈现规则](../../../../maintenance/writing-guide.md#keep-sources-available-without-interrupting-reading)。AI 来源按[维护技能入口](../SKILL.md)中的规则更新[AI 文献索引](../../../../review/ai-literature-index.md)。仓库维护命令见[README](../../../../readme.md)。

## 仓内例子：DeepSeek-V3 的 MTP

一批 MTP 材料可以按所回答的问题分别进入已有章节：

- DeepSeek-V3 报告 §2.2 的[训练机制](https://arxiv.org/html/2412.19437v2#S2.SS2)进入[语言模型训练章节的 MTP 小节](../../../../ai-engineering/foundations/how-llms-work.md#%E8%AE%AD%E7%BB%83%E6%97%B6%E5%A6%82%E4%BD%95%E9%A2%84%E6%B5%8B%E5%A4%9A%E4%B8%AA%E6%9C%AA%E6%9D%A5%E8%AF%8D%E5%85%83%EF%BC%9F)，回答模型怎样训练额外预测目标。
- DeepSeek-V3 报告 §2.2 的 [MTP 推理说明](https://arxiv.org/html/2412.19437v2#S2.SS2)支持 MTP 模块可用于生成推理时的候选草稿；Leviathan 等人的[推测解码论文](https://proceedings.mlr.press/v202/leviathan23a.html)支持目标模型验收候选并校正到目标分布。两项材料都进入[服务章节的候选验证小节](../../../../ai-engineering/systems/llm-serving-and-kv-cache.md#%E6%8E%A8%E6%B5%8B%E8%A7%A3%E7%A0%81%E5%A6%82%E4%BD%95%E9%AA%8C%E8%AF%81%E5%80%99%E9%80%89%E5%B9%B6%E5%A4%84%E7%90%86%E4%B8%B4%E6%97%B6%E7%BC%93%E5%AD%98%EF%BC%9F)，报告说明候选从何而来，论文说明验收如何保持目标分布。
- 关于当前推理引擎是否支持某个 MTP 模块，核对对应版本的官方文档与实现，并在服务章节标明适用的模型家族、版本和配置。该证据只说明已核实的兼容路径，不推出所有引擎都支持 MTP，也不单独支持性能建议。

现有[AI 文献索引](../../../../review/ai-literature-index.md)为 DeepSeek-V3 报告和 Leviathan 论文分别保留了主题条目，前者关联训练章和服务章，后者关联服务章。同一来源可以支撑不同的问题，章节仍按读者要回答的问题划分。

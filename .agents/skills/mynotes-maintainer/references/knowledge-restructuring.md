# 怎样从知识出发重编一个领域

重编一个领域或大批重写时，现有章节只是素材，不决定新结构。先弄清有哪些知识，再决定怎样编排。读者看到的结构、章节和写法遵循[写作规范](../../../../maintenance/writing-guide.md)。

## 1. 盘点知识单元

逐篇读完范围内的正文，不按现有标题切分，拆出知识单元。一个单元是一个可以单独讲清的想法，大致相当于一节。每个单元记下：

- 它主张的机制、结论或决策规则，用一句话写出内容，不写话题名；
- 它回答读者的哪个问题；
- 类型：概念、机制、决策规则、失败模式、度量方法、具体系统实例或历史背景；
- 前置知识和依赖它的后续知识，包括其他领域的；
- 出处、所用案例，以及它长期成立还是依赖某个产品或版本。

同时记录表达问题（难读的段落、硬套的案例、过量的限定语）和跨章重复。范围大时，按文件分给多个并行的只读子任务，每个子任务交回一份清单。清单只用于本轮编排，不提交进仓库。

## 2. 聚类并找出金字塔

按单元回答的问题和依赖关系聚类，不按原文件聚类。贯穿多个簇的原则是总论点的候选。用三到五条主线覆盖全部主线单元，每条主线写成一个问题和一段答案提纲。逐个核对单元：

- 每个单元只有一个归属，被多处使用的单元按写作规范的权威位置规则安放；
- 找不到归属的单元，要么补进合适的章，要么说明不收录的理由；
- 主线之间若有交接产物，比如一条主线产生的状态正是另一条主线的输入，就在交界处写明它产出什么、下游读取什么。

## 3. 挑战一轮

按 AGENTS.md 的规则，把草图和清单要点交给一个独立的 Sol 审阅者，挑战一轮。重点检查：

- 主线之间是否大致互不重叠、合起来没有遗漏；
- 排序是否合理：最难的推导如果只被少数章使用，应降为支线，不要挡在入口；
- 有没有读者还没学到就要用的依赖；
- 案例分配是否合适。

由主 agent 决定采纳哪些意见。

## 4. 定章节边界和案例

按写作规范的章节规则从主线切出章节和支线。案例按写作规范的主线案例规则分配。为每章写下它负责的单元、权威定义、前后章交接的输入与产出，作为写作任务的说明。

## 5. 重写和收尾

按单元清单、原文和一手证据重写，不在旧稿上逐句修补。保留独特的例子和证据。核对旧路径的去向，更新入链、索引和阅读进度；完成后按维护技能入口的检查项验收。

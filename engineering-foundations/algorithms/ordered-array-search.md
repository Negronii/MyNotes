# 有序数据怎样让二分查找和双指针安全排除候选？

案例背景：合成报表 42 已取回一页事件，按 `(occurred_at, event_id)` 升序排列，即先比发生时间，时间相同再比事件 ID。现在要在页内定位某条记录、找出下一页从哪里开始，另外还要在别的有序数组上找两数之和。这些任务都靠“有序”在每一步安全地排除一批候选；前提是数据的排序规则、查找用的比较器和对返回结果的约定三者一致。本章最后的零值压缩例子不依赖排序，它靠读写两个下标的不变量工作。

## 二分查找如何缩小有序区间？

精确查找的前提：数组已按比较器定义的顺序升序排列，目标也是同一种键；比较器对同一对值总是给出相同的正负号，且比较结果可传递，能定义一个一致的顺序。下面的闭区间版本返回任意一个相等项的下标；空数组或找不到时返回 -1。有重复项时，命中的不一定是第一个。

~~~javascript
function binarySearch(values, target, compare) {
  let left = 0;
  let right = values.length - 1;
  while (left <= right) {
    const middle = left + Math.floor((right - left) / 2);
    const order = compare(values[middle], target);
    if (order === 0) return middle;
    if (order < 0) left = middle + 1;
    else right = middle - 1;
  }
  return -1;
}
~~~

先用便于手算的数字数组 `[3, 7, 11, 15, 19, 23, 27]` 查找 19。这些都是有限数值，可以传入比较器 `(a, b) => a - b`，结果的正负号就表示大小关系。循环不变量是：若目标存在，它一定在当前闭区间 `[left, right]` 内。

| 轮次 | 当前闭区间 | 中点下标和值 | 比较后的动作 |
|---|---|---|---|
| 1 | `[0,6]` | `3 → 15` | `15 < 19`，排除下标 0–3，令 `left=4` |
| 2 | `[4,6]` | `5 → 23` | `23 > 19`，排除下标 5–6，令 `right=4` |
| 3 | `[4,4]` | `4 → 19` | 命中并返回下标 4 |

若查找 20，前两轮相同；第三轮比较下标 4 的 19，令 `left=5`，闭区间 `[5,4]` 为空，返回 -1。只要目标不在数组中，闭区间最终都会变空。

有序性也决定了复杂度：中点小于目标时，`left` 到 `middle` 的值都更小；中点大于目标时，`middle` 到 `right` 的值都更大。所以每次比较至少舍弃一半候选，最多比较 O(log n) 次，额外空间 O(1)。中点写成 `left + floor((right-left)/2)`，在固定宽度整数的语言里可以避免 `left+right` 溢出；JavaScript 数组长度远小于 Number 的精确整数上限，不会溢出，但这种写法便于移植。如果数组无序，或比较器与排序规则不一致，就不能这样排除候选。

**回到报表 42：复合键要逐字段比较。** 先比较 `occurred_at`，时间相等时再比较 `event_id`。示例把时间统一存成 UTC、精度相同的 ISO 8601 字符串，所以字符串的字典序就是时间顺序；ID 是两位数字、宽度固定的 `eNN` 字符串，所以字典序与编号顺序一致。生产环境中，这个比较器还必须与数据库的字段类型、空值排序位置和排序规则（collation）完全一致。

~~~javascript
function compareEvent(a, b) {
  if (a.occurred_at < b.occurred_at) return -1;
  if (a.occurred_at > b.occurred_at) return 1;
  if (a.event_id < b.event_id) return -1;
  if (a.event_id > b.event_id) return 1;
  return 0;
}
~~~

时间优先于 ID，只有时刻相同时才由 ID 决定先后。下面用完整的合成页说明：e07 在 09:00，e03、e11 在 09:02，e18 在 09:05。e03 的 ID 比 e07 小，但时间更晚，所以排在 e07 后面。因此这份数组按 `event_id` 单独看并不是升序，不能只用 `event_id` 在上面二分。

| 排序行 | `occurred_at` | `event_id` | 与游标 `(09:00, e07)` 的关系 |
|---|---|---|---|
| e07 | 09:00 | e07 | 相等 |
| e03 | 09:02 | e03 | 更大；时间更晚，即使 ID 字典序更小 |
| e11 | 09:02 | e11 | 更大；时间晚于游标。两条 09:02 记录中，e11 排在 e03 后 |
| e18 | 09:05 | e18 | 更大；时间更晚 |

`compareEvent` 既可用于精确查找，也可用于求边界。表格中的时分只是简写，代码里用的是完整时间戳。用于分页时，完整排序键 `(occurred_at, event_id)` 必须能唯一确定每条记录；如果仍可能有完整键相同的记录，就要再加一个 tie-breaker（平局裁决键），并且排序和分页条件都要用上它。

~~~javascript
const events = [
  { occurred_at: '2026-11-12T09:00:00.000Z', event_id: 'e07' },
  { occurred_at: '2026-11-12T09:02:00.000Z', event_id: 'e03' },
  { occurred_at: '2026-11-12T09:02:00.000Z', event_id: 'e11' },
  { occurred_at: '2026-11-12T09:05:00.000Z', event_id: 'e18' }
];

console.log(binarySearch(events, events[1], compareEvent)); // 1：精确找到 e03
~~~

**找边界时，待探测的元素范围与可能的答案不是同一个区间。** 分页需要的往往不是“某条记录在哪”，而是“插入点在哪”。在升序数组中，`lower_bound` 返回第一个键 `>= target` 的下标；所有键都小于目标时返回数组长度 `n`。待探测的元素下标是半开区间 `[lo, hi)`，而答案可能是闭区间 `[lo, hi]` 中的任一位置（包括 `n`）。初值 `lo=0, hi=n`；不变量是 `lo` 左侧的键都 `< target`，从 `hi` 开始的键都 `>= target`。若中点小于目标，令 `lo=mid+1`；否则 `mid` 本身仍可能是答案，令 `hi=mid`。下面的 `bound` 函数用参数 `afterEquals` 同时实现 `lower_bound`（默认）和后文的 `upper_bound`。

~~~javascript
function bound(values, target, compare, afterEquals = false) {
  let lo = 0;
  let hi = values.length;
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    const order = compare(values[mid], target);
    if (order < 0 || (afterEquals && order === 0)) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}

const target = { occurred_at: '2026-11-12T09:02:00.000Z', event_id: 'e08' };

console.log(bound(events, target, compareEvent)); // 2：首个 >= target
console.log(bound(events, events[1], compareEvent)); // 1：首个 >= (09:02,e03)
console.log(bound(events, events[1], compareEvent, true)); // 2：首个 > (09:02,e03)
~~~

第一个调用的查询键 `(09:02,e08)` 落在两条 09:02 记录之间，数组中没有与它相等的项。下表逐轮记录探测范围与候选边界：

| 当前状态 | 元素探测范围 | 候选边界 | 中点 | 比较与更新 |
|---|---|---|---:|---|
| 第 1 轮 | `[0,4)` | `[0,4]` | 2，`(09:02,e11)` | 大于目标，令 `hi=2`；下标 2 不再探测，但边界 2 保留 |
| 第 2 轮 | `[0,2)` | `[0,2]` | 1，`(09:02,e03)` | 小于目标，令 `lo=2` |
| 结束 | `[2,2)` | `[2,2]` | — | 探测范围为空，唯一边界为 2，首个符合项是 `(09:02,e11)` |

`lower_bound` 本身不代表找到：若要找第一条与目标相等的记录，先求出 `pos`，再检查 `pos < n && compare(values[pos], target) === 0`；否则 `pos` 可能指向第一个更大的项，或者等于 `n`。

分页时，游标（cursor）是上一页最后一条记录的排序键，下一页应从严格大于游标的第一条开始，这就是 `upper_bound`。把 `afterEquals` 设为 `true` 即可让相等项也被跳过；此时不变量变为 `lo` 左侧的键都 `<= target`、从 `hi` 开始的键都 `> target`，结束时返回已加载数组中第一条严格大于游标的位置，没有更大的键则返回 `n`。以游标 `(09:02,e03)` 为例：`lower_bound` 返回 1（游标自身），`upper_bound` 返回 2（当前页中的下一条）。即使游标对应的行已被删除，只要用同一完整排序键比较，严格边界仍能定位到第一条更大的记录。

注意，这里求的只是已加载页内的边界；向数据库取下一页时，查询仍要使用相同的查询范围、排序规则和严格的游标条件。如果两条记录的排序键完全相同，而游标恰好停在两者之间，严格 `>` 会跳过后一条，因此分页键必须唯一，或加上 tie-breaker。

两个边界版本都从 `[0,n)` 开始，每轮待探测项至多剩一半，所以最多 O(log n) 次键比较、O(1) 额外空间。本例的键是定长字段，一次比较按 O(1) 计；若键长随输入增长，要另计比较成本。无序数组谈不上 lower/upper bound：只查某条记录是否存在时，可以线性扫描；要找有序边界，就得先按同一比较器排序，或换用能维持这种顺序的数据结构，并把建立有序表示的成本算进去。

## 双指针何时能替代重复扫描？

二分每步舍弃一半候选；双指针则用两个只向前（或只向内）移动的下标，每步至少排除一个候选，把原本的嵌套循环降为一次扫描。它不能替代任意嵌套循环：每次移动指针都要有“被跳过的候选不可能是答案”的理由。下面的两数之和靠数组升序提供这个理由；零值压缩不要求排序，靠的是读写位置的不变量。

### 有序数组两数之和

问题：在升序数组中找两个不同下标，使对应值之和等于 `target`。为了让 JavaScript `Number` 的整数比较精确，本例要求值、`target` 以及每次算出的两端和都在安全整数范围内；业务数据超出这个范围时，应改用精确数值类型和相应的比较方式。

移动理由：若两端和小于 `target`，当前左端已经和剩余候选中最大的值相加，仍然不够，它与任何其他右端配对只会更小，所以左端可以排除；若两端和大于 `target`，当前右端已经和剩余最小的值相加，仍然太大，所以右端可以排除。被排除的一端不会再参与答案，指针也就无需回头。

~~~javascript
function twoSumSorted(values, target) {
  let left = 0;
  let right = values.length - 1;
  while (left < right) {
    const sum = values[left] + values[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;
    else right--;
  }
  return null;
}
~~~

示例输入 `[1, 2, 4, 7, 11]`，`target=9`。函数返回一对下标，或在无解时返回 `null`；循环条件 `left < right` 保证两个下标不同：

| 步骤 | `left` 与值 | `right` 与值 | 和 | 排除理由或结果 |
|---|---|---|---:|---|
| 1 | `0:1` | `4:11` | 12 | `12 > 9`；右端 11 与其余任一左值配对也会过大，`right=3` |
| 2 | `0:1` | `3:7` | 8 | `8 < 9`；左端 1 与其余任一右值配对也不足，`left=1` |
| 3 | `1:2` | `3:7` | 9 | 命中，返回下标 `[1,3]` |

循环不变量：任何尚未排除的解，两个下标都在当前 `left` 到 `right` 之间。每次移动都排除了不可能参与解的一端；两指针相遇时候选为空。每轮至少移动一个端点，所以总共 O(n) 时间、O(1) 额外空间。值相同的两个不同下标也可以构成解，例如 `[2,2]` 求 4。

数组未排序时，上面的极值论证不成立，不能照搬移动方向。例如未排序的 `[3,1,2]` 求 3，下标 `[1,2]` 是解，但这段代码第一轮 3+2=5 过大、第二轮 3+1=4 仍过大，右指针左移两次后与左指针相遇，返回 `null`。如果先排序再用双指针，得到的是排序后数组的下标；需要原数组下标时，要在排序前记下原位置，并把排序成本算进去。

### 把零移到末尾并保留其他次序

问题：把数组中的零全部移到末尾，同时保持非零值的原有相对次序，且原地完成。这里两个指针都从左向右走：`i` 负责读，`next` 指向下一个非零值应写入的位置。处理下标 `i` 前，数组分为三段：`[0,next)` 是已扫描的非零值，顺序与原输入相同；`[next,i)` 全是零；`[i,n)` 尚未扫描。

- 当前值是零：`next` 不动，这个零自然并入中间那段。
- 当前值非零且 `next<i`：交换后，该非零值写到 `next`，原来 `next` 处的零移到 `i`。
- 当前值非零且 `next===i`：自己和自己交换，数组不变。

处理完并推进 `i` 后，三段的不变量重新成立。

~~~javascript
function moveZeros(values) {
  let next = 0;
  for (let i = 0; i < values.length; i++) {
    if (values[i] !== 0) {
      [values[next], values[i]] = [values[i], values[next]];
      next++;
    }
  }
  return values;
}
~~~

以 `[0,1,0,3,12]` 为例，扫描结束时 `next` 之后的后缀全是零：

| 处理下标 `i` | 处理前 `next` | 操作 | 处理后的数组 | 新 `next` |
|---:|---:|---|---|---:|
| 0 | 0 | 值为 0，跳过 | `[0,1,0,3,12]` | 0 |
| 1 | 0 | 交换下标 0 与 1 | `[1,0,0,3,12]` | 1 |
| 2 | 1 | 值为 0，跳过 | `[1,0,0,3,12]` | 1 |
| 3 | 1 | 交换下标 1 与 3 | `[1,3,0,0,12]` | 2 |
| 4 | 2 | 交换下标 2 与 4 | `[1,3,12,0,0]` | 3 |

函数原地修改并返回同一个数组，时间 O(n)、额外空间 O(1)。它面向稠密数组，把严格等于 0 的项（包括 -0）移到末尾，其余项保持原有相对次序。若要把 null、空字符串等也当作“零”，需要改写判定条件；若输入含空槽，读到的 `undefined` 会被当作非零值移动，使用前要先定义好这种情况的语义。
